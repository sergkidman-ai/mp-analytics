# CLAUDE.md — mp-analytics («Пульт бизнеса»)

BI-система маркетплейс-аналитики продавца картриджей «Цифровой квадрат»: забрать по API данные
всех площадок, свести в одну БД, считать реальную экономику каждого SKU. Карта проекта —
`ARCHITECTURE.md` (читать только при споре о принципах). Проект живёт ТОЛЬКО в `/opt/mp-analytics`;
соседние (`/opt/sokol-server`, `/opt/tz-analyzer-src`, `/var/www/sokol`) не трогать.

## Инфраструктура

- PostgreSQL 16 в Docker (контейнер `mp-postgres`), `127.0.0.1:5433`, база `mp_analytics`,
  том `/opt/mp-analytics/pgdata`; доступ — `DATABASE_URL` из `.env`.
- Python: `./venv/bin/python` (3.10, venv в репозитории).
- Дашборд: `uvicorn web.app:app` на `127.0.0.1:8090`, юнит `web/mp-dashboard.service`.
- git здесь, ветка `main`. Структура репозитория — `docs/archive/CLAUDE_реализованное.md`.

```bash
./venv/bin/python core/db.py      # self-check подключения к БД
./venv/bin/python run_daily.py    # полный прогон сбора + пересборка витрин
systemctl restart mp-dashboard    # перезапуск веб-дашборда (:8090)
```

## Аккаунты

WB: `wb_acc1`, `wb_acc2`. Ozon: `oz_acc1` (Премиум-Про, есть отзывы/рейтинг), `oz_acc2` (Дисквэр).
Различаются полем `account`; площадка — полем `platform`.

## Потоки и точка входа

`fin` (себест/маржа/P&L, `run_daily.py`, миграции 0xx) · `mkt` (реклама/ABC/просадки,
`run_marketing.py`, миграции 1xx) · `rev` (отзывы) · `gab` (габариты) · `inv` (банк/платежи) ·
`card` · `prc` · `ret` · `ev` · `infra`. Реестр — `docs/SESSIONS_MAP.md`.

1. Старт сессии: этот файл + свой `docs/BRIEF_<ПОТОК>.md` — и больше ничего.
   Полный `docs/HANDOFF.md` — только по прямой просьбе.
2. Конец значимого блока работы: обновить свой бриф (состояние / сделано / ветка-worktree /
   открытые вопросы / следующий шаг).
3. Одна сессия = одна задача. Файлы чужих потоков не менять, вопрос фиксировать в своём брифе;
   новый модуль помечать шапкой `# поток: <имя>`.
4. `margin_by_sku` пишет ТОЛЬКО `fin`; остальные потоки читают (read-only).

## Инварианты (нарушение стоит денег)

1. **МойСклад — источник правды** по товарам и себестоимости; артикул — единый ключ МС↔площадки.
2. **Себест для анализа — из витрины `margin_by_sku`** (`article` = nm_id). Наивный джойн
   `external_code → cost_seb` ЗАПРЕЩЁН (дырявый путь). Себест конкретной отгрузки — `report/stock`
   на ДАТУ отгрузки, не усреднённый.
3. **Сторно COGS возврата — себест САМОЙ отгрузки** (мост «отправление → документ отгрузки МС»).
   Месяц сторно НЕ выравниваем: раздел «Себестоимость» — месяц ОТГРУЗКИ, витрина и «Отчёты МП» —
   месяц ДЕНЕЖНОГО РЕВЕРСА (решение 14.08.2026, вопрос закрыт).
4. **Контроль финансового пайплайна:** nmID 216421567 за май 2026 → чистая **3741.77 ₽**
   (тест `tests/test_control_margin.py`).
5. **Габариты: придумывать, оценивать и рассчитывать ЗАПРЕЩЕНО** — коэффициенты, медианы по модели,
   ужимка. Только реальный короб с явным источником. `profiline` — источник ТОЛЬКО веса.
   Расхождение поставщиков: согласие = ≤10 % ИЛИ ±1.5 см по стороне, брать БОЛЬШИЙ реальный короб.
6. **Отправка данных на WB / Ozon / Яндекс — только по отдельной прямой команде Сергея.**
   Наличие данных ≠ разрешение на запись; dry-run можно, запись — нет.
7. **Секреты только в `.env`** (gitignored): не хардкодить, не выводить в чат, не отдавать Codex.
8. **Платные ресурсы — только после явного «да» Сергея** на конкретную сумму и объём, с письменной
   оценкой стоимости ДО запуска: API с оплатой по факту, платные подписки и каталоги, отдельно
   тарифицируемые серверные инструменты. Молчание и «продолжай» согласием НЕ являются; разрешение
   разовое, расширение объёма — новый вопрос. Ключ в `.env` — не мандат на трату.
9. **Гигиена контекста:** содержимое файлов данных в чат не выводить никогда (скрипт → файл →
   сводка ≤20 строк); вывод любой команды ≤50 строк; медиа/xlsx/pdf не тянуть в контекст —
   извлекать нужное скриптом в текст. Ответ/файл >1 МБ — на диск, разбирать `jq`/`grep`.
10. **Общий чекаут всегда стоит на `main`:** переключение ветки здесь ЗАПРЕЩЕНО (HEAD уедет под
    всеми параллельными сессиями). Работа в ветке — только в своём worktree под
    `.claude/worktrees/<поток>-<задача>`, ветка `<поток>/<задача>` от `origin/main`; внутри сразу
    симлинки `.env` и `venv` и файл `.workstream` с именем потока. Коммитить в `main` из общего
    чекаута можно.
11. **Перед ожидаемым ASK — шесть строк:** намерение · объём числом · эффект · обратимость ·
    рекомендация YES/NO · read-only preview (`count(*)` тем же `WHERE`, dry-run) до записи.

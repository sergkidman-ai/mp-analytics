## Готовность октября WB

Проверка 08.11.2026 по обоим аккаунтам. Последний закрытый месяц в снимке — сентябрь.
Проверенный источник обновлён 08.11 около 07:21 UTC. В сырье по каждому юрлицу
присутствуют отчёты с датами формирования 01,05,12,19,26 октября.

В Пульте WB учитывается **по месяцу формирования отчёта**, что закреплено
действующей моделью проекта (`create_dt`), а не по календарной дате заказа/продажи.
Отчёт за 26–31 октября уже загружен, дата формирования 01.11, поэтому он относится
к ноябрю; сформированный 02.11 отчёт охватывает 01.11. Следующий недельный отчёт
за 02–08.11 относится к ноябрю и не является недостающим октябрьским отчётом.

Это различие следует сохранять при обсуждении закрытия и при будущей смене баз.
WB отдельно указывает период и дату формирования в финансовом отчёте:
https://seller.wildberries.ru/instructions/ru/ru/material/how-to-read-general-financial-report
Проверена также официальная справка о недельной детализации; общий срок появления
может быть до среды, поэтому точная гарантия выпуска следующего отчёта утром
09.11 не утверждается.

Октябрьские COGS в витрине: Цифровой 805 SKU / 617123,16 ₽, Дисквэр 591 SKU /
455887,855 ₽. Пропусков COGS 0. Доля «Итого удержания WB» от нашей цены:
53,0384% и 53,6141% соответственно.

Проверка штатного `_freeze(...,2026,10)` на копии JSON прошла по обоим аккаунтам,
прежние месяцы сохранены. По текущим данным октябрь готов к закрытию в рамках
существующей модели; ожидание отчёта за 02–08.11 не требуется. Последующие правки
старых отчётов WB — отдельная штатная задача реконсайла. В текущем поручении
проверялся статус: **октябрь не закрывался**, снимки не записывались.

## Исправления отображения

В замороженных столбцах `row(showpc=True)` рисовал долю от оборота, а живые
столбцы получали только форматированную сумму. Добавлен маркер `data-showpc`
и общий JS-расчёт доли по числовому API `value`:

- WB: база `own_price` — наша цена до СПП;
- Ozon: база `sales`;
- Маркет: база `own` (выручка + зачёт баллами).

Проценты появляются только у тех строк, у которых они уже предусмотрены
в закрытых месяцах. Факт использует свой оборот, прогноз свой, годовой итог
суммарный фактический оборот года. Нет деления на ноль, процента от неизвестной
суммы и дублирования span при повторном обновлении. Динамические подстроки
не наследуют нежелательный процент от родителя. Заодно годовые ячейки заполняются
во всех отображениях одного ключа (в Маркете `netting` показывается дважды),
а сам ключ учитывается в годовом расчёте один раз.

Общий дефект устранён для живых столбцов всех трёх площадок и столбца «Итого за год».

У WB октябрь ранее имел last_report=26.10 и ошибочные remaining_days=5 даже в ноябре.
Это строило прогноз несуществующих будущих октябрьских дней. Для завершённого
календарного месяца теперь remaining_days=0, прогноз равен загруженному факту;
истинная дата последнего отчёта 26.10 сохранена. Для текущего ноября прогноз
сохраняется. Календарное завершение не приравнивается к закрытию в снимке.
Фактические суммы всех API до/после совпали, финансовые базы не пересчитывались.

# Яндекс.Маркет: закрытие октября 2026

По прямой команде пользователя октябрь закрыт в «Отчётах МП» для существующего
аккаунта ya_acc1, в ранее подтверждённом контуре семи FBS/экспресс-магазинов.
`report_closed=true`, `accounting_provisional=false`, источник `closure_reconciled`.
В Пульте текущий месяц — ноябрь. Закрывающий отчёт и услуги получены заново за октябрь.

## Проверенный периметр и оговорка FBY

В `.env` отсутствовал список кампаний. Он восстановлен только в процессе проверки
из прежней подтверждённой сентябрьской базы, без изменения `.env`/настроек торговли.
Семь магазинов доступны по API; на текущих октябрьских платежах/услугах четыре
действующих магазина Москвы, остальные три — без октябрьских операций.

При обнаружении бизнес-кампаний найден также старый FBY21589415 «Цифровой квадрат».
API отвечает `403 API_DISABLED`, отключён вручную. Он не входил в прежний
подтверждённый семимагазинный контур. В полученном октябрьском INCOME-отчёте и
общем отчёте услуг операций FBY нет. Пользователю задан вопрос о его октябрьской
активности; на момент закрытия ответа нет. Это закрытие не объявляет проверенной
отдельную деятельность недоступного FBY и не расширяет прежний периметр Пульта.
Задача смены баз сторожей остаётся отдельно отложенной с этой оговоркой.

## Найденная ошибка и исправление

Сохранившийся parser ошибочно относил файл `period_closure_income_sold_refunds`
к возвратам. По официальной схеме это **«Реализовано от имени заказчика»**;
возвраты реализованного находятся в `period_closure_income_sold_defect_refunds`.
Источник: https://www.yandex.ru/dev/market/partner-api/doc/ru/reference/reports/generateClosureDocumentsDetalizationReport

В октябре обнаружена одна такая продажа бизнесу на 1685 ₽ от 09.10,
документ1000003171875. В CSV это положительное «Начисление», «Продажа бизнесу»,
а в обычном stats/orders такой документ отсутствует. Исправлен SHEET_CAT и сохранён
source_sheet. Проверочная база теперь учитывает только явно подтверждённые
документные реализации/возвраты как отдельные финансовые движения, с защитой
от повторного счёта, неоднозначного совпадения суммы и неверного направления.
Обычные отсутствующие платежи из закрывающего отчёта НЕ подставляются автоматически:
они продолжают блокировать верификацию.

Ещё одна ошибка проверки требовала наличия заказов всех прошлых закрытых месяцев;
не найденные пять январских заказов блокировали октябрь. Проверка сужена до
обычных заказов текущего закрывающего отчёта; документные продажи сверяются
самостоятельно. Требования к полной пагинации всех семи кампаний и схождению денег
сохранены. Предыдущие месяцы не пересчитывались: исторические заказы прочитаны
только для выделения октябрьских денежных движений, последующие проверки использовали
50 сохранённых страниц без повторного обращения к API.

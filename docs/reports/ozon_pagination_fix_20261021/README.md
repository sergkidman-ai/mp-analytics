## Причина и поведение

Ozon может завершить выдачу пустой страницей с прежним last_id, сохраняя total
выше числа реально отданных позиций. Старый код выбрасывал исключение и прерывал
весь обход. Также ранняя остановка по total могла принять неполную выдачу за полную.

Новый обход идёт по курсору до окончания наблюдаемой выдачи. Пустая последняя
страница с прежним курсором допустима; количество и изменения total проверяются
отдельно. Возвращаемый список содержит явные complete и diagnostic. По умолчанию
неполный результат остаётся исключением ActionPaginationIncomplete, поэтому
лестница и другие потребители сохраняют строгую проверку отсутствия.

Сторож акций явно принимает наблюдаемую часть, проверяет её прежним расчётом,
отмечает неполноту и продолжает другие акции/кабинеты. Ошибки формата/повтор ID/
непустая зацикленная страница/превышение бюджета страниц остаются ошибками чтения;
они изолируются по акции. Ошибка всего кабинета не блокирует следующий.

При перечитывании отсутствие товара в неполном списке не подтверждает снятие:
статус остаётся sent с пояснением. Из него также нельзя вывести, что подъём цены
снял товар. Найденная позиция с достаточной фактической ценой может подтвердить
подъём; найденная после удаления позиция доказывает неуспешное снятие.

Итог кабинета виден отдельно от строк решений: stdout и
logs/oz_promo_guard_runs.jsonl с ok/partial/failed/error, количеством ошибок,
неподтверждённых операций и диагностикой action_id/cursor/count. После обработки
обоих кабинетов неполнота/ошибки дают exit code1. В штатном apply предупреждение
использует существующую сводку; --no-tg запрещает отправку. Это не отметка
«всё безопасно»: неизвестная часть ответа остаётся явно непроверенной.

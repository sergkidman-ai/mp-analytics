# Solutions Print: восстановление сборщика11.10.2026

Восстановлен новый read-only инструмент `tools/card_solutionsprint_scraper.py` для cartridge.ru. Исходный временный crawl_dims_ms.py в репозитории не найден. Новый код собирает URL, числовой код поставщика, название, таблицу характеристик, цвет, ресурс, тип товара, аналог, отдельные свойства чипа при наличии, значки чипа и примечания основного товара, текст наличия. Сохраняются только извлечённые данные и SHA-256 страницы; авторизационные HTML, cookies и токены не сохраняются.

Источники ограничены одним main-product-wrap:характеристики из единственной characteristics-table, отметки наличия/чипа из единственного product-page. Старый небезопасный выбор первого analog__content не используется; связанные товары и комплект в рекомендации не дают оснований для характеристик или остатка основного товара. Неоднозначный блок/таблица/код приводит к отказу парсинга.

Проба public_probe_3:3/3 карточки,0 ошибок; у всех есть имя, код, цвет, ресурс и вид товара;2 «в наличии»,1 «под заказ». Карточка290096:SP W2031A голубой,без чипа,ресурс2100 страниц,под заказ~14.10.2026; поэтому не основание чипа при положительном остатке.Числовые коды и полные тексты остальных в records.csv. Отдельного свойства чипа в таблицах трёх проб нет; «Без чипа» у290096 есть отдельным значком и в названии. Это не проверка всех карточек и не доказательство отсутствия поля в закрытом кабинете.

Наличие относится к текущему региону/сессии сайта. «В наличии более10шт» сохраняет нижнюю границу10, а не точное количество. «Под заказ» не считается положительным остатком; неясный статус остаётся unknown. Остатки не суммируются по складам и не заменяют проверку фактического supplier stock.

## Вход

GET /personal/ HTTP200, найдена уникальная актуальная форма POST /personal/ с полями AUTH_FORM,TYPE,backurl,USER_LOGIN,USER_PASSWORD,USER_REMEMBER. Реализован режим --login:читает только SOLUTIONSPRINT_LOGIN/SOLUTIONSPRINT_PASSWORD из .env, входит через форму и требует подтверждение авторизации. Секреты не выводятся. На первом шаге данных в .env и действующих cookies не было; после указания пользователя пароль найден в Dropbox, данные сохранены в .env. В истории есть только старый логин e-shop@digitalsquare.ru.11.10 сначала выполнена публичная проба, затем вход подтверждён с данными Dropbox; режим --login работает. Данные Профилайн/почты не пробовали; CARTRIDGE_API_KEY относится к другой системе ТК thecartridge.ru.

## Запуск

Публичная проба:
`./venv/bin/python tools/card_solutionsprint_scraper.py --urls-file docs/reports/card_solutionsprint_scraper_restore_2026-10-11/probe_urls.txt --limit 2`

После получения данных в .env:
`./venv/bin/python tools/card_solutionsprint_scraper.py --login --urls-file docs/reports/card_solutionsprint_scraper_restore_2026-10-11/probe_urls.txt --limit 2 --out docs/reports/card_solutionsprint_scraper_restore_2026-10-11/private_probe`

Также есть --url, --discover (карточки из sitemap-iblock-1.xml) и явный --limit (по умолчанию5). Последовательный сбор с паузой1сек, без массового обхода в этой проверке. Для последующей сверки МС связывать карточку по числовому коду поставщика в своей группе, а не по похожему OEM или названию.

7 meaningful unit tests прошли:чужой analog и наличие из рекомендации не подмешиваются;под заказ не даёт положительное наличие;неясный статус остаётся unknown;неоднозначная таблица отклоняется;чужой домен/URL с токеном запрещены. Три свежие страницы разобраны успешно. Никаких записей в МС/ТК/БД/площадки не было; расписания сбора/записи нет.

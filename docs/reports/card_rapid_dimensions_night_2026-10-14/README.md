# Ночная запись размеров Рапида, 14–15.10.2026

По команде пользователя «давай сразу на 1016 прогон» расширен ранее подготовленный список 122 товаров из оприходований до **1016 активных карточек всей группы Рапид/Суперфайн**, без ограничения по наличию. Это 3048 пустых полей: «Длина, см.», «Ширина, см.», «Высота, см.». 142 товара сейчас с положительным остатком, 874 без остатка. Архив, чёрный список, карточки «Брак»/«Стоп лист» и спорный SF-T9451Bk исключены. Исходный подготовленный, но не включённый план 122 сохранён в `superseded_122/`.

Запуск: **14.10.2026 23:20 МСК / 20:20 UTC**. Жёсткий конец окна: **15.10 05:00 МСК / 02:00 UTC**. Timer `card-rapid-dimensions-20261014.timer` установлен, enabled, active/waiting. При подготовке service inactive, ExecMainStartTimestamp=n/a, journal отсутствует, записей 0. Состояние сохранено в `schedule_verification.json`.

До первой записи — свежий API Рапида, контроль идентичности источника, размеров, чёрного списка. Наличие не фильтруется, текущие оприходования для расширенного плана не являются условием. Изменившийся источник исключается из исполнения с причиной. Перед каждой партией — свежий GET карточек МС, проверка ID/артикула/внешнего кода/поставщика/архива/Брака/Стоп-листа. Уже совпадающее значение не записывается; появившееся отличающееся значение останавливает прогон. Заполняются только пустые поля, прочие атрибуты сохраняются из свежего GET.

Партии до 50 карточек, пауза не менее 60 секунд; после первых 200 записей — 10 минут и контроль чтения операционных документов МС. При медленном ответе пауза увеличивается. Прогон ждёт действующий `prc-enter-buyprice.service` и известные другие массовые исполнители. Полный backup перед каждой партией, журнал sending/verified с fsync, POST без автоматических повторов, GET всех изменённых карточек, сверка атрибутов и основных полей. Неопределённый ответ/ошибка → остановка и ручной аудит журнала; повторная отправка автоматически запрещена.

## Подписки и восстановление

Read-only инвентаризация показала единственного активного потребителя `product.UPDATE` — ТК (`thecartridge.ru`). По `.claude/skills/ms-mass-change/SKILL.md` габариты являются немым изменением: ТК не читает эти поля. Поэтому перед **каждым POST партии** адресно выключается только подписка UPDATE товара `ed64d51f-6dfc-11f1-0a80-0e6f00770df1`, с проверкой полного хэша URL, entity/action и списка потребителей. Сразу после POST она восстанавливается в `finally`, до GET и всех пауз. Подписки документов и CREATE товара не меняются. Массовые product.UPDATE не добавляются в общую операционную очередь. Наличие поллингового добора у внешней ТК не заявляется проверенным; нагрузка этих массовых событий устраняется адресным подавлением.

Изменение подписки — однократный PUT с GET-подтверждением; перед ним на диск fsync сохраняется владение изменением и исходное enabled=true. Если состав потребителей/URL/тип/действие изменились, запуск прекращается до POST товаров. Восстановление имеет три механизма: finally, `ExecStopPost` основного сервиса и независимый persistent timer **15.10 05:01 МСК** `card-rapid-dimensions-restore-20261015.timer`. Восстанавливается только собственное незавершённое изменение с совпадающей идентичностью. Повторное восстановление — no-op. Никакие исходно чужие отключения не включаются. Пользователь уведомлён в переписке; сообщения другим людям не отправлялись.

## Артефакты и проверки

- `plan.json`, `plan.csv`: замороженные 1016 ID, источник и целевые Д/Ш/В. SHA-256 в summary и authorization.
- `authorization.json`: прямая команда пользователя, scope=all_active_rapid, stock filter=false.
- `ms_before_prepare.json`: полный срез исходных карточек при подготовке.
- `summary.json`: состояние планирования/записи, счётчики writes/verified.
- `webhook_inventory_redacted.json`: инвентаризация без секретных URL.
- При исполнении: свежий источник, execution_plan, skips, backup/payload по партиям, GET after, journal, состояние восстановления подписки.

Исполнитель: `tools/card_rapid_dimensions_night.py`. Девять тестов прошли: сохранение других атрибутов, отсутствие перезаписи непустых, no-op уже заполненных, идентичность/архив/Стоп-лист/Брак, запрет дублей атрибутов, включение нулевого остатка без фильтра оприходований, идемпотентное восстановление только собственного изменения подписки. Четыре systemd unit-файла проверены `systemd-analyze verify`. Проверены 1016 уникальных ID, 3048 целевых полей, SHA и исключения.

# Чип: группа «в ТК нет данных» — проверка гипотез по слепкам (21.08.2026)

Ни одного запроса в МС/ТК: слепок остатков поставщиков `supplier_stock` за 21.08.2026
(склад «Удаленный», только `stock > 0`, 17 309 строк), каталог `prc_tc_model`, файл конфликтов
`prc_tc_fields_chip_conflicts_2026-08-20.csv`. Чип из названия — `prices.features.chip`.

## 1. Чип — свойство модели, а не отдельного поставщика

1337 строк группы = 906 внешних кодов. Что говорят ДРУГИЕ поставщики того же внешнего кода
(у кого есть остаток на «Удаленном»):

| ситуация по внешнему коду | кодов |
|---|---|
| ≥3 поставщика, все пишут одно и то же | 23 |
| 2 поставщика, пишут одно и то же | 138 |
| источник один (сравнивать не с кем) | 479 |
| никто в названии про чип не пишет | 265 |
| **разнобой между поставщиками** | **1** |

Вывод: расхождение НЕ локальное «этот поставщик привёз другую комплектацию». Под одним внешним
кодом поставщики почти всегда единогласны → это **пробел в ТК**, а не другой товар.

## 2. Метод проверен на моделях, где чип в ТК ЗАПОЛНЕН

1096 моделей ТК с непустым чипом; там, где есть поставщик с остатком и словом про чип в названии:

- совпало — **569** (с чипом 446, без чипа 71, с чипом б/сч 52);
- разнобой у поставщиков — 8;
- **расхождение ТК ↔ поставщики — 2** (ТК «без чипа» ← поставщики «с чипом»; ТК «с чипом» ←
  поставщики «с чипом без счётчика»).

Совпадение 569 из 571 (99.6 %) — название поставщика как источник чипа надёжно, значит и обратное
верно: пустое поле в ТК можно заполнять по единому мнению поставщиков.

## 3. Что заполнять в ТК

По группе: «с чипом» 1322 строки, «без чипа» 13, «с чипом без счётчика» 2. По единому мнению
поставщиков закрылось бы **640 внешних кодов** (632 «с чипом», 7 «без чипа», 1 «с чипом б/сч»).
Оставшиеся 266 — сравнивать не с чем (никто про чип не пишет / нет остатка).

Общий масштаб: у 5592 из 6688 моделей ТК поле «чип» пустое. Наши 906 — только та часть, где
поставщик написал про чип в названии и потому расхождение стало видно.

## 4. Переносить карточку или заводить новинку

- «есть куда перенести» (в ТК уже есть модель того же картриджа с нужным чипом) — **58 строк**;
- «вариантов модели в ТК нет» — 1279. Но это следствие п.1: вариант не нужен, нужно заполнить
  поле у существующей модели.
- Правило Сергея «карточку без чипа не заводим, если в ТК есть с чипом / с чипом без счётчика»
  задевает мало: «без чипа» у нас всего 13 строк (7 кодов).

## 5. Ретро по 65 «противоречиям» (карточки уже в архиве)

| кто прав по мнению поставщиков с остатком | строк |
|---|---|
| поставщики за ТК (наше название было белой вороной) | 30 |
| у поставщиков разнобой | 24 |
| проверить нечем (нет остатка) | 9 |
| **поставщики ПРОТИВ ТК** (значит, менять надо было ТК) | **2** |

Детали — `prc_chip_conflict_retro_2026-08-21.csv`. Архивация 30 подтверждается; по 24 «разнобой»
под одним внешним кодом действительно живут разные комплектации; 2 строки — кандидаты на правку
в ТК, а не на архив. Все они были с нулевым нашим остатком, новая карточка заводится при
появлении товара — потери нет.

## 6. Найденный дефект парсера

`features.chip` не понимает сокращение **«б/ч»**: 27 строк остатков поставщиков и 8 строк файла
конфликтов с «б/ч» в названии парсер считает «про чип ничего не сказано». Если «б/ч» = «без чипа»
(подтвердить у Сергея), шаблон `nochip` надо дополнить — часть «нет данных» и «противоречий»
объяснится сразу.

Файл построчно: `prc_chip_nodata_analysis_2026-08-21.csv`.

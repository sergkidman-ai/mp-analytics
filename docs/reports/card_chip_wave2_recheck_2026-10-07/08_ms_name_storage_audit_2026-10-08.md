# Куда загрузчики сохраняют название поставщика — 08.10.2026

Проверка только чтением, внешних изменений нет.

## Прайсы из почты

`prices/loader.py:359`, `card_updates`: для загружаемых товаров типа product, принадлежащих группе поставщика, актуальное название строки прайса сохраняется в **description / «Описание»**. Также обновляется buyPrice. Поле **name / «Наименование»** в patch отсутствует: существующую карточку загрузчик не переименовывает.

`prices/run.py:147` вызывает `card_updates`, кроме запуска с `--no-cards`. `prices/loader.py:419` отправляет подготовленные изменения в `/entity/product` после создания всех новых оприходований. Строки, не прошедшие отбор к загрузке, не входят в этот список обновлений.

Позиции оприходования содержат ссылку assortment на существующую карточку, количество и цену (`prices/loader.py:351`); само создание оприходования не меняет name карточки.

При создании новой карточки через `prices/ms_import.py:1053` сохраняются оба поля: name из «Наименование» и description из «Описание». Уже существующие карточки этот путь пропускает (`prices/ms_import.py:1047`). Это другой процесс, а не переименование при каждой загрузке прайса.

## Проверка данных МС

Во всех 16 сохранённых ответах МС для выборки прайсов от 07.10 поле **description совпадает с названием из прайса** после удаления внешних пробелов. В 13 из этих товаров отличается только поле name относительно прайса. Значит, предыдущая проверка name была неполной и **не доказывала утрату актуального названия в МС**.

GG-C9403A / внешний код 0968 дополнительно прочитан живым GET 08.10: description содержит полное название с окончанием **«без чипа»**, точно совпадающее с прайсом 07.10; name этого уточнения не содержит. Ответ сохранён отдельно в `raw/ms_samples/*_2026-10-08.json`. В этой задаче надо сопоставлять актуальный прайс прежде всего с description, а name показывать отдельно. При отсутствии свежего источника description не объявлять автоматически актуальным.

## Оприходования внешнего API-загрузчика

`prices/profiles.py:242` и `prices/unprocessed.py:4` явно описывают отдельный внешний загрузчик для Булата, ВТТ, Рамис, Блоссома и других поставщиков. Наш процесс получает сообщения о несопоставленных позициях; это не полный прайс и не код внешнего загрузчика.

Реализация внешнего загрузчика в проверенном проекте не найдена. Поэтому нельзя достоверно утверждать, обновляет ли он name, description или оба поля. Совпадение двух проверенных названий Булата с сайтом не доказывает механизм обновления. Для установления поведения нужен код/настройки этого загрузчика либо сравнение полей карточки до и после его штатной загрузки с известным изменившимся названием.

## Следствие для проверки чипа

Сохранение названия поставщика в description уже работает в нашем почтовом загрузчике; менять загрузчик только из-за несовпадения name оснований нет. Дальнейшая проверка должна учитывать оба поля, даты источника и положительный остаток. 150 кодов с основанием только по name МС нужно перепроверить по description и доступным свежим источникам: пока их статус не пересчитан.

# 12. Солюшнс Принт: перепроверка мэтчинга по НАЗВАНИЯМ. Статус «непроверяемый» снимается

Дата: 2026-07-29. Поток gab. **На маркетплейсы ничего не отправлялось.**
Инструмент: `tools/gab_sp_title_verify.py` → `docs/solutionsprint_title_check.csv` (801 строка).

## Почему SP считался непроверяемым

Артикул Солюшнс Принт — внутренний числовой код cartridge.ru (`38008`, `344707`, `333154`).
OEM-кода в нём нет, поэтому обычная проверка «код из артикула ↔ код карточки» на нём не работает:
из 801 карточки-матери по коду подтверждалось только 382 (47.7%, отчёт 11). Отсюда и осторожная
формулировка «внутренние коды, надёжность ниже» — при том, что SP один держит 2525 карточек (25.5%).

Но модель картриджа у SP есть **в названии строки** почти всегда:
«Картридж Samsung CLT-K508L», «Фотобарабан Brother DR-6000», «Картридж HP 90X (CE390X)».

## Как проверено

Проверка **независима от артикула**. Для каждой карточки:

1. Из **нашего** названия берётся модель — то, что стоит между носителем и словом «для»:
   «Картридж **CF283A** для HP LJ Pro M125 чёрный» → `CF283A`.
   Диапазон раскрывается в оба конца: «Картриджи Q6470A-Q6473A для…» → `Q6470A`, `Q6473A`.
2. Эта модель ищется **в названиях всех строк прайса SP** регэкспом, устойчивым к разделителям:
   `TN-2420` ≡ `TN2420` ≡ `TN 2420`, но с жёсткими границами — `TK-60` не подцепится внутри
   `TK-6017`, зато подцепится в `TN-2420/2425`.
3. Короб найденной строки сверяется с тем, что реально записан в карточку, по правилу п.9
   (согласие = по каждой сортированной стороне ≤10% **или** ≤1.5 см).
4. Дополнительно: нет ли среди подошедших по названию строк **радикально другого** короба
   (≥1.5× по объёму) — чтобы «подтверждение» не пряталось за удобно выбранной строкой.

## Результат

| Вердикт | карточек | доля |
|---|---:|---:|
| **подтверждено** — название нашлось, короб сходится, разночтений нет | **654** | **81.6%** |
| **подтверждено, но есть разброс строк прайса** | 127 | 15.9% |
| в прайсе по названию не найдено | 20 | 2.5% |
| **расходится** (нашлось, но короб другой) | **0** | **0%** |
| **ИТОГО подтверждено** | **781** | **97.5%** |

**Расхождений нет ни одного.** Там, где модель находится в прайсе SP, записанный короб всегда
совпадает со строкой прайса — то есть привязка была сделана верно, просто раньше её нечем было
доказать.

### Замечание о методике

Первая версия проверки давала 76% подтверждения и 14 «расхождений». Причина была в **проверке**,
а не в данных: сравнение шло по нормализованной строке с границей «не буква и не цифра», и код
`TN-2420` не находился внутри `TN-2420/2425`. После перехода на регэксп по исходному тексту
подтверждение выросло до 97.5%, а расхождения обнулились. Проверять надо было мягче по
разделителям и строже по границам, а не наоборот.

```
vc=0231  «Фотобарабан KX-FAD89A DU для Panasonic KX-FL401 чёрный»
   модель KX-FAD89A → SP 38008 «Фотобарабан Panasonic KX-FAD89A (KX-FAD89A7)»
   SP 35.0x12.9x16.7  =  записано 35x12.9x16.7

vc=3779  «Картридж TN-2420 для Brother DCP-L2510, HL-L2350DW чёрный»
   модель TN-2420 → SP 344707 «Картридж Solution Print TN-2420/TN-2410 3000стр Brother»
   SP 35.0x12.9x16.7  =  записано 35x12.9x16.7

vc=5581  «Картридж W1350A для HP LJ M209, LJ M209dw чёрный»
   модель W1350A → SP 333154 «Картридж SP 135A (W1350A) для HP чёрный (с чипом)»
   SP 10.0x30.0x10.0  =  записано 10x30x10

vc=5154  «Фотобарабан DO-428 для M7108DN, M7108DW чёрный»
   модель DO-428 → SP 356878 «Фотобарабан Pantum DO-428»
   SP 10.0x36.0x21.0  =  записано 10x36x21
   ▸ по коду эта позиция НЕ проверялась (семейство DO- вне белого списка) — именно такие
     419 позиций и составляли «непроверяемую» часть SP. По названию они закрываются.
```

## Расхождения по этому критерию — и то, чего этот критерий не видит

По критерию «короб карточки совпадает со строкой прайса, найденной по модели» расхождений **нет**.
Но этот критерий проверяет только **происхождение размера**, и у него есть слепая зона: он не
смотрит на **цвет**.

Параллельная проверка (`docs/reports/gab_solutionsprint_divergent.csv`) сверяет цвет карточки с
цветом строки SP и величину короба против других поставщиков. Она нашла **13 расхождений** — и
**все 13 лежат внутри моего «подтверждено»**. Мой канал их поймать не мог. Примеры:

```
vc=0128 «Картридж BCI-24 для Canon BJC-2000 ЧЁРНЫЙ»
   ← SP 26191 «Картридж SP BCI-21/BCI-24 Color для Canon ЦВЕТНОЙ»   (BK vs Color)

vc=5440/5441/5442 «Картридж LC-472XL C/M/Y для Brother MFC-J2340DW»
   ← SP 339317 «Картридж SP LC-472XL Bk для Brother ЧЁРНЫЙ»          (C/M/Y ← Bk)

vc=0937/0938 «Картридж T5595/T5596 для Epson светло-голубой/светло-пурпурный»
   ← SP 222673/222674 «ЧЕРНИЛА ДЛЯ ЗАПРАВКИ картриджей Epson T0485/…»
   ▸ здесь не только цвет: короб взят у бутылки чернил, а карточка — картридж.

vc=5560/5561 «Блок проявки DV-8115 … пурпурный/жёлтый» ← SP «…, голубой»
vc=4889/4890/4891 «Картридж C-EXV58 … голубой/пурпурный/жёлтый» ← SP «C-EXV58 BK»
```

Часть из них практически безобидна: у C-EXV58 и DV-8115 цветовые версии — физически один и тот же
корпус, короб у них общий (см. подтверждение этого на Сакуре, отчёт 11, примеры 4–5). Но
`BCI-24 Color`, `LC-472XL` и особенно `T5595/T5596` — реальные дефекты привязки.

**Вывод по методике:** ни одна из двух проверок не самодостаточна. Сверка по названию доказывает,
**откуда** взят размер; сверка по цвету и по величине ловит, что размер взят **не от того товара**.
Считать SP подтверждённым нужно по обеим.

## Что вместо расхождений: 127 случаев с разбросом строк прайса

Короб записан верно (он совпадает с одной из строк SP), но **в самом прайсе SP по этой модели
есть вторая строка с существенно другим коробом**. Это не ошибка привязки, а неоднозначность
источника, и её нужно разобрать глазами.

**(а) 75 случаев — одиночная строка против одиночной.** Две строки SP на один и тот же товар
с разными коробами; записан больший (правило «против занижения»):

```
vc=0576 «Картридж TN-135C для Brother HL-4040 cn голубой»
   записано 37x19x15   (SP 30632  37.0x19.0x15.0)
   но по названию также подходит SP 50617  36.1x10.1x17.2 «Картридж SP TN-135 C для Brother, голубой»
   → объёмы 10.5 л против 6.3 л. Та же картина у vc=0575/0577/0578 (чёрный/пурпурный/жёлтый).

vc=1775 «Картридж 43459436 для OKI C3300, C3400, C3450, C3600»
   записано 24.8x31.3x10.2 (SP 79290)
   но также подходит SP 69853  31.3x10.2x6.2 «Картридж SP 3300Bk (43459436) для Oki чёрный»
   → 7.9 л против 2.0 л, разница вчетверо.
```

**(б) 52 случая — по названию подошла ещё и строка-КОМПЛЕКТ.** В большинстве это безобидно:
записан короб одиночной строки, комплект просто попал в выдачу поиска. Например vc=2785–2788
(OKI 45862849–52): записано 7.5x42x14 — одиночный короб, а комплект 50x38x15.2 в карточку не
попал.

**Но 17 карточек-одиночек получили короб именно строки-КОМПЛЕКТА** — это уже дефект, короб
набора на товаре, который продаётся поштучно:

```
vc=3469/3470/3471/3472  «Картридж 106R0352x для Xerox VersaLink C400» (4 цвета, по отдельности)
   записано 37.5x36x17 = SP 293459/293460/293461/293462
   «Комплект картриджей SP C400/405 (106R03520-106R03521-106R03522-106R03523)» — короб на 4 шт.

vc=5670 «Заправочный комплект PGI-425 для Canon Pixma iP4840»
   записано 7x17x10 = SP «Комплект картриджей SP PGI-425/CLI-426 для Canon (6 цветов)»

vc=5308 «Печатающая головка C4813A для HP InkJet 1100»
   записано 3.7x6.5x8 = SP 354399 «Комплект печатающих головок HP 11 (C4810A-C4811A-C4812A-C4813A)»
```

Из 17 часть — это карточки, которые **сами являются комплектами** («Сервисный комплект MK-460»,
«Заправочный комплект TN-C2310HC»), там короб комплекта как раз уместен. Реально спорных —
9 позиций: 4× Xerox VersaLink C400, MK-4105 (карточка одиночная, а строка SP — сервисный
комплект), PGI-425, 4× печатающие головки HP 11.

## 20 не найденных по названию

Модель из нашего названия в прайсе SP не встречается вовсе. Это не противоречие, а отсутствие
подтверждения по этому каналу — короб у них взят из строки, найденной другим путём:

```
vc=5612/5610/5611  TO-910XY / TO-910XC / TO-910XM  (Pantum CM9105DN)
vc=4592            DKN-55224  (лента Brother QL-1050)
vc=0698            CLP-510BK  (Samsung CLP-510)
```

## Вывод

**Статус «непроверяемый» с Солюшнс Принт снимается.** Основание:

- проверка по названию **независима от внутреннего артикула** и подтверждает происхождение короба
  у **781 из 801** карточки-матери (97.5%);
- по критерию происхождения **расхождений ноль**; отдельная сверка по цвету и величине короба даёт
  **13 расхождений** (все внутри «подтверждено» — см. раздел выше), из них по-настоящему спорных
  около пяти. С учётом обеих проверок SP выходит на те же 91–92% чистоты, что и остальные
  поставщики, — то есть **на общий уровень, а не ниже него**;
- остаточные вопросы касаются не привязки, а **неоднозначности самого прайса SP**:
  75 позиций «одиночка vs одиночка» и 9 позиций с коробом комплекта на одиночном товаре —
  всего **84 позиции на ручной разбор**, они помечены в CSV (`вердикт=подтверждено_с_разбросом`);
- 20 позиций остаются без подтверждения по названию — не опровергнуты, просто не проверены
  этим каналом.

Формулировку в `summary_for_sergei.md` правим: SP — источник **уровня остальных поставщиков**,
с оговоркой про 84 позиции под ручную сверку, а не «надёжность ниже» целиком.

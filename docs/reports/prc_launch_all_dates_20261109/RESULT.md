## Даты и полнота

Предыдущий прогон ограничивался14.06.2026 и локальным каталогом; интерфейс дополнительно отсекал всё до14июня даже в режиме«всё». Теперь полный каталог МС включает архив, проверяются все модели, временные ошибки повторяются отдельно. Для невременных ID запрашивается фактический CREATE, UUID не подставляется вместо отсутствующей даты. Самая ранняя подтверждённая дата в восстановленных записях 2015-11-05. Ранние продажи запрещают позднюю дату создания модели.

После проверки нерешено 568 моделей; причины по типам ошибок: {'ValueError:unambiguous_create_not_found': 568}. Полный перечень —unresolved.json рядом с первичными аудитами. Наличие товара в МС не гарантирует наличие CREATE в доступной истории: на примере0004 в истории есть UPDATE с09.12.2015, но нет CREATE; общий аудит товаров до01.01.2015 также вернул0событий. Дата обновления/переноса базы не заменяет дату создания. Дополнительно проверены все56994payloadтоваров: отдельного поля/дополнительного атрибута даты создания нет.

Инструмент tools/prc/restore_launch_catalogue_dates.py: полный каталог и возобновляемый кэш, чтение внешних API; --apply обновляет только локальные evidence/tracker. Дата подтверждается событиями CREATE с проверкой идентичности карточки, архивные более ранние карточки учитываются. Новые данные сохраняются в prc_launch_creation_evidence и не теряются при штатном обновлении. Исходные даты и результаты всех применений сохранены. Никаких записей в МС/МП или финансовые таблицы.

Коды и даты сохранены в одну строку, названия имеют минимальную ширину220px; широкая таблица прокручивается внутри своего блока, заголовок не перекрывает первую строку (проверены координаты в Chromium).

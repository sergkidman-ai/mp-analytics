ТН ВЭД Али — выполнено 08.10.2026
Область: 6575 покрытых источником ТК карточек из активной группы 7700 товаров, находящихся в продаже и имеющих положительный остаток в фиде и Али.
Записаны и проверены: 6545. Для 30 модель не подтверждена, запись не выполнялась. 1125 прочих активных товаров, не имеющих исходного покрытия, вне этой операции.
Коды исключительно из ТК API ved_eaes_code: {'3215900009': 39, '3707909000': 9, '8443999000': 6497}.
Основания связи: {'FEED_CHECKED': 5634, 'FALLBACK_MODEL_CANDIDATE': 866, 'FALLBACK_IDENTITY': 45}. Приоритет — проверенная цепочка фида, затем связь МойСклад/точное название, затем подтверждённые модели. МойСклад и фид используются только для идентификации, не как источники кода.

Две карточки 40057 и 10284 отклоняли одновременную запись обоих полей; после раздельной записи старого поля и нового регуляторного блока оба значения успешно прочитаны.
У части карточек наблюдался временный переход onSelling -> auditing после обновления. Повторным чтением подтверждён возврат onSelling; окончательные проверки выполнены после возврата.

Метод записи: POST /api/v1/product/partial-update, products[].item_id, sku_info_list[].sku_code. Только tnved_codes и seller_regulatory_data.classification.tnved_codes; остальные имеющиеся сведения регуляторного блока сохраняются.
Для этих legacy карточек запись по sku_id давала product validation failed; метод по sku_code проверен пилотом для всех трёх кодов. После успешного пилота выполнены основные и дополнительные партии.
Каждая успешная партия: задачи Ali status=3, затем чтение полного товара; каждый код подтверждён в обоих полях SKU. Минимальные запросы не содержали цен/остатков/категорий/статусов. Во всех записанных карточках полные данные до/после проверены на неизменность остальных полей, кроме служебных временных отметок Али и ожидаемых пустых/нулевых элементов нового регуляторного блока. Али обновил служебные даты у 6545 карточек автоматически, включая ali_created_at; идентификаторы карточек и SKU сохранились.

Исключения: unresolved_30.csv. В частности, числовая модель принтера HP LaserJet 1015 совпадала с названием расходника Konica Minolta 1015, Business InkJet 1100 — с моделью Dell 1100. Такие строки не получили код из неподходящего товара ТК.

final_summary.json — сводка; before/ и after/ — полные ответы до/после; batches/ и additional_batches/ — запросы, ответы и статусы заданий; ledger.json — подтверждённый результат по каждому SKU.

## Что считать карточкой и связью

- Карточка — уникальный `product_id`; `offer_id` — строковый внутренний артикул, `sku` и `sources[].sku` — отдельные идентификаторы Ozon. Ведущие нули сохранены. 77 518 положительных SKU-алиасов связываются с карточками без коллизий. У 223 архивных карточек нет положительного основного SKU/model_id; они остаются по product_id.
- Четыре цифры — родительский артикул. Первые четыре цифры длинного артикула — **кодовый якорь**, а не самостоятельное доказательство исполнения. Numeric SEO, суффиксный SEO-кандидат и физический тип хранятся отдельно. В архиве номенклатура шире картриджей: числовой шаблон там не гарантирует SEO-смысл.
- Родительская группа `PG:` представляет подтверждённый по спецификации/правилу базовый код и его представления. `specification_parent_code` отделён от `warehouse_parent_code`: последний заполнен лишь при точном существующем неархивном `ms_product.external_code`. 789 карточек (572 текущих) имеют спецификацию, но не имеют такого живого MS-кода; их проверка явно открыта. Наличие кода в МС не доказывает исполнение конкретного заказа.
- **Бандл** — несколько одинаковых единиц; **набор** — разные компоненты. `XN` умножает физическое количество, суффиксный `XN` требует подтверждения названием/прямым правилом. Количество подтверждённых разных компонентов берётся из `set_cost.components`, вложенные составы раскрываются с умножением количества. Слово «комплект» в названии не заменяет спецификацию.
- Обычная numeric SEO-дочка может наследовать одиночный родительский товар по правилу владельца только после проверки: количество 1, явно чёрный цвет, соответствующий чёрный/монохромный якорь, одиночная роль и отсутствие конфликта модели/набора/барабана. Этот уровень (`owner_article_rule_ordinary_single`) отделён от точной модели+цвета и точного BOM. Цветная/наборная дочка не становится чёрным одиночным товаром по префиксу.

## Предлагаемая единая логика

Хранить независимо: карточка и её SKU-алиасы → кодовый якорь → подтверждённое физическое исполнение/состав → родительская группа → большой семейный контекст → фактический model_id. Каждая связь имеет источник, статус и дату. SEO — признак представления, а не физический тип.

Проверяемая граница BF: **полное точное множество конечных компонентных кодов** подтверждённого BOM. Различия количества внутри того же полного множества допускают один контекст семьи, но физические количества сохраняются для каждой карточки. В семью включаются сам набор, его компонентные родительские группы, доказанные SEO и бандлы. Смешанный набор не исключается. Прямой единственный компонентный контекст даёт назначение; несколько контекстов оставляют карточку неоднозначной. Транзитивного слияния по одному принтеру или чёрному компоненту нет. Равный united_title без проверенной полной серии даёт только кандидата, не автоматический union.

Унифицировать стоит именно поля доказательств и правило исключений, затем проверять одинаковые представления и допустимые оси склейки. Не следует пытаться сделать одну склейку из всей большой семьи: тонер, барабан, составные наборы и различные модели могут требовать разных групп Ozon.

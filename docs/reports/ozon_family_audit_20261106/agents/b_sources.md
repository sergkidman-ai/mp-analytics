# B — источники фактических объединений Ozon

Дата проверки: 06.11.2026. Аккаунт: oz_acc1. Работа только чтением; этот документ не разрешает изменения карточек.

## Рекомендации к единому снимку

1. Полный каталог = union product/list visibility=ALL и ARCHIVED. В `collectors/ozon_products.py` явно зафиксировано, что ALL не включает архив. Сохранить страницы, total, last_id, timestamps, HTTP, requested/returned/missing product_id; дедупликация по product_id, а не по SKU.
2. Для каждого product_id сохранить полный `/v3/product/info/list`: исходный model_info (включая отсутствие, null, нулевые значения, типы), model_id, count; sku и sources[].sku; is_archived/is_autoarchived; category/type; статусы, ошибки и источники. Не заменять отсутствие model_id значением offer_id.
3. Полные атрибуты `/v4/product/info/attributes` сохранить по product_id с timestamp, category/type, id/complex_id/dictionary_value_id/value; исходные объекты не нормализовать с потерями. Имеющийся `raw_ozon_attributes` — полный JSONB, но текущий collector запрашивает только ALL и делает UPSERT по offer_id; архивное покрытие и свежесть проверяются отдельно.
4. По каждой паре category/type нужна схема категории с id/name/is_aspect/is_required/is_collection и ограничения значений. Общая инструкция не устанавливает допустимую ось объединения конкретного типа картриджа.
5. Для доказательства витринного состава нужен экспорт/скриншот группы из ЛК «Товары → Объединить товары → Модель» либо наблюдение покупательской карточки с перечислением вариантов и временем. API model_id доказывает API-связь; видимость на сайте сама по себе им не доказана.

## Официальные источники

- [Как объединить карточки товаров на Ozon, 11.01.2024](https://seller.ozon.ru/media/boost/kak-obuedinit-kartochki-tovarov-na-ozon/). Требуются одна модель, одинаковые категория и бренд; среди примеров вариативности названы цвет, размер, объём и количество единиц в упаковке. Совпадение поля названия модели — механизм запроса объединения при создании, а не подтверждение успешного объединения. Отсутствие различающихся характеристик может давать различие между объединением в кабинете и отображением на сайте. Это общий материал, не специальная норма для картриджей.
- [Новое в договоре: изменения ближайших 2 недель, 31.03.2026](https://seller.ozon.ru/media/news/novoe-v-dogovore-izmeneniya-blizhajshih-2-nedel/). С 15.04.2026 разъясняет последствия объединения разных моделей, категорий или брендов и разграничивает «Модель», «Похожие товары», «Комплекты» и «Товары на фото». Формулировка вариативности короче, чем в статье 2024 года; переносить старый список на категорию без проверки нельзя.

- [Seller API, ProductAPI_GetProductInfoList](https://docs.ozon.ru/api/seller/#operation/ProductAPI_GetProductInfoList). Официальная страница доступна, инструмент web вернул 0 читаемых строк. Точное определение и scope `model_info.count` по первичной документации не подтверждены; несходство с observed count — исключение полноты, не доказанный размер пропуска.

Поиском официальных сайтов не найдена отдельная читаемая инструкция об объединении именно картриджей принтеров. Общие нормы и схема категории должны быть представлены раздельно. Посты сообщества, библиотеки сторонних разработчиков и инструкции других маркетплейсов не использованы как нормативное основание.

Сохранённый ведущим официальный ответ `/v1/description-category/attribute`, category/type `17028935/95980`, HTTP 200 (`snapshot/category_schema_17028935_95980.json`) уточняет техническую схему картриджей: 50 атрибутов; `is_aspect=true` у `8163` Объём мл, `10676` Формат плёнки, `8513` Количество в упаковке шт, `10675` Толщина плёнки, `9602` Цвет тонера/чернил. Это флаги схемы, не разрешение объединять произвольные разные модели по одному из этих значений. Обязательны, в частности, `9048` Название модели для объединения, `85` Бренд, `8229` Тип. `12141` Название модели для шаблона наименования — другой атрибут и в сравнение имени объединения не подмешивается. Ресурс, совместимые принтеры, бренд печатающего устройства и тип расходного материала не помечены `is_aspect`; их различия фиксируются для проверки, а не автоматически признаются нарушением. Странные для картриджей оси «плёнка» сохранены как факт API, не переинтерпретированы.

## Имеющиеся источники в проекте

- `collectors/ozon_products.py`: ozon_product хранит SKU-алиасы, offer_id, name, is_archived. model_info не переносится в витрину, поэтому одной таблицы недостаточно.
- `collectors/ozon_attributes.py`: полный payload в raw_ozon_attributes, ключ account+offer_id; отсутствие удалённых строк и неодновременная свежесть исключают предположение «всё текущее» без сверки.
- `docs/reports/ozon_full_inventory_20261105/analyze_inventory.py`: проверяет полноту info для union ALL+ARCHIVED, хранит ссылки на raw и время, но итоговый CSV не сохраняет model_info.count. Для аудита нужен raw.
- `docs/reports/ozon_recovery_20261103/addendum_build.py`: сопоставляет current model_id и count, но состав семей описывает по доступным членам/продажам, не даёт универсального доказательства полного состава.
- `docs/reports/ozon_wave_revision_20261106/build_plan.py`: различает артикульную связь и model_id. Назначение волны не является структурным доказательством объединения и в этом аудите не меняется.

## Критерии доказательства

- Положительный непустой model_id одного product_id = наблюдаемая API-принадлежность. Список всех product_id с этим model_id в проверенном едином снимке = весь наблюдаемый состав аккаунта.
- Сопоставление observed count с согласованным count и полным каталогом позволяет назвать группу согласованной по числу в пределах снимка. Это не доказывает исторический состав или отображение всех вариантов на витрине.
- Один наблюдаемый product_id при count>1, отсутствующем count, неполном каталоге либо несовпадающих count не является доказанной отдельной карточкой.
- Положительный model_id, count=1, один product_id, полный каталог и непротиворечивый снимок дают API-признак отдельной карточки. Витринную одиночку подтверждают ЛК/сайт.
- Отсутствующий/null/нулевой model_id не превращается в отдельную карточку автоматически.
- Общее название модели/артикульный префикс/большая товарная семья не заменяют model_id. Несколько model_id внутри семьи не означают ошибку, а смешанный фактический состав не доказывает нарушение без предметного и категорийного основания.

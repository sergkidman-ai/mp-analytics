# ТК: цены и исключение товаров из акций Ozon

Имена полей API отправки цен не изменились. Однако ошибка ТК от 26.10.2026 — `the method is blocked due to unified price logic` при исключении товара из акции — требует поправить **выбор метода удаления**. Код ТК в этом репозитории недоступен; ниже точное требование для его разработчика. Предыдущий вывод «ТК менять не нужно» относился только к отправке обычных цен и теперь не должен применяться к удалению из акций.

| Поле запроса `/v1/product/import/prices` | Значение |
|---|---|
| `prices[].price` | предельная цена товара, теперь общая для цен и основных акций |
| `prices[].min_price` | ограничение для акций и стратегий |
| `prices[].old_price` | зачёркнутая цена |

В ответе `/v5/product/info/prices` соответствующие поля вложены в `price`: `price.price`, `price.min_price`, `price.old_price`. Это имена полей чтения, не отправки.

После исправления удаления ТК тоже сможет менять общую предельную цену через `/v1/actions/products/update`: переданный `action_price` может обновить её и в разделе «Цены». Поэтому обычная отправка цен ТК и исключение из акций должны пользоваться одним расчётом цены товара и не перезаписывать друг друга разными значениями. Наш сторож отдельно координирует пересекающиеся акции, но не управляет очередью записи ТК. [Предупреждение Ozon](https://dev.ozon.ru/news/840-Seller-API-napominanie-o-edinoi-predelnoi-tsene/).

## Что исправить в удалении из акций

Выбирать метод по `action_type`, полученному из `/v1/actions`, а не по названию акции:

| Тип акции | Запрос для исключения товара |
|---|---|
| `ELASTIC_BOOSTING`, `STOCK_DISCOUNT` | `POST /v1/actions/products/update` с `action_id`, `product_id` и `action_price` (`Money`) **строго выше** `max_action_price` этой акции. Цель: `max(текущая общая предельная цена, ceil(max(max_action_price, экономический пол)) + 1 ₽)`. Если текущая общая цена уже выше лимита, сначала перепроверить участие, не повышать её автоматически ещё на рубль. Одно решение и одна запись на товар с учётом всех его действующих акций. |
| `PROMO_CODE` | `POST /v2/actions/products/deactivate` с `action_id` и `product_ids`. |
| Неизвестный тип | Остановить автоматическое удаление и показать ошибку для разбора. |

Текущие акции обоих наших кабинетов имеют типы `ELASTIC_BOOSTING` и `STOCK_DISCOUNT`; вызов `/v2/actions/products/deactivate` для них даёт ошибку новой логики. На скриншоте метод прямо назван удалением из «Промокодов», а описание направляет ценовые акции на `/v1/actions/products/update`. Официальное описание Ozon использует условие `action_price >` лимита; поэтому надёжно отправлять на 1 ₽ выше, даже если отдельный экран документации допускает равенство. [Описание перехода Ozon](https://dev.ozon.ru/start/563-Obnovlenie-metodov-raboty-s-aktsiiami-v-Seller-API-v2/).

Обрабатывать раздельно `deactivated_product_ids`, `active_product_ids`, `rejected` и `warnings`. После ответа перечитать общую цену через `/v5/product/info/prices` и участие товара в затронутых акциях. При отказе `update` не повторять `/v2/actions/products/deactivate` для ценовых акций: показать причину отказа и оставить товар на проверку. Поскольку `action_price` теперь меняет общую предельную цену, нельзя независимо подбирать разные значения по акциям одного товара.

# 12. Разведка nix.ru — разбор прогона (10 артикулов, 03.08.2026)

Материал: `docs/rebuild/data/nix_raw/` — 17 карточек, `nix_network.csv` (858 обращений),
`nix_found.csv` (209 строк). Разбор: `tools/rebuild/step9_nix_parse.py`.

## Задача 1. Есть ли адрес, отдающий список данными

Есть: **`POST https://www.nix.ru/scripts/action.php/FastSearch/goods`**, ответ
`application/json` (11 вызовов на 10 артикулов; размер ответа растёт с числом находок:
1489 Б при пустой выдаче → 20526 Б при широкой). Рядом того же семейства: `FastSearch/loadShops`,
`loadInternals`, `loadParametersValues`, `reloadParameters`, `activeParameters` — все POST, все JSON.
Всего JSON/XML-ответов 315 на 26 уникальных адресов.

**Параметры назвать нельзя.** Все FastSearch-вызовы идут методом POST **без строки запроса**
(`с query: 0`), то есть поисковый текст и номер страницы лежат в ТЕЛЕ запроса, а тело прогон
не записывал — логировались только адрес, метод, код, тип и размер. Поэтому:
- какие поля отвечают за запрос и страницу — **неизвестно**, домысливать не буду;
- можно ли брать выдачу обычным `requests` без браузера — **пока не доказано**; ответ даст только
  повторный прогон с записью тела POST и заголовков.
Отдельно: `robots.txt` nix.ru запрещает `/scripts/` — этот адрес вне разрешённого роботам.

## Задача 2. Разбор габаритов

Таблица по всем файлам — `docs/rebuild/data/nix_cards.csv` (файл, адрес, название страницы,
название из выдачи, тип, метка, строка размеров как есть, единицы, Д/Ш/В в мм, вес, годность, причина).
Итог: **карточек 17, со строкой размеров 16, без размеров 1**.
Метка у никса одна — «Размеры упаковки (измерено в НИКСе)», единицы везде **см**; вес — «Вес брутто
(измерено в НИКСе)», кг. Перевод в мм — точным ×10, исходная строка сохранена рядом; ничего
не округлялось и не досчитывалось. Метки «Габариты (ширина x высота x глубина)» в материале нет.

## Задача 3. Отбор карточек

Правила: код обязан буквально стоять в названии карточки; тип никса обязан совпадать с нашим;
`card_main.html` — главная, отбрасывается. Проверка ведётся по паре (артикул × карточка).
Сопоставление файла с артикулом — **по canonical-адресу внутри HTML**, а не по имени файла
(имена с Windows усечены и продублированы `.html.html` — по ним матчинг не работал).

**Из 10 артикулов пригодный размер получен по 6** (`docs/rebuild/data/nix_verdict.csv`):
Q5949A 10×16.5×32.1 см; CE505X 11.3×22.2×34.5; Q7516A 48.71×32.14×19.92; 006R01179 45.15×7.65×7.53;
C13S050630 7×5×19.5; C13S050629 11.5×11.2×18.2.

Не получен по 4:
- **CC388A** — обе сохранённые карточки чипы (NV-Print CH20239, ELP CH-HM-Un9X), у нас картридж;
- **NPG-28** — выдача дала драм-юниты (NetProduct N-C-EXV14D, Canon C-EXV14), у нас картридж;
- **C13S051099** — на никсе «Барабан Epson S051099», кода `C13S051099` в названии нет, тип барабан;
- **LS050099** — карточек товара в выдаче нет вовсе, единственная ссылка «Архив каталога» на главную.

Все четыре отказа — правильная работа фильтра, а не сбой: никс по OEM-коду картриджа охотно
подсовывает чип и драм-юнит той же модели.

# Чипы: внешний код → оприходование поставщика → полная карточка МС

Проверено 05.10.2026. Все запросы к МС — GET; изменения товаров и каталогов не выполнялись.

## Правильный контур

Загрузчик прайсов создаёт документы **Оприходование (`entity/enter`) на «Удалённом складе»**. Обычные приёмки закупки (`entity/supply`) — другой контур и не могут заменить проверку загруженных прайсов. Отбор ведётся по ID нужного склада, а не по одному совпадению имени документа.

Прочитаны все **185 текущих оприходований**, **17 473 позиции**, **13 групп поставщиков**. Пагинация документов и позиций завершена; для каждого документа сверено число позиций с размером ответа API. В оприходованиях найдено **1 975 из 2 842 неизвестных внешних кодов** и **5 224 их активные карточки**.

Чтобы не потерять позиции без текущего остатка, дополнительно прочитан **весь активный каталог МС: 45 088 карточек**. Для 2 708 неизвестных кодов нашлось **12 072 полных карточки поставщиков**. Для 134 неизвестных кодов активных карточек МС нет; это не доказательство отсутствия чипа. Они остаются в очереди проверки привязки/архива/ассортимента.

## Логика проверки, которую теперь можно повторять

1. Взять наш **внешний код**, не путать его с артикулом или кодом отдельного поставщика.
2. Найти все позиции текущих оприходований на удалённом складе; по `assortment.meta.href` получить точный `ms_id` товара и сохранить документ, группу поставщика и дату.
3. Сверить `externalCode` каждой карточки с исходным кодом. Дополнительно включить все активные товары этого кода, даже если они сейчас не входят в оприходование.
4. Читать **наименование, описание, «Код поставщика», «Название WB» и «Чип»**. Сохранять текст, поле и источник, а не только итоговую метку.
5. Разбирать формулировки по словарю: «с чипом», «без чипа», «б/ч», «w/o chip», «New chip», отдельный класс «чип без счётчика»; «требуется/необходим чип» и «чип отдельно» проверять как отсутствие комплектного чипа. Особое написание Blossom `w/chip` — только в контексте этого поставщика, не глобально.
6. Объединять **явные указания**, не голосовать количеством молчащих карточек. Если явные классы расходятся, вынести внешний код на проверку. Текст «не требуется чип» из шаблона не считать независимым доказательством.
7. Если все проверенные товары молчат, отдельно применить сохранённое правило «3+ товара → предполагается без чипа» и отдельно проверить, не спорит ли оно с другим правилом поставщика. Не превращать предположение в якобы найденное поле.

Словарь находится в `prices/features.py` (`CHIP_PATTERNS`), уточнения поставщиков — в `tools/prc/tc_fields.py` (`EXTRA_NOCHIP`, `name_chip`). Общий словарь и рабочие импорты прайсов не изменены. «Чип» без уточняющей формулировки нельзя механически считать комплектным чипом в любом произвольном поле: важны контекст и словарь поставщика.

## Результат для исходных 2 842 кодов

| Группа результата | Внешних кодов | Что это означает |
|---|---:|---|
| Явное указание в МС/прайсах | 21 | 19 «с чипом», 2 «без чипа»; в том числе 19 новых относительно проверки прайсов |
| Предполагается «без чипа» по старому правилу 3+ | 990 | Все проверенные карточки молчат; явного указания нет |
| Два сохранённых правила спорят | 392 | 3+ молчащих карточки дают «без чипа», правило Кактуса — «с чипом» |
| Остальные на разбор | 1 439 | Недостаточно карточек/привязок, нет активного товара, неясное или неподходящее значение |
| Всего | 2 842 | Группы не пересекаются |

**Массового восстановления явных данных не произошло:** полный обход добавил 19 кодов к двум, найденным предыдущим прогоном. Это не следует скрывать за количеством прочитанных карточек. При этом старое число 61 % объединяло совершенно разные случаи: отсутствие явного указания и возможность вывода по сохранённому правилу.

Всего 1 382 неизвестных кода имеют 3+ активные карточки, все молчат; у 1 323 из них есть как минимум три разных ссылки на контрагентов-поставщиков МС. Число карточек и число контрагентов сохранены раздельно. У 392 из 1 382 включается противоположное правило Кактуса, поэтому они вынесены отдельно; оставшиеся 990 — условная классификация, **не техническое подтверждение** отсутствия чипа.

Эти группы могут пересекаться, их нельзя складывать. По коду `prices/loader.py:card_updates` описание товара обновляется наименованием прайса с проверкой принадлежности товара поставщику. Поэтому описание — существенный дополнительный источник, которого не хватало в прежнем расчёте по одному нормализованному названию.

«Название WB» и поле «Чип» могли заполняться нашим обработчиком по ТК (`tools/prc/tc_fields.py`). Они полезны как сведения карточки МС, но не автоматически являются независимым подтверждением от поставщика. В четырёх найденных кодах указание есть только в «Название WB»; их происхождение нужно подтвердить до исправления ТК или склейки. По 17 из 19 новых кодов есть текущие оприходования; это доказывает попадание карточки в загруженный ассортимент, а не техническую истинность текста.

## Что обнаружено в самом поле «Чип»

У **11 958 карточек** из проверенных 12 072 стоит **«не указан»**. Это сохранённое пустое знание, а не признак «без чипа». Ни одного дополнительного явного класса из самого поля «Чип» в этой группе не получено.

У двух карточек, внешние коды **4354 и 4355**, в поле «Чип» записан список принтеров `DeskJet Plus Ink Advantage 6000/6075/6475`. Это неподходящее значение поля, а не класс чипа; вынесено в CSV. Остальные карточки могут не иметь заполненного поля вообще.

## Дальнейший порядок работы

1. Проверить 21 код с найденным указанием, особенно четыре, где источник только «Название WB». После проверки привязки можно заполнить общий справочник и распространить подтверждённый класс на варианты этого кода.
2. Разобрать границы правила Кактуса, начиная с десяти ранее выявленных противоположных указаний других поставщиков. До этого 392 кода с конфликтом правил не включать в автоматическую склейку по чипу.
3. Для 990 кодов сохранить именно статус «предполагается без чипа по правилу», если это правило остаётся рабочим. Для строгих склеек требовать подтверждение исполнения, а не выдавать молчание за поле поставщика.
4. В остатке 1 439 отдельно разобрать 134 кода без активных карточек МС и два неверных значения поля. Для остальных искать спецификацию исполнения и данные поставщика по точному артикулу; повторный прогон той же строки без новых данных результата не добавит.

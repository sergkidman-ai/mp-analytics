## Выполнение

- Перед первой записью заново читаются страницы поставщика для всех кодов плана. Проверяются точное название, код, нужный склад, а для шести карточек — подтверждающие значки/примечания.
- При изменении названия или подтверждения чипа запуск остановится до записи. Карточки, чей остаток соответствующего склада стал менее 4, будут пропущены с отдельным журналом.
- Перед каждой записью МС проверяются UUID, поставщик, артикул, внешний код, отсутствие архива и неизменность исходного Описания. Уже равные итоговому значению не отправляются.
- Партии до 50, пауза не менее 60 секунд. После первых 200 изменений — 10 минут и проверка доступности операционных документов МС. При медленном ответе пауза увеличивается.
- Запуск ждёт завершения `prc-enter-buyprice.service`. Вебхуки не подавляются; изменение трактуется как значимое. Контрольное чтение документа проверяет API, а не доставку вебхуков.
- Резервные копии перед записью, журнал отправки с fsync, контрольное GET-чтение каждой карточки. Автоматического повторного POST при неопределённом результате нет.

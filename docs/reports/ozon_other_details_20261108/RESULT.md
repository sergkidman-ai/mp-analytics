# Ozon: раскрытие «Прочих начислений»

По запросу пользователя добавлено раскрытие строки «Прочие начисления» в блоке
«Начисления в плюс». Проверены оба юрлица, все 10 закрытых месяцев и текущий ноябрь.

## Состав суммы

За закрытый октябрь вся строка — тип 62 `RfbsClientDeliveryCharge`,
«Перечисление за доставку от покупателя»:

| Юрлицо | Начислений | Сумма, ₽ |
|---|---:|---:|
| Цифровой | 195 | 71 951 |
| Дисквэр | 28 | 9 004 |

За январь–октябрь у Цифрового 734 702 ₽ (как в сохранённых отчётах):
доставка 404 820 ₽, корректировки услуг 331 621 ₽, компенсация −1739 ₽.
У Дисквэра 89 003 ₽, целиком доставка.

По текущим данным ноября ещё 7370/1023 ₽ соответственно. В годовом столбце
на момент проверки 08.11: Цифровой **742 072 ₽**, Дисквэр **90 026 ₽**.

Крупные исходные операции Цифрового:

- 15.01.2026, ID44057403104: +327 750,00 ₽, тип57 «Корректировка стоимости услуг»;
- 19.01.2026, ID44260652798: +3817,95 ₽, тот же тип (январь суммарно +331 567,95 ₽);
- май: +52,80 ₽, тот же тип;
- 17.07.2026, ID57195664051: −1738,63 ₽, тип10 «Компенсация».

Типы и суммы подтверждены исходными начислениями в восстановительной БД,
а не только синтетическими transaction-кодами. В исходном NON_ITEM имеются
тип и сумма, нет описания причины корректировок и документа-основания.
Совпадение +327750 ₽ с другими услугами само по себе не доказывает связь;
например, называть это возвратом за отзывы без документа нельзя.

## Реализация и сохранность закрытых данных

- В `DETAIL_LINES` добавлен `other`. Детализация доходов нормализует знак так же,
  как родительская строка; расходы продолжают работать с прежним знаком.
- Генератор использует kind родителя: положительный доход не отображается расходом,
  отрицательная компенсация сохраняется отрицательной. Название строки раскрывается
  по нажатию, как у существующих расходных строк.
- Для исторической расшифровки проверено совпадение с сохранённым `lines.other`
  по каждому из 20 account-month. Для января/мая/июля Цифрового восстановленные raw
  с нынешним классификатором не включали старые распределения type57/type10 в other.
  Эти конкретные исходные операции добавлены как `HIST:RealizationReportCorrection`
  и `HIST:Compensation` только в расшифровку прежнего закрытого итога.
- Сумма округлённых подстрок в каждом месяце равна прежнему итогу точно.
  Прочие статьи, split, COGS, прибыль, маржа, статусы закрытия и остальные детали
  не менялись; это проверено полным сравнением JSON с исключением только `detail.other`.
- Текущий классификатор операций не менялся. Октябрьская корректировка +18 325,99 ₽
  Цифрового остаётся в «Неклассифицировано», как до этой работы; здесь не было её
  переноса или повторного добавления в прибыль.
- `refresh_detail` сохраняет подтверждённую историческую разбивку доходов,
  когда восстановленный raw не объясняет прежний закрытый итог. Следующий обычный
  refresh не сотрёт восстановленные исторические корректировки.
- SQL только для чтения. Пересчёт себестоимости/маржи, закрытие или открытие месяцев,
  внешние записи МП/МС и Telegram-рассылки не выполнялись. WB/Market JSON побайтно прежние.

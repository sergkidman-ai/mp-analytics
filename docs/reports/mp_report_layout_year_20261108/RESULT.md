# Отчёты МП: жалобы Ozon, ширина таблиц и годовой итог

## Установленные изменения

- Точное правило `AccrualType_DefectFineComplaint → penalty / Жалобы покупателей`
  добавлено по прямой команде пользователя. В Ozon появляется отдельная
  раскрывающаяся подстрока в «Другие услуги и штрафы».
- За октябрь у Цифрового жалобы составляют 644,32 ₽, у Дисквэра 4347,36 ₽.
  В unclassified Цифрового остаётся положительная корректировка 18 325,99 ₽;
  у Дисквэра остаток положительный 1748,14 ₽ (корректировка минус обработка товара).
  Изменилось распределение между статьями; удержания, перечисление и прибыль
  от этого переноса не изменились. Сторно жалоб сохраняет знак.
- Снято ограничение основного контейнера 1200 px в общем оформлении отчётов.
  Все три таблицы занимают доступную ширину рядом с боковым меню; прокрутка
  остаётся внутри таблиц, названия строк и подстрок закреплены.
- Добавлен столбец «Итого 2026» (год берётся из выбранного периода).
  В него входят фактические месяцы с января по выбранный месяц включительно:
  сохранённые месяцы плюс все промежуточные открытые месяцы. Каждый учитывается
  один раз. Предыдущий год и прогноз исключены. Маржа = сумма прибыли / сумма
  оборота, средний чек = сумма оборота / сумма заказов. Суммы и количества
  складываются; проценты не суммируются.
- API живых ячеек теперь дополнительно отдаёт `value`; существующие `txt/cls`
  сохранены. Исторические ячейки содержат числовое значение и период в data-атрибутах.
  Общий JS считает итог без разбора форматированного текста и без запросов к МС/МП.
- При недоступности одного фактического месяца неполный годовой итог не показывается.
  Если в закрытых снимках нет истории конкретной новой расшифровки, её годовой
  итог — прочерк, а не предположение о нулевых расходах. Основные строки проверены.

## Что требуется для закрытия октября Ozon

Октябрь до этой работы остаётся вне `period_keys`, хотя отчёты реализации обоих
юрлиц загружены. Штатный обновлятор восстанавливает открытые данные и сохраняет
закрытые месяцы; фиксация октября в него не включалась.

Нужен штатный шаг фиксации октября и сверки с реализацией:
`freeze_estimate(2026,10)` и `reconcile_final(2026,10)` из `reports.ozon_mp_freeze`.
Выполнен предварительный расчёт через `_freeze_estimate` и `_reconcile_final`
на копии JSON в памяти: обе организации проходят, старые месяцы сохраняются.
Подтверждённая реализация применяет продажи/возвраты/комиссию и разбивку
деньги/баллы/партнёры; расходы и FIFO сохраняются. Ждать выхода реализации не нужно.
Вопрос пользователя «какое действие нужно?» не трактовался как команда менять
статус закрытия. В рамках этой работы октябрь не закрывался, ни один снимок
закрытых месяцев не изменён. Конкретный результат подготовлен к применению.

Также исправлена вводящая в заблуждение сноска живого Ozon: предварительность
теперь связана с незакреплённой финальной сверкой, а не утверждением, что отчёт
о реализации ещё не вышел.

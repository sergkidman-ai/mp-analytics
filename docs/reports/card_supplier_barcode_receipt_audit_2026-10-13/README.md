# Штрихкоды поставщиков: товары текущих оприходований МС, 13.10.2026

Только чтение. Свежие источники получены около 14:48 МСК; текущие оприходования прочитаны из МС, страницы Спринта дочитаны около 15:00 МСК. МС/ТК/БД не менялись.

Охват: последние партии `rapid`, `bulat`, `profiline`, `s_print_msk`, `s_print_spb`, всего 73 документа. Считаются уникальные действующие карточки товара МС внутри оприходований, не количество единиц на складе и не полный ассортимент поставщика. Карточки СПб/Мск считаются отдельно, даже если относятся к одному коду поставщика. Три архивные карточки Спринта исключены. Дополнительный фильтр по текущему остатку поставщика не применялся: основание включения — наличие карточки в текущем оприходовании.

## Качество и формат данных

**Рапид:** поле `Ean` непустое у 961 из 1408 карточек. У 958 сразу корректный EAN-13; ещё у одной (`SF-CLT809C`, внешний код 2629) значение `'4627199113975` содержит ведущий апостроф, как маркер текстового формата Excel. После удаления маркера EAN-13 корректен. Итого пригодных кодов 959. Два значения непригодны: `SF-CTL1100HM` / 4669 — `462719911257` (12 цифр, контрольная цифра не подходит), `SF-CTL1100HY` / 4670 — `46271991125` (11 цифр). Ещё у 447 карточек поле пустое. В полном API встречаются несколько значений в одной строке, но у товаров этих оприходований таких случаев нет. `EanImagePath` — ссылка на изображение штрихкода; дополнительных корректных кодов сверх `Ean` она не дала.

**Булат:** из 2519 карточек у 1314 корректный EAN-13, у 879 поле пустое, у 326 значение `0`. Нулевая заглушка не считается штрихкодом. Непустых полей формально 1640, но покрытие пригодными кодами — 1314. Фид датирован 13.10.2026 04:30.

**Профилайн:** у всех 1414 карточек корректный EAN-13, одно значение в строковом поле `barCode`. Дата внутри свежего ответа — 13.10.2026 14:47. `code` — отдельный GUID товара, не штрихкод.

**Солюшнс принт:** заново прочитаны все **890 уникальных кодов поставщика**, соответствующие 1422 карточкам МС из текущих оприходований. Все 890 страниц прочитаны успешно. В таблицах основных характеристик и в подписанных значениях основного блока товара штрихкодов нет. Дополнительно в основной карточке TK-3060 проверены названия полей и атрибутов HTML: BARCODE/EAN13/штрихкод отсутствуют. Код товара SP и номер поставщика не засчитывались как штрихкоды. Это результат по доступным страницам кабинета; он не означает, что сам поставщик не имеет штрихкодов в других выгрузках.

**Изипринт:** повторный GET 13.10 около 14:52 МСК завершился `No route to host`, HTTP-ответа нет. Формат и покрытие не установлены.

## Файлы

- `summary.json` — итоговые числа; `review.json` / `receipt_supplier_barcodes.csv` — полный результат по карточкам текущих оприходований, исходные значения и проверенные коды.
- `valid_supplier_ean13.csv` — 3687 карточек с пригодным EAN-13, только из указанного охвата; это данные проверки, не план записи в МС.
- `current_docs.json`, `current_positions_expanded.json` — свежие документы и развёрнутые карточки МС.
- `rapid.json`, `profiline.json`, `bulat.xml` — свежие исходные ответы; секреты не выводились.
- `sprint_product_details.json`, `sprint_pages/` — результаты чтения 890 страниц Спринта.
- `rapid_invalid_barcodes.json` — исходные три значения с отклонением формата, из них одно нормализуется удалением апострофа.
- `rapid_barcode_image_check.json`, `easyprint_access_check.json` — дополнительные проверки.
- Скрипт `tools/card_supplier_barcode_receipt_audit.py`; проверено распознавание EAN-13, UPC-A и отклонение неправильных контрольных цифр.

Проверка не изменяла существующие штрихкоды МС. Внутренние EAN-8/Code128 МС не учитывались как штрихкоды поставщика.

## Источники и метод

- Цифровой: `dropbox/20261008_184804_Natalie_Pro_natalya_Downloads.zip`, ИНН 7807355364.
- Дисквэр: `dropbox/20261008_195126_Natalie_Pro_natalya_Дисквер_отчеты_о_пострадашвих_товарах_ВБ.zip`, ИНН 7811803918.
- Оба аккаунта: не хватает официальных отчётов по Владимиру, Котовску и Невинномысску
  относительно прежнего списка складов. Старые снимки в официальный итог не включаются.
- Цифровой: архив 09.2023–07.2026; Дисквэр: 12.2024–07.2026, плюс июльский текущий список и статусы.
  Граница поиска — месяц перед первой отгрузкой соответствующей организации в МС.
- Производные числовые артикулы сведены к первым четырём цифрам (`00191` → `0019`).
  Проверены и суффиксы Дисквэра: `6414X1XF7NYJ` → `6414`, `0064X9775UHA` → `0064`,
  `4692X5BV7567` → `4692`: базовые модели/наборы ТК и фактические позиции точных nmID согласуются.
  Буквенно-цифровой хвост не трактуется как количество; чистый маркер вроде `6414X3` без состава ТК не угадывается.
- Наборы раскрыты с учётом кратности и вложенности, замены универсальных моделей — через связи ТК.
  Вся отгрузка должна соответствовать полному составу одной единицы ВБ.
- Распределение сначала максимизирует покрытие, затем суммарную дату выбранных отгрузок
  (берёт поздние доступные документы). Один UUID отгрузки используется один раз внутри аккаунта.
  Переназначение по остаточной сети исключает потери покрытия из-за жадного выбора общей отгрузки.
- **Между складами с одинаковым составом распределение условное**, в стабильном порядке названий складов.
  Статусы архива не подтверждают физический путь конкретной единицы после обезличивания возврата ВБ.
  Это расчёт по согласованному правилу выбора документов, а не доказательство их связи с потерей.

## Фактическая себестоимость МС

Для выбранного документа — `report/stock/byoperation?operation.id=<UUID>`.
`positions[].cost` — сумма списания позиции в копейках; итог отгрузки = сумма этих стоимостей / 100.
Поле `quantity` отчёта не используется как количество отгрузки: это текущий остаток.
Количество и полнота состава — из позиций документа МС.

Полный положительный локальный кэш `ms_demand_pos` принимается, если количества согласованы
с фактическими позициями, сумма совпадает с `ms_demand_cogs.cogs` и принадлежность аккаунту проверена.
При отсутствии/расхождении кэша точечно запрошен оригинальный отчёт МС; сырой ответ сохранён.
Два самых дорогих выбранных документа из кэша Цифрового дополнительно сверены с живым отчётом МС — суммы совпали.
Нет подстановок из приёмок, закупочных цен, витрины, текущей цены ТК или усреднения по истории.
Отсутствие стоимости не меняет выбор отгрузки на более раннюю с известной стоимостью.

Новые таблицы: `wb_loss_demand_cost`, `wb_loss_cost_result`, миграция 513.
Финансовые витрины и источники других потоков не изменены.
Сырьё/результаты разделены, повторный расчёт использует сохранённые источники.

## Артефакты и воспроизведение

- `ops/wb_loss_official.py --account wb_acc1|wb_acc2`: импорт, архив, подбор, точечные документы МС.
- `ops/wb_loss_cost.py --account wb_acc1|wb_acc2`: выбор поздних отгрузок и фактическая себестоимость.
- `data/wb_loss/cost_wb_acc1.json`, `cost_wb_acc2.json`: подробный снимок выбранных документов и источников.
- `data/wb_loss/cost_products.csv`: 541 строка официальных отчётов с покрытием и рассчитанной суммой.
- `data/wb_loss/cost_shipments.csv`: 562 выбранные отгрузки, дата/стоимость/фактические позиции.
- `data/wb_loss/cost_unresolved.csv`: непокрытые строки с причинами.

После обновления `match` обязательно повторить расчёт `wb_loss_cost` для соответствующего аккаунта.
Статусы WB и источники МС используются как сохранённый снимок исследования, не обновляются автоматически.

Проверки: 15 тестов (PDF/наборы/производные коды/кратность/распределение/неповторное использование/
неподмена отгрузки из-за отсутствия стоимости), API всех 18 PDF и деталей строк, арифметика по документам,
разделение аккаунтов. Живая страница проверена Chromium, включая выбор документов и мобильную ширину.

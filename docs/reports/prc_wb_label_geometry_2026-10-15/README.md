# Название WB — проверка геометрии по образцам, 15.10.2026

Второй этап выполнен в пределах доступных источников: добавлена общая проверка ширины
текста и двух строк. Она включена в Пульте и массовом dry-run, версия `2026-10-15.2`.
**Исходный шаблон МС и физическая печать не проверены.** Расчёт по PDF-образцам
не отмечен как проверка исходного шаблона и сам по себе не разрешает ночную запись.

## Источники и расчёт

- Четыре исходных товарных PDF из Dropbox прежние. Новый архив 15.10 содержит
  ярлыки складских ячеек, не исходник товарной этикетки. В доступных файлах проекта
  экспорт шаблона товарной этикетки не найден.
- Размер этикетки — 58×40 мм; название — NotoSans Regular 9 pt. Полностью видимая
  строка «фотобарабаном и девелопером» имеет ширину **141.12 pt** и находится в границах
  страницы. Третья строка названия на присланных образцах выходит за нижнюю границу.
- Для консервативной проверки взята ширина **140 pt (49.39 мм)**, меньше наблюдаемой
  полностью помещающейся строки. По числу букв ширина не оценивается: используются
  суммы ширин конкретных глифов NotoSans 9 pt. Перенос — по пробелам, без деления
  кодов моделей или составных цветов.
- Получен [эталонный NotoSans-Regular](https://github.com/notofonts/noto-fonts/tree/main/hinted/ttf/NotoSans)
  с лицензией OFL. Ширины **всех 61 глифа**, извлечённых из встроенных шрифтов четырёх
  исходных PDF, совпали с эталоном. Для 11 строк расхождение с округлёнными координатами
  XML не превышает 0.5 pt. Источники, SHA256 и координаты сохранены в `font_source.json`,
  `embedded_font_widths.json`, `font_validation.json`.
- Для прочих глифов используется эталон той же гарнитуры; совпадение именно этих
  глифов с не полученным шаблоном отдельно не доказано. Неизвестный глиф блокирует
  строку. Расчёт предполагает сохранение шрифта/кегля/полей присланных образцов.

В рабочий код добавлены только таблица метрик и лицензия:
`prices/data/wb_label_font_metrics.json`, `prices/data/NotoSans-OFL.txt`.
Зависимость от fontTools в рабочем генераторе не появилась; библиотека нужна только
для подготовки таблицы и расчётного PDF в текущем окружении.

## Новые правила в общем генераторе

`prices/wb_label.py` теперь сокращает название при **любом** из двух условий:
длиннее ориентира 50 знаков либо требует больше двух строк по указанной геометрии.
После сокращений обязательны предел 55 и размещение в две строки. Полностью
непомещающийся отдельный код модели не разрезается — карточка уходит в разбор.
Словарь сокращений и защищённые признаки товара сохранены.

Это закрывает случай, который не ловил один счётчик символов:

«Лента для принтера JP-7-M/817562 для Ricoh черный» — **49 знаков, но три строки**.
После словарного сокращения «черный → черн.» — две строки, модель сохранена.

## Проверки и просмотр

- **44 теста прошли**, включая реальные обрезающиеся образцы, имя короче 50 знаков,
  требующее трёх строк, сохранение целого кода модели и отказ на неизвестном глифе.
- **13 470 сравнений** Пульта и массовой формулы, **0 различий** — `formula_parity.json`.
- Шесть кандидатов с шириной строки возле границы перечитаны из живого МС: идентичность,
  прежнее поле и результат генерации совпали во всех 6. Это выборочная проверка, не
  замена полного preflight. Результат — `live_sample_checks.json`.
- `mp-dashboard` перезапущен. Живая форма отдаёт `2026-10-15.2`; старое ручное название
  отклоняется в проверке `dry=true`, карточки не создаются — `live_pult_checks.json`.
- `label_geometry_preview.pdf`: **7 пар «до/после», 2 страницы**. Размер рамки каждого
  образца 58×40 мм, шрифт 9 pt. Внутри каждого явно написано «расчётный макет / не для
  печати». Штрихкод заменён обозначением его зоны, чтобы макет нельзя было принять за
  рабочую этикетку. HOLD вместо неправильного товара не содержит предложенного имени.
  PDF проверен на корректность страниц/встроенного Unicode-шрифта и извлечение текста.

## Следующее действие

Нужна проверка в исходном редакторе МС и/или контрольная печать по настоящему шаблону.
Официальный порядок экспорта: открыть редактор этикеток через «Печать → Настроить»,
затем «Экспортировать»; см.
[инструкцию МойСклад](https://support.moysklad.ru/hc/ru/товары%20и%20склады/этикетки%20и%20ценники/как_сделать_ценники_и_этикетки_в_моемскладе).
Из доступных API-путей исходник редактора получить не удалось; отсутствие шаблона в
аккаунте этим не доказано. Подменять такую проверку утверждением «шаблон проверен» нельзя.

Остаются также условия ночного прогона из первого этапа: потребление поля/добор ТК,
место для резервных копий/журналов, свежий preflight и замороженная партия. Пользователю
задан отдельный вопрос о потреблении поля ТК, ответ пока не получен. Подписки не менялись.
В [ms-mass-change](../../../.claude/skills/ms-mass-change/SKILL.md) прямо указано:
«Нет списка → изменение считается значимым»; для значимого изменения «подавление ЗАПРЕЩЕНО».
Поэтому уведомления не подавлялись, ночной запуск не назначен до проверки потребителей
и остальных условий. Это условие регламента, не новый запрос разрешения на саму задачу.

Записей карточек МС **0**, новых расписаний **0**. Коды/модели/штрихкоды исходных
карточек не менялись. Изменён и перезапущен только общий генератор и его проверки.
Работа в общем main без переключений, коммитов и пушей; чужие изменения сохранены.

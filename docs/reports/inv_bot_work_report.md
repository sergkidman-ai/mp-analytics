# Отчёт по работе: Телеграм-бот «Счета и УПД → МойСклад»

Период: 20–29 июля 2026. Поток `inv`. Модули: `invoice_bot/` (~2700 строк, 5 модулей),
14 профилей поставщиков, 4 адаптера УПД, ~30 содержательных правок.

---

## 1. Изначальное ТЗ (языком заказчика)

> Нужен бот, которому пересылаешь в Телеграм (или он сам забирает с почты) файл счёта или
> УПД от поставщика — а он без ручного ввода заводит документ в МойСклад:
> 1. распознаёт тип документа и определяет поставщика;
> 2. по **счёту** создаёт **Заказ поставщику** — нужный склад, дата, НДС, номенклатура
>    подобрана по артикулам, итог сходится со счётом до копейки;
> 3. по **УПД** создаёт **Приёмку** на этот заказ — переносит номер ГТД и страну
>    происхождения построчно, пишет закупочную цену в карточку товара;
> 4. чистый счёт проводит сразу, спорный оставляет черновиком на проверку;
> 5. по команде `/report` показывает сводку: что закрыто, что ждёт УПД, где реальные ошибки;
> 6. работает круглосуточно, секреты в защищённом месте.

---

## 2. Этапы (факт. часы работы, без простоев)

### Этап 1. Анализ и проектирование — ~7 ч
- Разбор API МойСклада: Заказ поставщику, Приёмка, товары, справочники ГТД/стран; схема
  связки **счёт → Заказ → УПД → Приёмка**.
- Инвентаризация реальных форматов 14 поставщиков (xls / pdf / xml-ЭДО); ключ связки =
  артикул поставщика.
- Архитектура: единый движок, независимый от канала + драйверы (Телеграм / почта); сырьё
  отдельно от расчёта; идемпотентность (повтор не плодит дублей).

### Этап 2. Реализация — ~45 ч
- **Движок счёт → Заказ поставщику** (`invoice_to_po.py`, 764 стр.): парсер xls/pdf, 14
  профилей поставщиков, правила склада/даты/НДС/номера, подгон итога под сумму счёта.
- **Движок УПД → Приёмка** (`upd_to_supply.py`, 1024 стр.): 4 адаптера — Excel-1С,
  PDF печатной формы 1137, XML ЭДО (Диадок), отдельный ГТД-реестр Спринта; матч позиций,
  перенос ГТД + страны, запись закупочной цены в карточку.
- **Каналы приёма**: Телеграм-бот (`tg_bot.py`) + почта IMAP (`mail_poller.py`) + dropbox.
- **Сводка `/report`** (`proc_log.py`) со сверкой состояния с МойСклад.
- Сервисное: автопроводка чистых счетов, автоприёмка для поставщика без УПД (Колортек),
  автоуборка обработанных файлов (хранение 7 дней), systemd-сервисы 24/7.

### Этап 3. Тестирование — ~14 ч
- Прогоны на реальных счетах и УПД всех поставщиков, сверка суммы с документом до копейки.
- Сверка Приёмок с Заказами (сумма / позиции / ГТД), контроль идемпотентности (без дублей).
- Регрессия парсера итога по ~35 счетам.

### Этап 4. Исправление и доводка — ~21 ч
~15 точечных правок по мере поступления реальных документов:
- **Парсинг:** рваный ГТД в PDF (голова+хвост), формат Булата, целые итоги без копеек,
  отсечка «в том числе НДС», float-итог без хвостового нуля, наборы Феррета (`CSP-…SET`).
- **Логика МС:** коллизия номеров в пределах поставщика, каноничный номер Одиссея
  (`ОД00004753`), дедуп Приёмки по заказу-основанию, кандидаты только без приёмки, матч
  ГТД по артикулу внутри наименования строки УПД.
- **Отчёт:** окно свежести (пред. рабочий день + сегодня), сверка ошибок с МС, дедуп
  успех↔провал по имени файла без таймстамп-префикса.

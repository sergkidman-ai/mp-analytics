# Ночной снимок и первый этап оптимизации МС — 09.11.2026

## Ночной снимок подтверждён

Действующий /etc/cron.d/mp-promo-guards запускает существующие
collectors/ms_products.py и collectors/suppliers.py --light --no-turnover
ежедневно21:10UTC /00:10МСК. Последний штатный запуск08.11 21:10UTC завершился
08.11 21:13:17UTC /09.11 00:13:17МСК, без перезапуска полного сбора в этой задаче.
Каталог56994 карточки (45321живых/11673архивных), supplier_stock за09.11 —19097
строк по складам; снимки за06–08.11 также существуют. Дата supplier_stock в МСК.
Источник проверки: БД и logs/promo-ms-snapshot.log.

Снимок уже используется сторожами цен/акций и складской аналитикой. Подходит для
аналитических страниц, предварительного отбора и фоновых сравнений. Закупочная
buy_price в нём — поле карточки МС, а cost_seb — поле отчёта остатков; ни одно не
подменяет подтверждённый FIFO конкретной отгрузки. Остаток/резерв ночного снимка
не является свежим наличием перед резервированием или отгрузкой.

Исправлены две ошибки лёгкого снимка: при наличии старых названий поставщиков
закупочная цена переносилась из старого supplier_stock вместо свежего каталога;
теперь цена всегда из ms_product, ноль/отсутствие не подменяются старой ценой.
Полностью обнулившийся склад теперь удаляет свои старые строки той же даты.

## Что включено

1. core/ms_api_control.py — файловый межпроцессный диспетчер на одном сервере:
   максимум3 одновременных HTTP, фон максимум1, ожидающим операционным чтениям
   приоритет перед фоном. Общий бюджет30 единиц за3сек с учётом веса3/4 обычного
   запроса и5 для stock/all,bystore. Действует общая пауза по заголовкам429 и при
   исчерпании оставшегося бюджета. Слоты освобождаются при ошибке/гибели процесса.
   Запросы POST не получают новых автоматических повторов; прежняя обработка
   неопределённого результата сохраняется. Ошибка записи телеметрии не превращает
   успешную запись МС в ошибку. В телеметрию не попадают auth/query/payload/UUID.
2. Подключены основные клиенты: core.ms_api, invoice_bot.ms, collectors.moysklad,
   ms_products/suppliers, shipment_guard.ms/CustomerMS, FBO proof, прямые MS-записи
   импортёров/обработчика статусов и клиент печати. Адреса других МП не ограничиваются.
   Рабочий customer guard из immutable runtime обновлён точечно; пользовательские
   изменения исходников сохранены. Добавлено разрешение каталога состояния в
   sandbox FBO-сервиса, проверенное отдельным systemd-процессом без HTTP.
3. core/ms_enter_cache.py — общий сжатый кэш полных позиций оприходования по
   (id,updated). Требуются полнота, уникальные ID строк, исходная версия и контрольная
   сумма. При изменении/замене документа старый кэш не используется; повреждение
   даёт cache miss. Свежие заголовки и проверки версии до/после чтения сохранены.
   Пульт и импортёр используют один кэш. Наличия/резервов/заказов/FIFO в этом кэше нет.
4. Импортёр сохраняет обе проверки общей генерации прайсов и конфликтов цен,
   но загружает позиции только изменённых документов. Холодный проход однопоточный.
   Изменение одного поставщика больше не заставляет скачивать позиции всех остальных.
5. В прежнюю ночную цепочку после снимка добавлен ops.ms_enter_cache_warm:
   использует существующий current_purchase_prices, не создаёт новый загрузчик.
   Прогревает проверенные позиции прайсов. При неизменившихся версиях нужны только
   контрольные списки документов. Все ночные чтения имеют background-приоритет.

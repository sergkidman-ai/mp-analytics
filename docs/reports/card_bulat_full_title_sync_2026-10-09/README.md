## Расписание и исполнение

Таймер `card-bulat-full-title-20261009.timer` установлен и включён. Следующий запуск подтверждён: **09.10.2026 18:00 UTC = 21:00 МСК**. Это один запуск на конкретную дату, не ежедневная задача. Меняется только `description`. Перед записью перечитывается каждая карточка, сверяются поставщик, артикул, внешний код, активность и прежнее описание. Менявшиеся вручную описания не перезаписываются. Полные резервные копии сохранены до каждой партии, журнал содержит отправленные и проверенные id. Партия 50 с паузой не менее 60 секунд, после первых 200 — пауза 10 минут и контроль чтения операционного документа. При медленном ответе пауза увеличивается. Проверка результата — GET каждого изменённого товара; лимит/ошибка останавливает запись, неопределённые записи автоматически не повторяются.

Используется общий проверенный исполнитель из `tools/card_rapid_description_sync.py`, без изменения области Рапида. Новые значения supplier_id из плана проверены на группу Булат. Вебхуки не подавляются; изменение считается значимым, полный список потребителей неизвестен. Контроль чтения документа не является доказательством доставки вебхуков. Старт блокируется при работающем `prc-enter-buyprice.service`. Лимит времени сервиса 1ч40мин — до следующего массового задания закупочных в 23:05 МСК.

Результат после запуска: `summary.json` (`status=complete`, `writes=verified`), `journal.jsonl`, `backup_batch_*.json`. Для возврата — `old_description` из плана и резервные копии; автоматического отката нет, чтобы не затереть более поздние ручные изменения. Перед повторным стартом требуется разобрать журнал, штатный повтор с журналом запрещён.

Проверка systemd-единиц и десять тестов общего исполнителя/выделения названия/нулевого остатка/области одобренных значений прошли. Подтверждение установленного расписания: [schedule_verification.json](schedule_verification.json). Коммитов/пушей нет.

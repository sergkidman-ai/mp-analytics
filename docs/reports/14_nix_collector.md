# 14. Массовый сбор габаритов с nix.ru — сборщик готов к запуску (03.08.2026)

Путь: браузер + карточки `/autocatalog/`. Внутренний JSON `/scripts/` не используется.
К nix.ru с сервера не обращались ни одним запросом; проверки делались офлайн, на уже
сохранённом материале прошлого прогона.

## 1. Ключи поиска — колонка `article` добавлена

`tools/rebuild/step8_nix_input.py`: артикул берётся из **уже выгруженной** таблицы
`ms_product` (поле «Артикул» МойСклада), к API МС не обращались. Карточка модели —
та, чьё название стоит в этой же строке (та же выборка, что и для OEM).

| | строк |
|---|---|
| всего моделей в `nix_input.csv` | 2540 |
| получили `article` | **2459** |
| без `article` (в выгрузке пусто) | 81 |
| есть хотя бы один ключ (`article` или `oem_article`) | 2475 |

Из очереди: только `article` — 1482, оба ключа — 662, только OEM — 16.
Остальные 328 из 2475 — бумага, чернила, ленточные кассеты, мастер-плёнка: наш тип
не читается однозначно, сверять тип не с чем → пропуск («лучше пусто, чем чужой размер»).
Обе строки посылаются в поиск **как есть**, посимвольно: без нормализации, без снятия
префиксов/суффиксов, без приведения регистра.

## 2. Что изменено в механике (`tools/nix_collect.py`, новый файл)

- `wait_for_selector(..., **state='attached'**)` — ссылки выдачи в DOM есть, но невидимы;
  ожидание видимости и давало ложный таймаут 30 с;
- имя сохраняемого файла — **из canonical-ссылки внутри HTML**, не из заголовка;
- карточки складываются в `nix_raw/<external_code>/`;
- ключ `article` → при пустом результате отбора `oem_article`; оба пусты — пропуск с причиной;
- запуск, паузы и окно браузера — как в рабочем пробнике: `headless=False`, `locale=ru-RU`,
  viewport 1360×900, десктопный User-Agent, один поток, пауза 5–8 с случайная (и между
  моделями, и между карточками), resume по журналу, лимит моделей аргументом.

## 3. Как устроен отбор (до открытия карточек)

Из выдачи забираются **все** ссылки `/autocatalog/` с заголовками, затем отсев по заголовку:
код обязан стоять в заголовке; тип обязан совпасть с нашим (чип, девелопер, термоплёнка,
барабан = фотобарабан = драм-юнит, тонер-туба, картридж = тонер-картридж, тонер); тип не
читается — карточка пропускается; главная и «Архив каталога» — не карточки. Из прошедших
открываются **до пяти**. Каждая ссылка с вердиктом пишется в `nix_links.csv` — фильтр
проверяем задним числом.

Проверка отбора офлайн на выдаче прошлого прогона (10 моделей, заголовки как есть):
Q5949A 71→26 прошло, CE505X 67→23, Q7516A 41→16, 006R01179 10→5, C13S050630 3→1,
C13S050629 2→1; CC388A 5→0 (в выдаче только чипы), NPG-28 7→0 (драм-юниты),
C13S051099 2→0 (барабан без нашего кода), LS050099 1→0 (карточек нет). Это те же
6 из 10, что дали размеры вручную, — фильтр воспроизводит прежний результат и теперь
берёт до 5 источников вместо одного.

## 4. Разбор карточек

Парсер прежний: «Размеры упаковки (измерено в НИКСе)», «Вес брутто (измерено в НИКСе)»;
см→мм только точным ×10, исходная строка сохраняется рядом. По каждой величине в
`nix_dims.csv` пишутся файл, канонический адрес, заголовок карточки, метка и точная строка.
Проверено на 17 сохранённых карточках: 16 с размерами, 1 без — совпадает с прошлым разбором,
имена файлов из canonical уникальны (17/17), усечений и `.html.html` больше нет.

## 5. Флаги коробов — `tools/rebuild/step11_nix_flags.py`

Флаг — пометка, а не повод менять число. Правило 1: один и тот же короб у одного бренда
на ≥5 разных моделях → «универсальная коробка». Правило 2: внутри модели один источник
по объёму ≥2× следующего → «выброс вверх», совпадающие остаются. Выход —
`nix_dims_flagged.csv` с колонками `флаг`, `короб_сорт_мм`, `объём_л`, `бренд`.

Два подозрительных из прошлого прогона — **только по найденным источникам, без эталонов**:
- **Q7516A**: Cactus 199.2×321.4×487.1 мм = 31.19 л и NV-Print 185.9×246.9×471.1 мм = 21.62 л.
  Два независимых источника дают одинаково крупный короб (отношение 1.44×, до порога выброса
  не дотягивает). Вывод по имеющемуся: это не опечатка одного прайса, но и не подтверждение
  розничной упаковки — нужны остальные источники нового прогона.
- **006R01179**: Hi-Black 451.5×76.5×75.3 мм = 2.60 л и Sakura 315×150×93 мм = 4.39 л.
  Формы разные, объёмы одного порядка, выброса нет.

## 6. Готовность

Скрипт готов к запуску на 100 моделях: `python nix_collect.py 100` (рядом положить
`nix_input.csv`). Оценка времени: ~1 мин на модель (выдача + до 5 карточек с паузами) →
около 1.5–2 часов на 100 моделей. Вернуть: `nix_collect_log.csv`, `nix_links.csv`,
`nix_dims.csv`, `nix_collect.log` и папку `nix_raw` архивом.

В лог по каждой модели: ключ и сработал ли он, ссылок в выдаче, прошло отбор, карточек
открыто, размеров прочитано.

Ограничения соблюдены: к nix.ru с сервера ни одного запроса; в WB/Ozon/Яндекс и реестр
ничего не писалось; к API МойСклада не обращались (только выгруженная таблица);
платного не трогали; размеры не додумывались и не усреднялись.

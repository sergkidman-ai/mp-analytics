# H-009 — автоматическая сверка экспериментов Ozon (22.08.2026)

Режим: `SHADOW_MODE_V0_1`. Оценщик: `EVAL_V1_0`. Аккаунт: `oz_acc1`.
Ни одной записи в БД, ни одного POST/PUT/DELETE, ни одной правки кампаний, цен, бюджетов
или cron. Все 193 теста контура зелёные.

## 1. Что закрыто

Разрыв был между «эксперимент запущен» и «вывод записан»: до сегодня `ozon_hypo.py evaluate`
показывал только календарь дат сверки и записывал решение человека, а само измерение,
проверка зрелости, выбор метода и фиксация вывода делались руками в каждой сессии заново.
Переходы `MEASURING → EVALUATED → KEEP/ROLLBACK/INCONCLUSIVE` в коде были недостижимы.

Теперь одна команда:

```bash
venv/bin/python tools/ozon_hypo.py evaluate-ready [--dry-run] [--only E5,E6] [--today ГГГГ-ММ-ДД]
```

делает восемь бывших ручных операций: ловит наступившую дату сверки → проверяет зрелость
каждого нужного источника → читает контракт, написанный ДО вмешательства → сверяет состав
когорты со снимком → ищет пересечения с другими экспериментами → считает эффект нужным
методом → выносит вердикт с кодами причин → дописывает вывод в append-only журнал.

## 2. Четыре сущности разведены

| поле | смысл | сегодня |
|---|---|---|
| `treatment_result` / `effect` | что произошло с метриками | считается |
| `verdict` | доказан ли эффект (метод) | считается |
| `recommendation` | что предлагается | считается |
| `decision` | что разрешил человек | **всегда `null`** |
| `execution` | что принял API | **всегда `null`** |

KEEP и ROLLBACK в журнале — рекомендация. Ни одна запись за сегодня не содержит решения
или исполнения (проверено: `решений записано: 0, исполнений: 0`).

## 5. G6 за 21.08 — не выполнен, и это правильный ответ

Витрина `mkt_ozon_ads_sku_daily` по `oz_acc1` доехала только до **2026-08-20**
(строк за 21.08 — ноль). День не зрелый, вердикт не выносится. За 22.08 не запускалось.

Побочная находка: старый `ozon_exp_eval.py g6 --date 2026-08-21` на пустой витрине выдавал
**ложный RED** — нули читались как обвал показов ядра. Это ровно тот класс ошибок, ради
которого H-009 и делался. В `cmd_g6` добавлен гейт зрелости: незрелый день теперь возвращает
`DATA_NOT_MATURE` вместо вердикта. Отчёт-артефакт ложного RED удалён.

G6 на последнем зрелом дне (20.08) через новый контур: `NO_CAUSAL_CLAIM` — сторож
`SPEND_X2` = 1.68 (норма), `STOCK_SHARE_MIN` = `UNAVAILABLE`. Причина `UNAVAILABLE` честная:
из 81 SKU стабильного ядра только 33 вообще находятся в прайсе поставщика по
`external_code`, поэтому доля «в наличии» мерила бы качество стыковки, а не наличие товара.
Старый `g6 --date 2026-08-20` отдельно: «Норма, оба порога не превышены».

## 6. Память — только дозапись

`docs/experiments/ozon_evaluations.jsonl`, 14 записей, 14 уникальных `evaluation_id`.

Идентичность оценки = `(hypothesis_id, experiment_id, contract_version, cohort_hash,
data_as_of, отпечаток зрелости, evaluator_version)`. Отсюда:

* повторный запуск на тех же данных → `дубль`, файл не растёт (проверено прогоном подряд);
* дозагрузка данных меняет `data_as_of` → **новая** запись со ссылкой
  `supersedes_evaluation_id` на прежнюю, прежняя не трогается;
* правка контракта меняет `contract_version` → новая версия оценки.

Причина файлового журнала, а не таблицы: `mkt_ozon_bid_journal` исторически переписывался
через `ON CONFLICT DO UPDATE` — такая память теряет прошлое. Миграции production-БД в этой
сессии не делалось.

## 7. Что осталось ручным

1. **Решение** KEEP/ROLLBACK и его исполнение — только человек, отдельной командой.
2. **Написание контракта** до вмешательства — новый эксперимент без контракта не оценится.
3. **Снимок когорты** в CSV при запуске: без снимка дрейф состава не ловится
   (сегодня снимки есть у E5/E6/E7/E8, у E1/E3 их нет — исторические).
4. **Свободнотекстовые сторожа** («не ронять органику ядра») — глазами; машинно они
   помечаются `GUARDRAIL_UNAVAILABLE`, а не молча пропускаются.
5. **Поисковая витрина недельная** — суточного среза нет, `SEARCH_VIEWS_DROP` на окнах,
   не кратных неделе, остаётся оценкой.
6. **Запуск по расписанию** — cron не трогали, команда запускается руками.

## 8. Готовность контура после H-009

OBSERVE → HYPOTHESIZE → PRIORITIZE → DESIGN → VALIDATE → PLAN → **MEASURE → EVALUATE →
MEMORY** автоматизированы. Не автоматизированы и автоматизированы не будут без отдельного
решения: DECIDE и EXECUTE.

# План нормализации «Название WB» в МойСкладе — 15.10.2026

Статус: **в работе по команде пользователя «давай пошагово выполнять»**.
Общий генератор и проверка перед сохранением включены в Пульте; отчёт первого этапа —
`docs/reports/prc_wb_name_shared_2026-10-15/README.md`. Массовая запись карточек не выполнялась,
новое расписание не создавалось. Приведённые ниже числа — первоначальная оценка;
актуальный dry-run лежит в отчёте первого этапа.
Текущая задача пользователя: найти действующую формулу, проверить реальные этикетки,
согласовать правила, затем подготовить ночное массовое обновление.

## Найденный алгоритм

Единственная реализация: `tools/prc/wb_fill.py:compose()`; правило 41 —
`docs/PRC_RULES.md`. Обёртка `prices/ms_import.py:wb_compose()` добавляет XL из
названия поставщика. Основной источник — активная модель ТК по точному `externalCode`.

Формула: **тип + модель + «для» + бренд принтера + дополнительное название + цвет +
чип + XL + объём/масса содержимого для тонера/чернил**. Пустые необязательные части пропускаются.

- «Комплект картриджей/фотобарабанов/чернил» → «Набор …».
- Удаляются «№» и лишние пробелы.
- Бренд принтера выбирается по числу совместимых принтеров; Konica Minolta → Konica,
  F+ Imaging → F+, Fuji Xerox → Xerox. Если бренд уже в модели, повтор не добавляется.
  Равные голоса разных брендов перед массовой заменой требуют проверки.
- Дополнительное название — синоним модели; перечень через запятую не печатается.
- Цвета приводятся к словарю; у комплектов перечень цветов опускается.
- Чип берётся из подтверждённого поля. Пустой признак не превращается в «без чипа».
  Противоречие между ТК и явным признаком товара поставщика блокирует строку.
- Увеличенная ёмкость даёт XL. Явный XL из названия поставщика сохраняется по действующей обёртке.
- Для тонера берётся масса содержимого в граммах, для чернил — объём в мл;
  `volume_ml` используется по принятому правилу типов, вес брутто не подставляется.

Старые программы нельзя запускать на весь каталог с `--apply`: `wb_fill.py` обрабатывает
только пустые названия, а его записывающая часть не реализует современный ночной регламент.
`wb_name_repair.py` ограничен карточками старого диалога новинок. Нужен отдельный исполнитель,
который переиспользует единую формулу и меняет уже заполненные ручные значения.

## Обязательное согласование с «Новинками» Пульта — уточнение пользователя 15.10

Нормализация существующих карточек и создание новинок должны использовать **одну
реализацию формулы, один лимит и один словарь сокращений**. Обновление генератора
новинок входит в эту задачу и должно предшествовать первой ночной волне.

Проверен действующий путь в коде:

- `web/app.py:novelties_ms_form`, GET `/api/novelties/ms-form`, вызывает
  `prices/ms_import.py:wb_compose()`, которая использует `wb_fill.compose()`.
- После `compose()` обёртка может дописать «XL ресурс» из имени поставщика.
  Поэтому сокращение и проверка лимита должны выполняться **после добавления всех
  признаков**, включая этот XL, а не только внутри базовой формулы.
- `web/static/novelties.html` показывает редактируемое поле «Название WB» и отправляет
  его как `c.wb`; POST `/api/novelties/ms-create` переносит полученное значение в
  `Доп. поле: Название WB`. На проверенном участке сохранения нет повторного применения
  формулы или контроля размещения: одной правки генератора черновика недостаточно.

В реализации после согласования предусмотреть:

1. Общий генератор окончательного названия: смысловая формула → все подтверждённые
   признаки товара → общие сокращения → проверка лимита и размещения. Его используют
   черновик новинки, конвейер создания карточек и массовый исполнитель.
2. Общую серверную проверку перед записью: ручная правка и диалог, открытый до
   обновления правил, также проверяются. Неподходящее значение не должно молча попасть
   в МС; показать причину и предложенный вариант. Клиентский счётчик — только подсказка.
3. Сохранить существующее различие источников: у новинки без модели ТК возможен
   разбор имени поставщика с предупреждением; массовая замена без подтверждённого
   источника остаётся исключением. Правила формирования и сокращения при одинаковых
   подтверждённых признаках должны совпадать.
4. Проверки совпадения результата новинки и массового dry-run на одинаковых данных:
   короткие и пограничные названия, длинные модели, XL из поставщика, дополнительные
   коды, редкие цвета, чипы, тонеры/чернила и наборы. Отдельно проверить сохранение
   ручного длинного значения и старого открытого диалога без записи в МС.
5. Сначала включить и проверить общие правила в Пульте; затем заново сформировать
   массовый dry-run той же версией правил и заморозить ночную волну. При повторном
   расчёте уже нормализованного товара не должно возникать новой дельты только из-за
   различий между Пультом и ночным инструментом.

Это обязательный критерий готовности к ночному обновлению. Изменения рабочего кода
Пульта и МС в ходе уточнения плана не выполнялись; прежний preview остаётся оценочным.

## Проверка этикеток

Источник: `dropbox/20261015_122453_Natalie_Pro_natalya_Downloads.zip` — четыре PDF.
Оригиналы извлечены в `labels/`, координаты — `label_metrics.json`, полный текст,
включая выходящий за страницу, — `label_full_text.json`. Проверены программным извлечением
текста и координат PDF; физическая пробная печать пока не выполнялась.

Все страницы **58×40 мм** (164.41×113.39 pt); название — NotoSans, 9 pt, межстрочный
шаг около 11 pt. Третья строка начинается около 108 pt и выходит за низ страницы.
Свободное место под название фактически рассчитано на **две строки**.

| Образец | Длина с пробелами | Результат |
|---|---:|---|
| Блок проявки A08ER70100… | 67 | «Konica черный» выходит третьей строкой |
| Картридж 071H… | 57 | «ресурс» выходит третьей строкой |
| Картридж 054HBK… | 59 | «ресурс» выходит третьей строкой; отдельная надпись BK не включена в название |
| Картридж CF543X… | 55 | Полностью помещается в две строки |

**Предлагаемый ориентир — 50 знаков; абсолютная граница — 55, включая пробелы.**
Это рабочая политика по четырём образцам, а не универсальная гарантия печати: ширина
букв и переносы важнее самого счётчика. Обязательный дополнительный допуск — название
целиком укладывается в две строки в реальном шаблоне с существующим шрифтом и полями.
Строка даже в 50 знаков, требующая третьей строки, не допускается к записи.
Текущие 60 знаков не подходят: фактическое обрезание есть уже при 57.

## Предлагаемые сокращения — в порядке применения

1. Собрать полное название единой формулой, убрать лишние пробелы и повторы,
   которые уже запрещены формулой. Основную модель не менять.
2. Если длиннее 50 либо не помещается в две строки — убрать дополнительный синоним
   модели (`5646C002`, `3028C002` и т.п.), сохранив основную модель.
3. При необходимости заменить **«XL ресурс» → «XL»**, сохранив признак ёмкости.
4. Если всё ещё тесно — применять только утверждённый словарь цветов:
   `черный → черн.`, `голубой → голуб.`, `пурпурный → пурп.`, `желтый → желт.`.
   Редкие и составные цвета оставлять полными до отдельного расширения словаря:
   нельзя потерять различие фото/матовый/светлый.
5. Затем только фиксированные сокращения типа: `Картридж → Картр.`,
   `Набор картриджей → Набор картр.`, `Фотобарабан → Фотобараб.`,
   `Набор фотобарабанов → Набор фотобараб.`. Новые варианты — через словарь, не обрезкой.
6. Оставшийся текст длиной 51–55 разрешать только после проверки двух строк.
   Более 55 или не помещающийся текст — отдельный список разбора.

Не обрезать строку по позиции, не ставить многоточие, не уменьшать шрифт.
Не удалять и не искажать основную модель, цвет одиночного товара, «с чипом»/«без чипа»/
«с чипом без счётчика», XL, количество в наборе, массу/объём содержимого.
Если эти признаки не подтверждены или противоречат источникам — HOLD.

Пример: «Картридж 071H для Canon 5646C002 черный с чипом XL ресурс» (57)
→ «Картридж 071H для Canon черный с чипом XL ресурс» (48).
Новый вариант ещё должен пройти проверку реального шаблона.

Важно: если название модели ТК само содержит описание устройства, его нельзя сокращать
как произвольный текст. Например, `5088bs`: старое поле «Блок проявки …», а тип ТК —
«Картридж». Это вопрос идентичности/типа, а не просто длины; строку исключить до проверки.

## План после согласования

1. Утвердить лимит, словарь сокращений, охват активных товаров и комплектов и правило
   исключения спорных строк. По умолчанию охват не ограничен наличием; архив не менять.
2. Подготовить исполнитель и отчёт dry-run. Использовать `compose()` как единственный
   генератор; подключить общий слой подготовки названия для этикетки к «Новинкам»
   Пульта и массовому обновлению, включая серверную проверку перед сохранением.
   Сначала проверить и включить его для новинок, затем пересчитать массовый dry-run
   той же версией правил. Изменение общего модуля потока prc сверить с его загрузчиками,
   не создавать расходящиеся копии формулы. Критерии описаны выше.
3. Перечитать источники и кандидатов из МС с небольшими страницами. Проверить точный
   `ms_id`, entity type, внешний код, товар/вариант/чип/XL/комплект и все 11 обязательных
   полей. Изменившиеся или неоднозначные карточки пропускать, не подменять источники
   значениями соседней карточки. Записывать только «Название WB»; остальные поля — вне задачи.
4. Прогнать новые названия через действующий шаблон этикетки. Подготовить PDF-превью
   пограничных примеров, длинных моделей, составных цветов, наборов, тонеров/чернил
   и вариантов чипа. Для физической читаемости — пробная печать выбранных примеров.
   Если редактируемого шаблона нет в доступе, сначала получить его: образцы PDF не
   доказывают, что новый текст будет перенесён точно так же.
5. Установить потребителей `product.UPDATE` и `bundle.UPDATE`. Пока нет доказательств,
   что они не читают поле, считать изменение **значимым**. Если читает ТК/другая интеграция,
   вебхуки не подавлять: проверить добор пропущенных событий опросом и предупредить владельца
   до окна. Если добора нет, значимую массовую запись не запускать.
   Если доказано, что поле никто не читает, допустимо только адресное подавление нужной
   подписки на наших запросах (`X-Lognex-WebHook-DisableByPrefix`), без отключения подписок
   целиком. Неподтверждённый добор ТК не считать существующим.
   Сообщения людям в рамках подготовки плана не отправлялись; текст предупреждения
   подготовить для владельца интеграции, адресата и канал согласовать перед отправкой.
6. Зафиксировать неизменяемый список `ms_id / старое / новое / причина / источник`,
   контрольную сумму и резервную копию. Показывать итоговый объём после всех отсевов.
   Внутри партии одно касание на сущность, только дельта; перед записью проверять, что
   старое значение и идентичность не изменились. Не перетирать правку человека между снимком и записью.
7. Назначить последовательные ночные волны **23:00–05:00 МСК**, не более **3 000
   изменённых сущностей в час и 10 000 за ночь**. Первые 200 → пауза 10 минут →
   проверка операционки → продолжение. При росте задержек увеличить паузу, при ошибках,
   проблемах заказов/уведомлений или окончании окна остановиться.
8. Вести возобновляемый журнал, не повторять неопределённый запрос без перечитки результата;
   контроль HTTP не заменяет GET-проверку сохранённого поля. Утром — сверка из МС,
   число verified / skipped / failed / осталось и список исключений. При откате учитывать
   новые ручные изменения и применять тот же ночной регламент, не перезаписывать их автоматически.

Оценка — **не менее четырёх ночей**, если после проверок останется около 31–35 тыс. замен.
Лимиты относятся к сумме изменений всех фоновых прогонов аккаунта, а не к каждому скрипту.

## Проверки и темп

- Перед первой записью заново получаются API Рапида/Профилайна и XML Булата; проверяется, что утверждённый EAN-13 по-прежнему отдаётся для того же артикула.
- Заново читаются последние оприходования этих трёх поставщиков. Карточки, вышедшие из текущих оприходований, и позиции с изменившимся кодом/сопоставлением источника пропускаются с причиной; новые карточки в план не добавляются.
- Перед каждой записью проверяются UUID, поставщик, артикул, внешний код, отсутствие архива. Актуальные собственные и другие коды перечитываются; изменения между подготовкой и запуском сохраняются, а не заменяются старым срезом.
- До 50 изменений в партии, пауза не менее 60 секунд. После первых 200 обработанных карточек (не более 200 изменённых) — 10 минут и проверка доступности операционных документов МС. При медленном POST пауза увеличивается до 120 секунд.
- Вебхуки не подавляются. Штрихкоды считаются значимым изменением для склада и интеграций. Контрольное чтение документа проверяет доступность API, не гарантирует доставку вебхуков.
- Полный резервный срез перед запуском и резервные копии каждой партии с fsync. Журнал отправки с fsync, GET-проверка полного списка штрихкодов после каждого изменения. Автоматического повторного POST и перезапуска сервиса нет.

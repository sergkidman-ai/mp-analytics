# P1b — план реализации и эвала (2026-08-22)

Дизайн — `kb_retrieval_p1b_design_2026-08-22.md`. **Ничего из этого не начато.**
Порядок шагов жёсткий: наборы (S4) замораживаются ПОСЛЕ того, как определён вид запроса
(S1–S3), иначе набор придётся пересобирать дважды. Прогонов до заморозки нет.

## S5 — ветки абляции

| арм | запрос | что проверяет |
|---|---|---|
| A0 | только промпт | базовая линия = поведение P1 на новом наборе |
| A1 | + хвост K=1, α фиксированный | достаточно ли одного обмена (§2: колено на UA1) |
| A2 | + хвост K=2, α фиксированный | нужен ли второй обмен |
| A3 | K=2, **α адаптивный** (S3) | оправдана ли адаптивность против константы |
| A4 | K=2, α адаптивный + подпись `tool_use` | окупается ли сигнал инструментов (+0…+7 стемов) |
| A5 | K=4 | контроль сверху: подтвердить, что глубокий хвост вредит |

Дополнительно, вне выбора конфигурации: разовый замер `thinking` в хвосте (вопрос 1 §10 дизайна)
и разовый замер кросс-сессионного хвоста на H07-подобных строках (вопрос 2) — только цифры,
в продакшн-конфигурацию не берутся.

## S6 — правило выбора (объявляется до прогона)

Побеждает арм с максимальным **recall@3 на агрегате калибровки** при условии:
**ни по одной страте нет просадки более 5 п.п. против A0**. При равенстве в пределах 2 п.п.
берётся более простой арм (меньше K, меньше источников). Правка ретривера, не улучшившая
агрегат измеримо, откатывается — как FIX-1 в P1.

## S8 — гейты holdout (утвердить ДО заморозки наборов, §10 вопрос 4)

| метрика | предлагаемый гейт | комментарий |
|---|---|---|
| recall@3, агрегат | ≥ 85% | P1 дал 46% |
| recall@3, self-contained | ≥ 90% | P1: 71% |
| recall@3, anaphoric | ≥ 60% | ниже остальных **сознательно**: потолок H07 (референт вне хвоста) |
| ложная инъекция на no-knowledge | ≤ 15% | P1: 100% |
| уверенно-неверный top-1 | 0 | единственный гейт, взятый в P1 — сохранить |
| бюджет инъекции | ≤ 1800 ток./ход, ≤ 8000/сессию | без изменений; хвост в контекст не идёт |
| задержка построения хвоста | p95 ≤ 250 мс | новый гейт; превышение → fail-open |

Гейты фиксируются в наборе при заморозке. После просмотра результатов holdout ретривер не правится.

## Дисциплина (перенос из P1, нарушать нельзя)

- Наборы P1 (30/15) выведены из обращения — видены, нестратифицированы, без провенанса.
- Эталон — только grep факта по канону с `evidence`; выдача ретривера при разметке не смотрится.
- Канон пиннут отпечатком; перед каждым прогоном сверка.
- Holdout вскрывается один раз.
- Никаких эмбеддингов до прохождения нового детерминированного эвала.
- Хук `UserPromptSubmit`, инъекция и P2 **не начинаются** до GO по S8.
- Абсолютные пути и `git -C` во всех командах (ловушка cwd, дважды за сессию P1).

## Оценка объёма

S0–S3 — правка двух файлов и тесты. S4 — самый дорогой шаг: ~100 строк ручной разметки
grep-ом плюс материализация и заморозка хвостов. S5 — 6 прогонов по 60 запросов, офлайн,
без платных ресурсов. Платных API в P1b не используется.

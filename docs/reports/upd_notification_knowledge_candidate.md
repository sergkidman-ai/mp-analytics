# Предложение дополнения telegram-channels

Это предложение по существующему correction flow, не каноническая карточка.
Текущее состояние реализации, счётчики и следующий шаг хранятся в BRIEF_FIN.

## FACT — канал и значения статусов

- Уведомления Наталии о готовых УПД по выкупам Wildberries использует
  `ops/upd_weekly.py`: бот из `TG_PRC_BOT_TOKEN`, адресат из `TG_PRC_NATALIA_ID`.
  Использовать адресата этого контура, а не общие списки получателей других ботов.
- В `wb_redeem_notice` независимы два факта: `upd_status='made'` — ручная отметка
  выгрузки УПД, `sent_at` — отметка уведомления Наталии. Доставка уведомления
  не доказывает отправку/подписание документа в ЭДО и не должна менять `upd_status`.

Провенанс: `ops/upd_weekly.py`, `web/app.py` (обработчик `/api/upd/status`),
`migrations/709_wb_redeem_upd.sql`, `migrations/710_upd_sent.sql`;
существующий контур в коммите `60044fc`, проверен чтением кода в этой сессии.

## RULE — принятая политика продукта

- Для уведомлений об УПД по выкупам допустима доставка на следующий день.
  Использовать существующий ежедневный прогон; минутный опрос не нужен.
- Наталии отправляется короткое уведомление: организация, номер, дата, сумма,
  ссылка на раздел `/reports/upd`. XML забирается из Пульта, а не пересылается ботом.
- Недоставленные уведомления должны повторяться в следующем ежедневном прогоне.
  Отметку доставки ставить только после подтверждения Telegram.

Провенанс: прямое решение пользователя в этой сессии 04.10.2026:
«каждую минуту не нужно проверять ... пусть оно придет на следующий день ...
главное чтобы дошло»; согласованный текст уведомления зафиксирован в BRIEF_FIN.
Это требование продукта, а не утверждение, что все гарантии уже реализованы.

После утверждения человеком дополнить существующую карточку `telegram-channels`,
затем штатные `kb index`, `kb deploy`, `kb verify`. Индекс и транспорт вручную
не менять; автоматического продвижения предложения в канон не выполнять.

  Поля: `nmID, sizeID, techSizeName, newPrice, oldPrice, newDiscount, oldDiscount, priceDiff`.
- Сейчас в карантине: **wb_acc1 — 51**, **wb_acc2 — 33**. Все 84 nmID есть в нашей `wb_price`.
- Триггер WB: формулировка ошибки говорит «в разы ниже», но по факту порог заметно мягче —
  карточка 209727462 улетела в карантин на падении **−35 %**. Проверенный безопасный шаг — −15 %.
- Выпуск: отдельного метода нет, руками — в ЛК `/discount-and-prices/quarantine`.
  **Автоматика — лестница** (проверено 23.08.2026 на nmID 209727462, vendorCode 2905):
  - перезалив ТОЙ ЖЕ цены НЕ помогает: задача `status=6`, `successGoodsNumber=0`, ошибка
    дословно «New price is several times lower than the current price. Item has been moved

  - три ступени по −15 % от цены покупателя: 12906 → 10970 → 9324 → **8363** (целевая цена ТК),
    каждая применилась без карантина, карточка из списка карантина ушла.
  - В `ops/price_quarantine.py` шаг адаптивный: сначала −25 %, при отказе — −15 %.

## Яндекс.Маркет — ЕСТЬ и чтение, и выпуск по API
- `POST /businesses/{businessId}/price-quarantine` → 200. Поля: `offerId, currentPrice,
  lastValidPrice, verdicts[]`.
- Сейчас в карантине: **ya_acc1 — 88** позиций. Вердикты: `PRICE_CHANGE` 112, `LOW_PRICE` 2.
- Карантин живёт на уровне БИЗНЕСА; по трём кампаниям (`/campaigns/{id}/price-quarantine`)
  пусто — значит разбирать надо бизнес-список.
- Выпуск: `POST /businesses/{businessId}/price-quarantine/confirm`, `offerIds` 1..200 за вызов
  (проверено пустым payload → 400 с описанием лимита). Полностью автоматизируемо.
- Дисквэра на Маркете нет — только Цифровой.

## Ozon — ни чтения, ни выпуска по официальному API
- Ни один из 12 вероятных путей карантина не существует (все 404).
- `/v5/product/info/prices` и `/v3/product/info/list` признака карантина не содержат
  (в ответе нет ни поля, ни строки `quarantine`; `statuses.status='price_sent'` у здорового товара).
- Никакой SMS Ozon не требует (уточнено Сергеем 23.08.2026). Поддержка Ozon ответила
  **отрицательно**: метода карантина в API нет.
- **РЕШЕНИЕ Сергея 23.08.2026: Ozon остаётся на ручном подтверждении в ЛК, автоматику не делаем.**
  Ниже — как это выглядело бы, если решение когда-нибудь пересмотрят.
- **Обход тот же, что на WB — лестница**, механика площадко-независима: порог смотрит на размер
  ОДНОГО изменения, значит N мелких шагов доводят цену до цели. Для Ozon не хватает только входа:
  API не отдаёт ни список карантина, ни ту цену, которую пытался поставить ТК
  (`/v5/product/info/prices` показывает лишь действующую цену). Варианты входа:
  1) артикулы и целевые цены из ЛК/от ТК → лестница по ним;
  2) реестр «какую цену ТК хочет видеть» на нашей стороне → карантин определяется сам собой,
     как расхождение «цель ≠ фактическая цена на площадке», список из ЛК не нужен вовсе.
  Порог Ozon (заявленные ~50 %) проверяется одним живым тестом — как на WB.

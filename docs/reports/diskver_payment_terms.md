# Дисквэр: фактические условия оплаты поставщикам (из истории МойСклад)

Период: 180 дней до 2026-08-02. Организация ООО «ДИСКВЭР» (ИНН 7811803918).
Данные: 848 приёмок, 294 исходящих платежа, 28 контрагентов.
Метод: FIFO — накопленная сумма платежей гасит приёмки по порядку, лаг = дата платежа − дата
закрытой им приёмки. Отрицательный лаг = деньги ушли раньше поставки (предоплата/аванс).
Сырьё: `docs/reports/diskver_payment_terms_raw.json`.

⚠️ **Что эта метрика меряет.** Не договорную отсрочку, а **скорость закрытия накопленного долга**.
У Дисквэра платежи укрупнённые: 169 приёмок Одиссея закрыты 10 платежами. Поэтому цифры —
основание для разговора, а не готовые условия. Исключение — Феррет (97 приёмок / 96 платежей,
1:1), там модель видна однозначно.

## Наблюдения, важные для архитектуры

1. **Модель платежа у Дисквэра другая, чем у ЦК.** У ЦК черновик делается под конкретный заказ
   (`prepayment_per_order` / `deferred` по документу). У Дисквэра, кроме Феррета, платежи —
   **укрупнённые погашения накопленного долга** (Одиссей: 10 платежей на 169 приёмок).
   Значит, `po_payment_watch` для Дисквэра нужен режим **«гасим сальдо по поставщику»**,
   а не «платёж на каждый заказ». Иначе получим 169 черновиков вместо 10.
2. **Феррет одинаков в обеих организациях** — предоплата за заказ, 1:1. Его логика (и мост
   «№ счёта = № приёмки») переносится без изменений.
3. **Дубль карточки Солюшнс** (ИНН 7806486149 в двух контрагентах) — та же беда, что в ЦК,
   где лечится `AGENT_OVERRIDE` в `invoice_to_po.py`. Ключ условий оплаты должен быть по ИНН,
   а не по карточке, иначе условия разъедутся.
4. **Три расхождения с условиями ЦК** требуют подтверждения человеком: Одиссей (у ЦК отсрочка 14,
   у Дисквэра фактически аванс), Блоссом (4 → фактически 17), КПД (5 → фактически аванс).
   Расхождение — не обязательно ошибка: у разных юрлиц могут быть разные договоры.

## Что нужно от человека

Подтвердить или поправить по каждому из 11 ИНН: **метод** (`deferred` / `prepayment_per_order` /
`prepayment_balance` / новый `balance_settlement`), **срок отсрочки**, **порог/сумму аванса**,
**потолок платежа**, **ставку НДС**. Заполненное идёт в `supplier_payment_terms` с ключом
(организация + ИНН поставщика).

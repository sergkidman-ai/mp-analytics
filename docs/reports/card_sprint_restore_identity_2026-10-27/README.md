# Восстановление кодов трёх карточек Спринта — 27.10.2026

Прямая команда владельца: восстановить поля, очищенные при архивации трёх карточек с длинным служебным `externalCode`. Прежние значения взяты из локального аудита каждой карточки МойСклад за 13.07.2026. Карточки снова активны.

| Товар | ID МС (начало) | Внешний код | Код МС | Прежний артикул |
|---|---|---|---|---|
| TN-241C/TN-245C SP | `62834f21` | `3149` | `3149sp` | `SP107248_MSK` |
| TN-241M/TN-245M SP | `628ad634` | `3150` | `3150sp` | `SP107249_MSK` |
| TN-241Y/TN-245Y SP | `629248b3` | `3151` | `3151sp` | `SP107250_MSK` |

Внешние коды и коды МС восстановлены: 3 PUT, 3 GET readback и независимая свежая проверка 3/3. Прочие проверенные поля, включая описание, характеристики, штрихкоды, вес, объём и состояние архива, не менялись. Полные снимки до и после, план, payload и журнал — в этой папке.

Артикулы **не восстановлены**: все три прежних артикула уже стоят на других активных карточках того же поставщика — TN-245C/M/Y с внешними кодами 0857/0858/0859. В `prices/loader.py` при двух карточках своего поставщика с одним артикулом оприходование получает статус `ambiguous`. Поэтому восстановление старого артикула прервало бы однозначное сопоставление действующего товара. У старых TN-241 карточек по этим артикулам нет актуальной страницы в ЛК. Позднее владелец решил вернуть эти три карточки в архив с очисткой идентификаторов; итог — [отчёт повторной архивации](../card_sprint_rearchive_2026-10-27/README.md).

# «На доработку» на Ozon — что это на самом деле (23.08.2026)

Поток `card`. Данные сняты с живого API, оба аккаунта.

## Короткий ответ

**«На доработку» — это НЕ сломанные карточки.** Фильтр видимости `PARTIAL_APPROVED`:
609 карточек на acc1 «Цифровой квадрат», 353 на acc2 «Дисквэр».

Все 609 на acc1 разобраны поштучно, и картина одинаковая до последней карточки:

| признак | значение |
|---|---|
| торгуют | **609 из 609** (431 «Готов к продаже», 178 «Продается») |
| модерация | `approved` — 609 из 609 |
| валидация | `success` — 609 из 609 |
| `status_failed` | пусто — 609 из 609 |
| уровень замечаний | **только `ERROR_LEVEL_WARNING`, 964 штуки. Ошибок уровня ERROR — ноль** |

То есть это не «упало», а «принято с замечаниями к качеству контента». Продажам прямо
ничего не мешает — карточки в продаже. Мешает косвенно: неполные и неверные атрибуты
режут показы в фильтрах и поиске.

## Половина лечится повтором — проверено опытом

Первая версия этого отчёта утверждала, что дожиматель здесь бесполезен. **Это оказалось
неверно.** Сергей сказал, что большинство таких замечаний снимается повторной отправкой на
модерацию; два прогона по 25 карточкам acc1 показали, что он прав, и заодно показали, где
проходит настоящая граница.

Граница проходит **по коду замечания, а не по группе**:

| код | отправлено | замечание снялось | вывод |
|---|---|---|---|
| `double_without_merger_offer` | 5 | **5** | лечится |
| `erased_attribute_value` | 5 | **5** | лечится |
| `pics_http_error` + `some_image_failed` | 5 | **5** | лечится |
| `attribute_hierarchy_fail` | 3 | **3** | лечится |
| `warning_attribute_values_out_of_range` | 2 | 0 | не лечится |
| `warning_attribute_values_empty` | 5 | 0 | не лечится |

Правило простое: **значение в карточке ЕСТЬ, а площадка держит устаревший вердикт → повтор
его снимает. Значения НЕТ → повтор его не создаст**, это работа ТК. Придумывать значения нам
запрещено границей потока: контент принадлежит ТК, наш пуш он затрёт следующим же обновлением.

Замер честный с двух сторон: перечитка карточки (код замечания исчез) и контрольный счётчик
площадки (все 18 вылеченных ушли из списка «На доработку»). Продажу не потеряла ни одна
карточка, повторная модерация не запускалась ни разу. Файлы: `ozon_partial_test_2026-08-23.csv`,
`ozon_partial_test2_2026-08-23.csv`.

Итог для автомата: класс **W** в `card_status`, белый список из пяти кодов в
`collectors/ozon_card_status.py` (`HEAL_WARN`). После пересчёта детектором лечимых карточек
**279 на acc1 и 25 на acc2**; дожимает их тот же ночной крон, 50 на аккаунт в сутки.
Остальные 320 acc1 и 328 acc2 — незаполненный контент, это в ТК.

## Приоритет для программиста ТК — по деньгам, а не по количеству

1. **«Совместимые модели принтеров» — 329 карточек (251 + 78).** Для картриджа это ГЛАВНЫЙ
   атрибут: по нему покупатель фильтрует товар («картридж для HP LaserJet 1010»). Значения,
   не попавшие в справочник Озона, в фильтр не встают — карточка просто не показывается
   тому, кто её ищет. Прямо перекликается с провалом показов Ozon летом-2026
   (−29 % показов при +31 % спроса). ТК шлёт модели своим списком, а не справочником Озона.
   Оговорка по итогам опыта: 251 карточка из 329 (`attribute_hierarchy_fail`) снимается нашим
   повтором — значение в карточке есть, у Озона протух вердикт. В ТК остаются 78
   (`…out_of_range`) — там значение реально вне справочника.
2. **Картинки — 17 карточек.** Единственное, что видит покупатель глазами. Проверено:
   лечится повтором, автомат забрал.
3. **Дубли — 27 карточек.** Две карточки одного товара делят между собой показы и отзывы.
   Проверено: снимается повтором, автомат забрал.
4. **«Нужен код маркировки» — 302 карточки.** Массово, но это признак товарной группы;
   на выдачу влияет слабее остальных.

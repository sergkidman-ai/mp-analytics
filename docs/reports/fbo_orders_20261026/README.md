# ФБО-заказы Ozon и WB — 26.10.2026

В «Склад → Заказы покупателей» подключены ФБО Ozon и WB по обоим кабинетам. Общий список отсортирован по дате заказа площадки, есть фильтр ФБС/ФБО, фильтры кабинета, номера, артикула, статуса и неподтверждённой себестоимости. ФБО показывает статус, товар и цену площадки. Себестоимость, прибыль, пол и отклонение пусты: связь конкретной проданной единицы с подтверждённой партией пока не доказана. Поэтому ФБО не участвует в сигналах об убытке и заданиях МС.

Источник Ozon — FBO Posting List v3; использован существующий сырой архив (240 постингов) и прямое обновление за 90 дней с размером страницы 100. Архивные статусы могут быть старее текущих, если постинг не входит в новое окно API. Источник WB — Statistics Orders за 90 дней с точным признаком `warehouseType = Склад WB`; статусы соединяются по `srid` с Order Feed (30 дней) и Statistics Sales (90 дней). Признак `isMp` для схемы не использован: он встречается и в заказах со склада продавца. Для заказов вне окна 90 дней история останется в локальной базе, но статус без нового источника не обновится. Цена WB помечена источником: `sellerPrice` из Order Feed или `priceWithDisc` из Statistics Orders; это сумма площадки для просмотра, не подтверждённая база для расчёта прибыли.

На момент первичной загрузки: Ozon 188/52 по кабинетам, WB 74/45. Все 119 загруженных WB-заказов получили известный статус, ни один не классифицирован по догадке об остатке. При каждом последующем чтении изменение источника записывается как событие. Сбор раз в час отдельным timer, только чтение API площадок и запись локальной БД. Он не использует токен МС, не создаёт `customer_guard_jobs` и не отправляет уведомления.

Проверка: изолированные тесты нормализации, истории, фильтра и отсутствия заданий МС; прямые чтения Ozon/WB; сравнение общего списка и фильтра ФБО; проверка HTTP API после публикации. Следующий этап — подтвердить происхождение единиц на складах площадок и только затем рассчитывать себестоимость ФБО.

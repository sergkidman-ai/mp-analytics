Пользователь поручил пошагово выполнить согласованный план и обеспечить одинаковую
формулу для создания новинок в Пульте и массового обновления карточек МС.

## Что включено в Пульте

- Единственная смысловая формула — `tools/prc/wb_fill.py:compose_details()`;
  совместимый вызов `compose()` сохранён. Общие сокращения — `prices/wb_label.py`.
- Ориентир 50, жёсткий предел 55 знаков. Последовательность: убрать дополнительное имя,
  «XL ресурс» → «XL», словарь основных цветов, словарь типов. Основная модель,
  составной цвет, чип, XL и масса/объём содержимого не обрезаются. Если результат всё
  ещё длиннее 55, название не возвращается, вместо него — причина разбора.
- XL из имени поставщика включается до сокращения. Для новинки без модели ТК
  поддержан действующий разбор имени поставщика; явная масса/объём тонера/чернил
  также переносится в общую формулу. Ошибка длины/неизвестного цвета/чипа в ТК
  не обходится подстановкой другого источника.
- GET `/api/novelties/ms-form` использует общую формулу и возвращает лимит/версию.
  Исходный код модели ТК сохраняется отдельно от нового внешнего кода новинки.
- POST `/api/novelties/ms-create` сверяет отредактированное название с общей формулой,
  включая старые открытые диалоги. При расхождении возвращает исправленный вариант
  до запросов создания товара. Общий `create_in_ms()` дополнительно проверяет всю
  партию до первой записи, в том числе при dry-run и вызовах вне веб-формы.
- `mp-dashboard` перезапущен; живая форма отдаёт версию `2026-10-15.1`, предел 55;
  сохранение устаревшего названия проверено запросом с `dry=true`: получен отказ с
  предложением формульного названия. Карточки при проверке не создавались.

Проверка символов **не подтверждает** перенос в две строки. Пока нет исходного шаблона
печати, размещение не считается проверенным и массовая запись не назначается.
Существующие названия не обновляются от одного открытия формы или перезапуска сервиса.

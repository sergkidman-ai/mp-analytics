# 17. Калибровка харвестера габаритов с карточек ВБ — слепой прогон против эталона

Дата: 2026-07-30 · поток: gab · ветка `gab/dims`
Продолжение отчёта 16 (`16_wb_competitor_harvest_2026-07-30.md`).

## ВЕРДИКТ: МЕТОД ЗАКРЫТ

Через фильтр редкости прошло **85 моделей, из них 57 (67 %) не бьются с эталоном**.
Метод не даёт габаритов — он даёт правдоподобные числа с вероятностью попадания около
трети. Для габаритов это неприемлемо: занижение = штраф ВБ, завышение = переплата логистики.

Следствие: условие Сергея «если годен — 121 модель идёт в покрытие» **не сработало**.
Ни одна из 121 модели в покрытие не идёт. Дефолтная массовка (431 модель, 2,2 млн) — тоже в отказ.
На маркетплейсы ничего не отправлялось. Платные ресурсы не трогались.

## Как проверяли

**Эталон — только вне интернет-карточек** (`tools/gab_calibration_set.py`):

| источник | что это | моделей |
|---|---|---|
| консенсус-поставщиков | ≥2 разных чистых поставщика (изи / cactus / sakura / SP) сошлись в ±10 % или ±1,5 см | 216 |
| замер-SolutionsPrint | короб из прайса SP, согласованный сам с собой | 915 |
| паспорт-Icecat | подтверждённые паспортные данные | 10 |
| **итого эталон** | | **1141** |

Ключ модели — ровно один полный OEM-код в названии (whitelist из
`GABARITY_SOLUTIONSPRINT_HANDOFF.md`); названия с нулём или двумя кодами отброшены.
Санитария: стороны 1–120 см, объём ≤25 л, объём из прайса бьётся с произведением сторон ±15 %.
Из 13 424 строк поставщиков — 1725 моделей с однозначным OEM → 1141 эталон.

**Слепой прогон.** Выборка 300 моделей (`random.seed(20260730)`: все 10 Icecat + 120 консенсус +
170 SP, перемешаны). Харвестер получил только `vendorCode CAL0001…CAL0300` + OEM — эталон он
не видел ни в каком виде. Собрано 1339 карточек конкурентов ВБ. Независимый валидатор:
279/279 обработано, **125 моделей подтверждено**, 739 строк отклонено.

| **прошли фильтр редкости** | 85 | 24 (28 %) | 27 (32 %) | **28 (33 %)** | 8,5 % / 385 % · 1,4 см / 32,0 см | 29,1 % / 2094 % |
| массовка (коробка у ≥5) | 37 | 1 (3 %) | 0 (0 %) | **1 (3 %)** | 19,6 % / 275 % · 3,7 см / 16,2 см | 58,1 % / 305 % |

Направление ошибки: среди прошедших фильтр редкости завышений объёма >20 % — 32 (38 %),
занижений <−20 % — 15 (18 %). То есть ошибка не односторонняя, «поправкой на коэффициент»
не лечится.

Фильтр редкости работает в правильную сторону — он выбивает 37×20×15 (34 модели, верна одна)
и поднимает попадание с 24 % до 33 %, медианную ошибку стороны с 12,2 % до 8,5 %. Но это
единственное, что он ловит: мелкие «свои» дефолты продавцов (36×22×12, 32×16×9, 37×30×12)
редки по определению и проходят насквозь. Ужесточать порог нечем — при RARE_MAX=1 выборка
схлопывается, а доля мимо остаётся двузначной.

## Почему метод не спасается поправками

1. **Ошибка двусторонняя.** 38 % завышено, 18 % занижено. Единого коэффициента нет.
2. **Хвост катастрофический.** Максимум по стороне 385 %, по объёму 2094 % — это не шум,
   это чужая коробка целиком (мастер-короб или сопутствующий товар в карточке).
3. **Селектор недоступен.** 39 % на консенсус-эталоне против 8 % на SP-эталоне — разница есть,
   но она в свойствах эталона, а не входа; отобрать «хорошие» модели заранее нечем.
4. **Валидатор уже отработал.** 739 строк из 1339 он отбросил, и всё равно 67 % выживших мимо.
   Дополнительного запаса ужесточения в цепочке не осталось.

Это ровно тот класс данных, который запрещён правилом потока: «только реальные замеры,
никаких оценок и прокси». Карточка конкурента — не замер.

## 3. ЕДИНИЦА ХВОСТА

Хвост считается **логическими обменами**, не строками транскрипта. В этом проекте на 12 сессий
приходится 5647 строк ассистента, из них текстовых блоков 536, `tool_use` 3172, `thinking` 1939 —
«последние N строк» дали бы почти одни вызовы инструментов.

**Обмен** = реплика человека + финальный текст ассистента этого хода + компактная подпись
его вызовов инструментов.

Границы:
- **K = 2 обмена** до текущего промпта (основание — колено UA1/UA2 в §2). K=1 и K=4 — арм абляции.
- **Только та же сессия.** Не склеивать сессии.
- **Дедлайн свежести 90 минут** между текущим промптом и последним ходом хвоста: возобновлённая
  через час сессия — уже другая тема.
- **`isSidechain: true` (субагенты) исключается целиком.** Контекст субагента — чужая задача.
- Текущий промпт в хвост не входит.
- Хвост не пересекает границу `cwd`/worktree.

## 5. КАК НЕ РАЗДУТЬ КОНТЕКСТ

Главное правило, из которого следует всё остальное:

> **Хвост диалога никогда не попадает в контекст модели и никогда не попадает в запрос текстом.
> Он попадает только как взвешенный вектор терминов, который живёт внутри процесса ретривера
> и умирает вместе с ним.**

Из этого:

1. **Бюджет инъекции не меняется** — 1800 токенов/ход, 8000/сессию. Хвост влияет на
   *ранжирование*, а не на то, что кладётся в контекст. Замеры P1 (med 858, max 1209) остаются
   в силе как базовая линия.
2. **Хвост читается «с конца файла»** — не более последних 400 строк JSONL. Сессии доходят до
   14 823 строк; читать транскрипт целиком на каждый промпт нельзя.
3. **Жёсткий бюджет времени** на построение хвоста, ориентир **250 мс p95**. Превышение,
   нечитаемый транскрипт, отсутствие `transcript_path` → **fail-open: запрос = только промпт**.
   Деградация до поведения P1, а не отказ.
4. **Почему именно взвешенный вектор, а не склейка текста.** В `score_cards()` сейчас
   `quniq = sorted(set(tokens(query)))` — частота термина в запросе отбрасывается, каждый
   уникальный стем весит одинаково. Значит, склеенный хвост в 2000 символов даст **каждому
   своему слову тот же вес, что словам самого человека**, и утопит запрос из 40 символов.
   Это механическая причина, а не опасение. Отсюда — изменение сигнатуры (§7).

## 6. АНАФОРА

**Анафора разрешается подмешиванием терминов, а не переписыванием вопроса.** LLM-переписывание
запроса отвергнуто: недетерминировано (ломает весь эвал-контур), стоит вызова модели на каждый
промпт и добавляет задержку в критический путь.

Вес хвоста **не константа**, а функция самодостаточности запроса. Основание в §2: у
самодостаточных запросов пересечение промпта с эталоном `base` = 4–5, у анафорных — **0–1**.
Фиксированный вес обязан быть либо слишком мал для H06, либо слишком велик для H03/H04.

**Детектор самодостаточности `s ∈ [0,1]`** — детерминированный, считается по промпту, без
обращения к ретриверу, из трёх сигналов:

1. число содержательных токенов после стоп-листа;
2. максимальный IDF термина запроса — назвал ли человек хоть одну редкую сущность
   (идентификатор, слаг, путь, бренд, номенклатурный номер);
3. **маркеры анафоры** — закрытый список: «прошлый раз», «ты (писал|говорил|делал)»,
   «мы (ведь|же)? (сделали|делали|обсуждали|говорили)», «мы это уже», «помнишь», «а там что»,
   «стоп а где», «а с этим что», «оно», «там», «это» в роли единственного содержательного слова.

Вес хвоста `α = α_max · (1 − s)`, зажат в `[0.15, 0.75]`. Самодостаточный запрос почти
заглушает хвост, анафорный — отдаёт ему главную роль. **Границы и `α_max` — цели калибровки,
здесь не назначаются.**

Отдельно: маркеры анафоры используются и как страта набора (§8), и как рантайм-сигнал —
то есть страты набора служат разметкой для проверки самого детектора.

## 7. ЕДИНЫЙ RETRIEVAL QUERY

```
qterms: dict[stem -> weight]

# 1. сам промпт — базовый вес
for t in tokens(prompt):
    qterms[t] = 1.0

# 2. хвост — max, не сумма
for обмен e на расстоянии d (1..K):
    for (текст, field_w) in сегменты(e):        # человек 1.0, ассистент 0.8, инструменты 0.6
        for t in tokens(cap(текст)):
            qterms[t] = max(qterms.get(t, 0), α · decay(d) · field_w)

# decay: d=1 -> 1.0, d=2 -> 0.6
# 3. отсечка: не более T=60 различных стемов из хвоста, по весу (тай-брейк по IDF)
```

- **`max`, а не сумма:** термин, повторённый в хвосте пять раз, не должен перевешивать слово,
  сказанное человеком один раз.
- **T = 60** — выше измеренного полезного сигнала (23–54 общих стема на UA4) и ниже словарного
  взрыва UA6. **Отсечку делать по весу, не по глобальному IDF** — top-N по IDF проверен и
  теряет сигнал (§2).
- В `score_cards()` вклад лексики становится `w(t) · idf(t) · …` вместо `idf(t) · …`.
  Сигнатура принимает либо строку (совместимость: все веса 1.0 → поведение P0 бит в бит,
  все 32 офлайн-теста обязаны пройти без правок), либо `qterms`.
- **Алиасы, owner, теги матчатся ТОЛЬКО по промпту, никогда по хвосту.** Слой и так мёртв
  (0% покрытия), а скармливать ему текст диалога — плодить ложных владельцев (случай C26).
- `is_action_query`, `is_governance_query` — только по промпту.
- Определение потока (`stream`) по `cwd` — без изменений.
- `qstems` для выдержек (`build_injection`) — **только промпт**, иначе выдержки начнут
  подсвечивать слова из диалога, а не из вопроса.

## 8. ПЕРЕСБОРКА НАБОРОВ (стратификация)

### Страты

| страта | доля | определение (по тексту запроса, до всякого прогона) |
|---|---|---|
| self-contained | 30% | тема названа в промпте: есть ≥1 доменная сущность, маркеров анафоры нет |
| anaphoric | 25% | маркер анафоры и/или ни одной доменной сущности; тема восстановима только из хвоста |
| ambiguous | 15% | тема названа, но недоопределена: правдоподобных карточек ≥2 |
| no-knowledge | 15% | факта в каноне нет; правильное поведение — **молчать** |
| collision-heavy | 15% | запрос из частотных для корпуса слов («маржа», «себестоимость», «озон», «отчёт»), бьющих по многим карточкам |

Страта присваивается **по тексту запроса, без просмотра эталона и без выдачи ретривера**, и
пишется в строку. Ровно те же сигналы видит рантайм-детектор §6 — поэтому страты работают
и как эталон для его проверки.

### Размер

**Калибровка 60, holdout 40.** Основание: при n=13 доверительный интервал recall@3 составил
19–75% — «гейты не взяты» надёжно, само число бессмысленно. При n=40 полуширина ДИ около
±9 п.п.; это по-прежнему грубо, и гейты поэтому ставятся и на агрегат, и на пол по стратам.
Минимальный компромисс, если разметка окажется дороже ожидаемого — 45/30, но не меньше.

### Обязательное новое требование — провенанс и замороженный хвост

Из §2: сегодня локализуются 9 из 15 запросов P1. Значит:

- каждая строка несёт `session_file`, `turn_uuid`, `turn_idx`;
- **материализованный хвост замораживается вместе с набором** — сайдкар
  `evals/p1b_tails/<id>.json`, sha256 в TSV. Иначе эвал невоспроизводим: транскрипты стареют,
  а один и тот же вопрос в другой сессии имеет другой хвост;
- **канон пинится**: число карточек + отпечаток тел записываются при заморозке и сверяются
  перед каждым прогоном (сейчас уже 92 / `f5f0766f7c835077`);
- эталон по-прежнему задаётся **grep-ом факта по канону**, поле `evidence` обязательно,
  выдача ретривера при разметке не используется;
- набор коммитится ДО первого прогона; **holdout вскрывается один раз**.

Наборы P1 (30/15) **выводятся из обращения** и остаются только как история: они уже видены,
не стратифицированы и не привязаны к транскриптам.

# Первая пробная партия Названия WB — подготовка 15.10.2026

По команде пользователя применять согласованные сокращения выполнен следующий
подготовительный шаг: **200 карточек с сокращёнными формульными названиями перечитаны
из живого МС, все 200 прошли проверку**. Это пробная партия, не вся очередь из 28 023.
Алгоритм/сокращения уже включены в «Новинках» Пульта, повторное согласование не требуется.

Инструмент `tools/prc/wb_name_preflight.py` имеет только read-only режим. Проверены
идентичность id/кода/внешнего кода/наименования, старое WB-поле, актуальные исходные
поля ТК, все обязательные поля, модель/тип/чип/бренд/объём и отсутствие стоп-признаков.
Новые названия совпали с согласованным расчётом и прошли предел 55/две строки по образцам.
Поле «Название WB» проверено точечным GET метаданных по id; название атрибута совпало.

- `live_before.jsonl.gz` — резервная копия полного ответа МС для этих 200 карточек.
- `plan.json`, `plan.sha256` — зафиксированный состав, точные старые/новые значения и
  хеши исходных полей/кода. Существующий план инструмент не перезаписывает.
- `checks.json` — результат каждой из 200 живых проверок, отказов нет.
- [Первая партия в Excel](https://bi.metaverseworld.ru/download/wb-name/canary.xlsx).
- 6 тестов нового preflight прошли: изменения человеком/внешнего кода/ТК, архив,
  пропажа обязательного поля и стоп-лист блокируют кандидата.

**Это ещё не готовый к автоматической записи ночной запуск:** в плане
`ready_to_apply=false`, расписание отсутствует, записей карточек МС 0. Сама работа
и согласованные сокращения пользователем разрешены; повторного разрешения не запрашивали.
Остались фактические условия запуска: настоящий шаблон/контрольная печать,
потребление поля и добор ТК, место для журналов и отката (на момент проверки около 32 МБ).

Далее — ночной исполнитель: только поле «Название WB», живая сверка непосредственно
перед записью, пропуск изменившихся карточек; 200 → 10 минут → проверка операционки.
После успешной канарейки — остальная очередь в том же ночном окне, не более 3 000
изменений/час и 10 000/ночь суммарно с другими фоновыми работами; утром GET-сверка.
Свежий backup/preflight не отменяет финальную перечитку перед записью, поскольку
между подготовкой и ночью товар может быть изменён человеком.

Источник требований: [ms-mass-change](/opt/mp-analytics/.claude/skills/ms-mass-change/SKILL.md).
Прямые ограничения: «Нет списка → изменение считается значимым»; для значимого
изменения «подавление ЗАПРЕЩЕНО»; «Нет добора — интеграция хрупкая, массовые прогоны
рядом с ней запрещены до появления добора». Данные о потреблении WB-поля/доборе ТК
пока не получены, поэтому запись не назначена. Подписки и данные МС не менялись.

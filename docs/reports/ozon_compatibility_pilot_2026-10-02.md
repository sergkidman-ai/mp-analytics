## Что выяснилось на живых отправках

- Простое совпадение имени с общим справочником недостаточно. Короткий MX310 (70881) API принял, но после проверки удалил. Canon Pixma MX310 (67938) сохранился, предупреждение снялось.
- Обобщённый ML-3310 (971072035) существует в справочнике, но Ozon удаляет его из Samsung-карточек. Результат 16 брендов / 15 моделей оставлял предупреждение. Повтор согласованных 15 пар снял его на всех трёх карточках.
- ML-3300 и SCX-4833 из ТК отсутствуют в текущем справочнике. Они не были в исходном списке карточек и не заменялись конкретными вариантами.
- У 2618 из 16 моделей ТК однозначно найден только P3150; Kodak отсутствует в справочнике брендов. Частичный список не отправлялся. Карточка сохраняет предупреждение.

## Перед автоматизацией

Нужна привязка к бренду, обработка комплексного блока 100007 (22888 / 22889), проверка после окончательной обработки Ozon и сохранение всех исходных моделей. Общий справочник не доказывает допустимость пары бренд/модель.
Найденные отсутствующие/неоднозначные модели — человеку; не удалять и не заменять похожими автоматически.
Пилот не менял cron, код проталкивателя или лимиты попыток. Исходные и итоговые снимки: backups/ozon_compatibility_2026-10-02/.

Ранее в этой сессии вручную протолкнуты и проверены 43 карточки W. Открыты проблемы автомата: ложный стоп на карточках, уже убранных из продажи до отправки; накопительный лимит попыток после успешного лечения рецидивов.

## Продолжение: родитель 2618 и тестовый режим

По отдельной команде проверены родители: `2618YVS70TZX` у Дисквера, `2618` у Цифрового, а также здоровые бандлы Дисквера. У всех ошибок нет, но моделей в API нет: только Lexmark. Полный список скопировать неоткуда. У ×12 повторно отправлен тот же блок Lexmark (без изменения содержимого): задача imported, предупреждение снято, карточка готова к продаже, остатка нет. Список принтеров НЕ восстановлен.

Подготовлены `tools/ozon_card_compat.py` и флаг `--repair-models` в `tools/ozon_card_push.py`. Обычный cron не использует новый режим.
- Донор: свежая здоровая базовая карточка того же семейства, категории/типа и модели картриджа, с непустым согласованным блоком. Производные по одному принтеру не используются. Конфликтующие доноры блокируются.
- Существующие модели не удаляются: разрешено заменить старый id на новый с тем же названием, подтверждённый здоровым родителем.
- Без донора: проверка текущих ссылок по справочнику, согласование количества значений одного бренда и существующих моделей, либо повтор существующего блока. Подбор новых id по похожим названиям не делается.
- Отдельный исход repeat_brand_only означает отсутствие моделей и повтор бренда, а не восстановление списка.
- Перед записью перечитываются цель и донор; свежие/изменившиеся карточки пропускаются. Все исходные данные сохраняются в backups/ozon_compatibility/. Проверяется imported, окончательный статус, точное сохранение пар и отсутствие предупреждения. Неудача останавливает остальные отправки.
- Пока тестовый --apply требует явный список не более 20 карточек. В расписание не добавлен. Не коммитили и не пушили.

Проверки: 19 unit-тестов (без API записи/БД), компиляция, сухой живой прогон на пяти карточках: все уже без предупреждения, отправок нет.

Сухой прогон: `venv/bin/python tools/ozon_card_push.py --account oz_acc2 --repair-models --limit 20 --plan-output /tmp/compat_plan.json`.
Следующий этап: проверка планов на новой волне предупреждений, ограниченный пилот по согласованному списку, затем решение о включении в расписание. Ложный стоп и накопительный лимит обычного дожимателя пока не изменены.

## Включение по команде пользователя 03.10.2026

Разрешены публикация в main и плановое тестирование на боевых карточках. Совместимость встроена в существующий ежедневный вызов `tools/ozon_card_push.py --apply` для классов с W, без точечного --offers. Расписание обоих кабинетов остаётся 08:14 UTC / 11:14 МСК. Этап совместимости идёт первым, под общим файловым lock; затем запускается обычный дожим. Если новый этап не подтвердил исправление, обычный дожим этого кабинета не запускается.

Автомат выбирает до 20 карточек кабинета, исключает needs_human и последние попытки моложе 20 часов. Накопленный счётчик старых успешных повторов не блокирует новый эпизод совместимости; неудача нового этапа оставляет needs_human=true и требует разбора человеком. Контентные ERROR и неоднозначные списки не отправляются. Сохранены перечитка перед записью, исходные снимки и проверка импортированной задачи, точных пар и окончательного статуса. Отключить новый этап отдельно можно флагом --skip-models; отдельный вызов нового этапа — --repair-models --models-auto --limit 20 --apply.

Проверено 24 unit-тестами, включая ограничение автоочереди, backoff, пропуск контентной ошибки и остановку обычного дожима после ошибки нового этапа. Первый отдельный запуск --models-auto --apply и полный запуск точных команд cron (--limit 500 --apply) в обоих кабинетах завершены: оба этапа без очереди и без отправок; общий lock открывается штатно. Для включения используется уже установленный cron; его текст не менялся. Каталог .git основного чекаута доступен сессии только для чтения, поэтому коммит и пуш подготовлены из отдельного клона в /tmp.

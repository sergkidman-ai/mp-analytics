# prod5: 23 удалённых в ТК карточки WB — остатки и корзина, 05.10.2026

Пользователь сообщил, что все 23 карточки из no_source.csv удалены в ТК,
и прямо разрешил обнулить их остатки на WB и перенести в корзину.
Это разовое разрешение только на эти 23 nmID в wb_acc1.
Никаких кодов ТН ВЭД и категорий WB не меняли. Операций wb_acc2 не было.

Результат подтверждён перечиткой 05.10.2026 10:49:26 UTC:
- 23/23 карточки в корзине, совпадение nmID и полного vendorCode проверено.
- 0/23 в активном каталоге.
- Все 23 chrtID на единственном складе продавца 944940 имеют явный amount=0.
- Положительных и неизвестных остатков FBS нет.
- Свежий warehouse_remains по wb_acc1: ни одного из 23 nmID в отчёте,
  физические остатки FBO и остатки в пути по этой выборке отсутствуют.

До записи FBS API не возвращал записи этих размеров: отсутствие ответа не приняли за ноль.
Выполнен один PUT /api/v3/stocks/944940: 23 chrtId, amount=0; HTTP 204.
После подтверждения нулей выполнен один POST /content/v2/cards/delete/trash
с ровно 23 разрешёнными nmID; HTTP 200. Затем выполнена независимая проверка
членства в корзине и отсутствия в активном каталоге, а также повторное чтение FBS.
Поиск корзины по отдельному nmID пропускал карточку; итог получен через реальную
пагинацию списка корзины с пересечением по разрешённым nmID.

Новый адрес аналитики stocks-report/wb-warehouses вернул пустое тело/объект,
поэтому не использован как доказательство нулевого FBO. Срез wb_stocks тоже
не принят за живой ответ. Для подтверждения создан существующий warehouse_remains:
у него нет фильтра по nmID, полный ответ сохранён на диск и отфильтрован локально.

Артефакты:
- `cards_before_apply.json`, `fbs_before_apply.json` — состояние перед записью.
- `journal.jsonl` — намерения запросов и ответы (без токенов).
- `verification.json`, `cards_after.json` — результат независимой перечитки.
- `fbo_verified.json`, `fbo_report_full.json` — живой отчёт FBO и целевая выборка.
- `tnved_review_examples.csv` — 7 примеров из трёх групп расхождений.

Карточки перенесены в корзину, не удалены навсегда. Для восстановления —
POST /content/v2/cards/recover с нужными nmIDs по отдельной команде пользователя.
Параметры карточек до переноса и прежние группы imtID сохранены; восстановление
не возвращает прежнюю группу автоматически. Исходных записей FBS не было,
положительные остатки для отката не предлагаются. ТК не менялся.

Инструмент `tools/card_wb_retire_deleted_tc.py` ограничен фиксированным списком
23 nmID и wb_acc1; по умолчанию только preview. Проверен журнал: два запроса
на запись затронули только разрешённые карточки/размеры, все записанные остатки равны нулю.

Исторический dry-run 16592 остаётся снимком 04.10: его 23 NO_SOURCE уже обработаны
этой операцией, они исключены из дальнейшего дозаполнения ТН ВЭД.

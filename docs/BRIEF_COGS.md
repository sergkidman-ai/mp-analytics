# Бриф: как считается себестоимость (COGS) «Цифрового квадрата» — Ozon / WB / Маркет

> Собрано из кода (read-only): `collectors/ms_demand_cogs.py`, `reports/margin_by_sku.py`,
> `reports/margin_ozon_sku.py`, `collectors/yandex_monthly.py`. Владелец логики — поток **fin**
> (миграции 0xx, `run_daily.py`). Этот бриф — справочный (поток rev), код не менялся.

---

## 0. Общий фундамент (для всех площадок)

1. **МойСклад — источник правды себестоимости.** Артикул — единый ключ связи МС ↔ площадки.
   `cost_seb` в справочнике `products` = закупочная цена (свежий прайс поставщика, обновляется ежедневно).
2. **Себест берётся с КОНКРЕТНОЙ отгрузки, а не усреднённый.** `report/stock/byoperation?operation.id=…`
   («Остатки по документу») отдаёт `positions[].cost` (в КОПЕЙКАХ, уже с учётом qty) — это FIFO-себест
   на `moment` документа отгрузки. `Σ cost/100` = себест всей отгрузки, ровно как в документе МС
   (не усреднение, не `report/stock` на дату). Эталон: demand `4747758355` = 284 ₽.
3. **Кэш `ms_demand_cogs`** (миграция 027): ключ `demand_id`, идемпотентный/резюмируемый.
   Витрины матчат по `demand_name` (= WB assembly_id / Ozon posting) напрямую.
4. **Деньги — якорь, не штуки.** net считается от денег площадки минус COGS; штуки — только для дележа
   себеста внутри мульти-позиционных отгрузок и для импутации непокрытого.
5. **Сторно COGS возвратов в продаваемый сток.** Если товар вернулся в СТОК (не «Брак»), себест исходной
   продажи реверсится — иначе при перепродаже спишется дважды. Гейт склада и период сторно у каждой
   площадки свои (см. ниже). Дефект («Брак») НЕ сторнируем — себест остаётся расходом.

## 1. WB — `reports/margin_by_sku.py` (platform='wb')

**Модель периода:** один недельный отчёт ВБ (`realizationreport_id`) целиком относится к месяцу своего
`create_dt` (дата формирования), не дробится по `rr_dt`.

**COGS основной путь (FBS):** готовый себест отгрузки из `ms_demand_cogs`, матч **assembly_id = demand_name
НАПРЯМУЮ**. Мульти-nm отгрузка делится между nm пропорционально штукам.

**FBO / непокрытое — каскад фолбэков по приоритету** (`_chain_cpu`):
1. cpu этого месяца (из матчей FBS текущей сборки);
2. cpu истории nm (`margin_by_sku` прошлых месяцев);
3. группа `cost_seb` по артикулу; 4) по префиксу (6зн→5→4 цифры);
4. состав набора (`set_cost`); 6) свежая закупочная (`ms_product.buy_price` по группе);
5. ручной себест (`cogs_manual`, диктует клиент).

**Сторно возвратов:** себест/шт = `cogs/qty` исходной отгрузки × штук возврата, **в МЕСЯЦ возврата**
(= месяц денежного реверса по строке «Возврат»). Мост — `salesreturn.demand.name` (= assembly_id).
Кап по бюджету sellable-штук (`ms_return_cogs`, поле `sellable`). Гейт склада: сторнируем **все, кроме «Брак»**.

**Формула:** `net = to_pay − logistics − storage − acceptance − other − COGS`.

## 2. Ozon — `reports/margin_ozon_sku.py` (platform='ozon')

**COGS основной путь:** тот же принцип, ключ озоновский —
`posting_number` → **первые 2 сегмента** (`order_id-shipment`, `norm_posting`) → FIFO-кэш `ms_demand_cogs`.
Мульти-SKU отправление: деньги и COGS делятся **поровну** между SKU отправления.

**FBO (~3.2%):** отгрузки в МС нет → прямой COGS не находится → **импутация** `sku_unit_cost_global`:
всеисторический себест/шт SKU из matched-постингов (кэш × их SKU по всем месяцам).
**Групповой fallback** по `external_code`: набор → `max`, одиночный → `min`.

**Сторно возвратов:** склад ∉ {**Брак, Озон**} («Озон» = удержан на стороне Озона, не наш сток).
Себест/шт = `cpu_global` (продажа обычно в другом месяце). Возврат даёт ДВЕ операции (денежную
`ClientReturnAgentOperation` и товарную `OperationReturnGoodsFBSofRMS`) → берём **MAX** штук на SKU
(одна физед.), кап по бюджету sellable. Бакетируется по **месяцу возвратной операции** (COGS SKU в этом
месяце может уйти в минус — корректная кредит-проводка).

**Формула:** `net = Σ(категории op) − COGS`. Пишет в `margin_by_sku` с `platform='ozon'`.

## 3. Яндекс.Маркет — `collectors/yandex_monthly.py` (`yandex_finance_monthly`)

**Ключевое отличие:** COGS **order-based**, БЕЗ `ms_demand_cogs` и БЕЗ `ms_return_cogs`.

**COGS основной путь (`_ms_cogs_monthly`):** `Σ products.cost_seb × qty` по позициям МС-документов
`customerorder` контрагента Маркета, **месяц = `moment` заказа**. Это ФАКТ из МС-заказов (приоритет);
**фолбэк** — карта себеста по SKU (`_cost_map`: `external_code` → баркод оффера → `ms_barcode` → МС),
с импутацией непокрытых штук (`cogs/qty_cov × непокрытые`).

**Сторно возвратов (внутри функции):** мост `salesreturn.demand.name` = `customerorder.name` (= номер
заказа ЯМ). Вычет **в МЕСЯЦ ЗАКАЗА** (где себест и учтён — иначе реверс попадёт мимо и переусторнирует
заказы вне окна). Себест возврата = `Σ cost_seb × qty` по позициям самого `salesreturn`, кап по себесту
заказа. Склад: сторнируем сток, **«Брак» НЕ сторнируем**. Возвраты по заказам вне окна `since` пропускаем.

**Также** в `_fold_order` COGS считается **без отмен и возвратов** (товар вернулся — себест не списываем).

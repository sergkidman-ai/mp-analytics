## B. СОПОСТАВЛЕНИЕ ПО ПРАВИЛЬНОМУ КЛЮЧУ

**Нормализация (и ничего кроме неё).** Артикул и «Код поставщика»: верхний регистр, затем выбрасываются все символы, кроме `0-9 A-Z А-Я` — то есть
пробелы, дефисы, точки, слэши, скобки; **ведущие нули НЕ срезаются** (`0185` и `185` — разные коды). Штрихкод: остаются только цифры, **ведущие нули
срезаются** (UPC-12 `0`+12 цифр = EAN-13). Похожие строки не склеивались, расстояния между строками не считались. 10 примеров «было → стало»:

```
k1  BS-X106R03694                → BSX106R03694
k2  BS-X106R03694                → BSX106R03694
k1  NV-TK450                     → NVTK450
k2  761-01                       → 76101
k1  TC-PMC2318H                  → TCPMC2318H
k2  TC-PMC2318H                  → TCPMC2318H
k1  TC-MTN-328BK                 → TCMTN328BK
k2  TC-MTN-328BK                 → TCMTN328BK
k1  BS-T5653                     → BST5653
k2  BS-T5653                     → BST5653
```

**По прайсам.** Строки прайса, сопоставившиеся по каждому ключу, считались независимо друг от друга (один и тот же товар может найтись обоими
ключами); «наших товаров» — уникальные `ms_id` по всем трём ключам с приоритетом article → «Код поставщика» → штрихкод. Колонка «шаг 3» — сколько
товаров давал ключ «Код поставщика» в одиночку.

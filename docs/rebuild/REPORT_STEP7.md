## 2. Перечитка каждого выбранного размера по его локатору

Все 2817 строк открыты заново в исходном файле: тот же лист → та же строка по `src_locator` (`лист!rN`) → те же колонки, что объявлены в парсере,
плюс пересчёт sha256 файла целиком. Проверено 2817 (3 файла, 4 листа): sha256 совпал 3 из 3, кодов строки ≠ `src_value_raw` — **0**, габаритов
в файле ≠ габаритам в сборке — **0**. `step7_reread_diffs.csv` пустой; указатели рабочие, размер восстанавливается из источника один в один.

**Выброс брака.** Убраны 34 коробки-переростка (`step6_review_big.csv`: объём >30 л или ось >600 мм) и 68 моделей, где один наш `code` привязан
к двум строкам ОДНОГО прайса с расхождением >50 мм; пересечений нет — выброшено 102 модели (`step7_dropped.csv`). Осталось **2715
подтверждённых строкой прайса**, из них четырёхзначных **2677**. Настоящая цифра покрытия: **2677 из 6586 = 40.6 %**. Выгрузка —
`step7_confirmed.csv`, у каждой строки полный указатель.

## 4. Разведка по nix.ru — НЕ ВЫПОЛНЕНА, сайт с этого сервера недоступен

Ни одна из 10 карточек не открыта, разведочных выводов о разметке nix.ru у меня нет, и придумывать их я не буду.

- **31.07,** curl по `/`, `/price/price_list.html`, `/search/?q=CE285A`, `/robots.txt` → 302 на `www.nix.ru/vpnerr.html`, тело пустое; через
  WebFetch — пусто.
- **01.08,** curl и urllib по `https://www.nix.ru/`, `https://nix.ru/`, `http://.../robots.txt` → TCP-отказ `91.233.230.52:443 connection refused`.

Наш egress-IP `155.212.189.66` сайт относит к VPN/датацентру (заглушка так и называется — `vpnerr`), сейчас соединение рвётся уже на уровне TCP.
Обход не искал: маскировка под другой IP — это обход блокировки, на такое нужна ваша команда.

**Проверил вместо nix** (только доступность и наличие блока габаритов, 8 запросов с паузой 3–4 с, никуда ничего не писал): `regard.ru` —
открывается, поиск по артикулу работает (`/catalog?search=CC388A` → 27 ссылок `/product/`), фронтенд Next.js с `__NEXT_DATA__`, есть sitemap, **но
габаритов упаковки в карточке нет вовсе** (`/product/179011/kartridz-cactus-cs-cf381a-cyan` — только «Количество в упаковке»); `dns-shop.ru` 401
антибот, `citilink.ru` 429, `onlinetrade.ru` 1.5 КБ JS-заглушка и sitemap 404, `openapi.icecat.biz` не соединяется; `nvprint.ru`, `hi-black.ru`,
`colortek.ru` главные 200, но поиск на JS — карточку одним GET не достал.

**Вывод прямой.** Через nix история нерабочая — не из-за разметки, а из-за доступа. Розница как класс сомнительна: у regard, единственного
открывшегося целиком, габаритов нет — магазину нужны вес и «шт в упаковке», а не короб.

**Где данные лежат машинно-читаемо, по убыванию дешевизны.** (1) **Прайсы брендов, которых у нас нет:** веб-пачка — это в основном NV Print,
Colortek, Blossom, S'OK, GP, то есть чужие бренды, а не «нет данных в природе». У cactus/sakura/izi габариты пришли колонкой в прайсе — значит
есть и у остальных; запрос менеджеру за выгрузкой с ДхШхВ закрывает сотни моделей и даёт указатель того же качества, денег 0. (2) **Сайты этих
брендов** — с сервера открываются, нужен короткий заход: есть ли блок размеров и берётся ли карточка одним GET. (3) **Платные каталоги** (Icecat
Full, 1С:Номенклатура) — правило 13, только с вашего «да» на сумму. (4) **Ваш браузер** (`claude-in-chrome`, резидентный IP) — nix, вероятно,
откроется, но это ручной канал: парсер снова упрётся в IP сервера.

**Цена сбора 3000 моделей парсером**, если источник найдётся: 2 запроса на модель ≈ 6000 запросов, пауза 3 с в один поток ≈ 5 часов, трафик ~5 ГБ,
денег 0, модель в разборе не участвует. Узкое место не цена, а доступ и наличие блока габаритов.

## 3. ИУ и МК

Разнесены по разным полям (`iu_*` и `mk_*`). Поле карточного размера заполняется только из ИУ.
МК не участвует ни в одном пересчёте: в `parsers.py` нет ни одной ветки, где `mk_*` попадает
в `iu_*`. У профилайна размеры не заводятся вовсе — ни одна карточка не может получить
ДхШхВ отсюда физически, колонок с линейными размерами в файле нет.

**Дубль короба у сакуры струйной (мм и см).** Загружены оба варианта: мм → `iu_*`,
см → `alt_*`. **Сходятся 353 из 353** (допуск 5% по каждой стороне), расхождений 0.

## 5. Указатель на источник и шлюз

На каждую загруженную величину записано: `src_file`, `src_locator`, `src_field`,
`src_value_raw`, `src_sha256`; на источник — размер, mtime, sha256, лист/число записей
(`sources_meta.json`).

Формат `src_locator`:

- xlsx/xls — `Лист1!r417`, `TDSheet!r842` — номер строки **как в Excel**;
- json рапида — `price[1204]#ID_1C2=П024069`. Взят `ID_1C2` (человекочитаемый код 1С), а не
  `ID_1C` (это GUID). Индекс плюс код: если файл перезаберут, указатель либо попадёт в ту же
  запись, либо честно упадёт.

**Шлюз** (`verify.py`) после записи CSV читает его обратно с диска, заново открывает исходные
файлы **своим отдельным кодом** (не переиспользуя парсеры), находит строку по `src_locator`,
колонку по имени из `src_field` и сравнивает с `src_value_raw`. Проверка сплошная, не выборкой.
Первое расхождение — исключение с именем файла, указателем, полем и обоими значениями; строка
без открывающегося указателя не записывается. У рапида дополнительно сверяется `ID_1C2` из
указателя с полем записи.

Проверено значений: cactus 34 920, izi 4998, sakura_laser 7465, sakura_inkjet 3971,
profiline 21 362, rapid 50 898. **Итого 123 614 значений, расхождений 0.**

Сравнение идёт по каноничному текстовому представлению (`common.canon`), одинаковому на
загрузке и на проверке: целые float пишутся без хвоста `.0`, остальное — как в ячейке.

## 6. rapid: единицы не объявлены

Файл — сырой ответ API (конверт `date/error/currency/level/total/price`, `total` = 8483,
совпадает с длиной массива). Габариты лежат в `GabarityDlina/Shirina/Visota` **строками**,
пустое значение записано как `'0'`. Поэтому:

- все три поля заполнены → 2031 запись, статус `ЗАГРУЖЕНО_БЕЗ_ЕДИНИЦ`;
- заполнены не все три → 18; пусто (нули) → 6434.

Единицы не объявлены нигде в файле, принадлежность ИУ/МК — тоже. **В мм ничего не

## 8. Наблюдения, которые пригодятся дальше (в этом шаге не использованы)

- **izi:** в колонке `Размеры мм` порядок осей не объявлен нигде в файле. Для объёма это
  неважно, для «длина/ширина/высота» — важно; при сопоставлении помнить.
- **cactus:** порядок колонок в файле — Длина, **Высота**, Ширина (не ДШВ). Колонки
  резолвятся по имени, не по позиции.
- **sakura_inkjet:** есть сводная текстовая колонка `Размер коробки мм` вида `60x25x105x25`
  (четыре числа). Не использовалась: источник — отдельные числовые колонки.
- **profiline:** между шапкой (строка 10) и данными идут 1196 строк-группировок
  («Бумага», «совм.») без GUID — помечены `СЛУЖЕБНАЯ`, не выброшены молча.

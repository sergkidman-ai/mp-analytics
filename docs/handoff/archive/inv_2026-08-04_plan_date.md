# inv · План-дата приёмки и срок доставки поставщика (03–04.08.2026)

Архив сессии. В `docs/BRIEF_INV.md` осталась выжимка; здесь — детали, как это устроено.

## Правило

План-дата приёмки в заказе МС = **через N рабочих дней после даты счёта**, приёмка ставится
на ту же дату, время **08:00**. Формулировка Сергея 03.08.2026 на примере заказа 3898 (Колортек,
счёт Пн 03.08 16:38 МСК → приёмка Ср 05.08): «через 1 рабочий день» = один ПОЛНЫЙ рабочий день
пропускаем, а не «ближайший рабочий». Счёт Пт 31.07 → Вт 04.08.

Первая реализация 03.08 прочитала правило наоборот (ближайший рабочий день, коммит `31dbccf`);
исправлено в `5fdaf96` параметром `skip` у `workcal.plan_date(inv, six, skip)`.

## Где живёт настройка

- `supplier_payment_terms.delivery_days` (миграция `208_payment_terms_delivery.sql`,
  `smallint NOT NULL DEFAULT 1`, CHECK 1..30) + колонка «Срок доставки» на странице
  `/suppliers/payment-terms`. Значение = через сколько РАБОЧИХ дней приёмка: **1 = завтра**
  (умолчание, прежнее поведение), **2 = послезавтра**. В календарь идёт `skip = delivery_days − 1`.
- Читает `invoice_to_po.plan_skip(org_inn, supplier_inn)`; `upd_to_supply._skip_for(order, inn)`
  берёт ИНН нашего юрлица из организации заказа (сроки у ЦК и Дисквэра независимы).
- Фолбэк, когда строки нет или БД недоступна — зашитый `SUPPLIERS[inn]["plan_skip"]`.
  Держать его в синхроне с БД не требуется: он срабатывает только при отказе БД.

## Поиск по ГРУППЕ поставщика

Напоминание Сергея 03.08.2026: поставщик = ГРУППА юрлиц, ООО у него со временем меняются
(та же логика давно работает в проверке позиций заказа). Поэтому настройка ищется не по ИНН
из счёта, а по всем ИНН групп, где состоит это юрлицо: `supplier_groups.related_inns(inn)`
(индекс `INN2GROUPS`; у 7806486149 групп две — «Спринт» и «Спринт МСК», отсюда множество).
Из найденных строк берём БОЛЬШИЙ срок: приёмка позже плана безобиднее, чем задним числом.

Одна строка на действующее юрлицо накрывает всю группу: у «Блоссома» настройка стоит на
«КАРТРИДЖ ТРЕЙД» (9718075418) и действует на счета «КОМПАНИЯ БЛОССОМ», «БРАВО», «АЛЫЕ ПАРУСА»,
которых в графике оплаты нет вовсе. В таблице группа видна в ячейке («2 — послезавтра · гр. Блоссом»).

Переводить на группу ОСТАЛЬНЫЕ условия оплаты не нужно — решение Сергея 04.08.2026: при смене
ООО баланс поставщика сводится в 0, расчёты по старому юрлицу прекращаются, условия переносятся
на новое ООО руками.

## Календарь `workcal`

- Строгий разбор ответа isdayoff.ru: коды ошибок («100», «101», «199») больше не читаются как
  «выходной» — раньше брался первый символ.
- Догадка-фолбэк (нет сети / дата за горизонтом сервиса) НЕ кэшируется, иначе замерзала бы навсегда.
- Будний день, объявленный выходным вдали от праздничного блока, перепроверяется мимо кэша
  и кэш чинится: так вылечился отравленный `04.08 = 1`.

## Выравнивание документов 03.08

Заказы КТ-000117, 3897, 3898 → 05.08; заказы 3880, 3881 → 04.08; приёмки КТ-000117, 3897 →
05.08 08:00. Проведённые и приёмка 3881 (дата уже наступила) не тронуты.

Грабли: приёмки этого поставщика нельзя искать по `name` — из-за годовой перенумерации МС есть
тёзки прошлых лет, PUT по чужому документу отбивается 412 «нарушено ограничение уникальности
параметра name». Искать по ссылке `purchaseOrder`. И запрашивать список с `order=moment,desc`:
без сортировки МС отдаёт САМУЮ СТАРУЮ страницу.

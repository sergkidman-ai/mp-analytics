# BRIEF_RET — фазы 7–8 (07.08.2026), вынесено из брифа 10.08.2026

**Фаза 7 — кнопка «Обновить» (07.08.2026).** Под каждой сводкой inline-кнопка: тот же
`/obnovit`, но не набирая команду. Обработчик живёт в `returns-bot.service`, поэтому кнопка
под ночной рассылкой тоже рабочая.

- **сбор быстрый** (`gather(quick=True)`): у WB одно окно вместо трёх, у вывоза FBO одно
  вместо двух — 8 с против 40 с. Старую закрытую историю (3900 из 4000 строк) кнопка
  не перечитывает, её освежает ночной полный прогон;
- **`store(mark_gone=False)` при быстром сборе обязателен**: при узком окне «нет в выдаче»
  ≠ «пропал», иначе быстрый сбор похоронит всё, что не попало в окно;
- в итоге вместо бессмысленного «обновлено 4036, позиций 4100» — **сколько получено нами
  с прошлого обновления** (`collect.received_since`, считается по `status_raw`, см. ниже);
- параллельный сбор заблокирован флагом `_busy`: вторая нажатая кнопка получает отказ,
  а не встаёт в очередь и не идёт в API площадок второй раз.

**Фаза 8 — правки по живой эксплуатации (07.08.2026).**

- **Яндекс `RECEIVED` — не «забрать», а «в пути».** Означает «принят в пункте выдачи»
  логистикой, а не «лежит и ждёт нас». Сергей проверил заказы 58716444738 и 59558307072:
  в ЛК у них «Готов к отправке», к выдаче их нет. Признак реальной готовности —
  `pickupTillDate`: по базе заполнен ровно у `READY_FOR_PICKUP` и пуст у всех `RECEIVED`.
  Забрать: 20 → 17;
- **штрихкод Ozon шлём файлом** (`sendDocument`), не фото: `sendPhoto` перегоняет PNG
  784×144 в JPEG, тонкие штрихи плывут и сканер в пункте выдачи код не берёт;
- **срок жизни штрихкода в подписи.** В API его нет нигде: `/giveout/barcode` отдаёт одно
  значение, `/giveout/info` и `/giveout/list` по обоим аккаунтам пусты. Дата напечатана
  только на бланке PDF (`/giveout/get-pdf`) — разбираем оттуда через `pdftotext` (шрифты
  подмножеством, свой парсер врёт). Код живёт сутки, повторными запросами **не продлевается**,
  у аккаунтов сроки разные. Печатаем по Москве (сервер в UTC), истёк — «⛔ обновить в кабинете»:
  сами обновить не можем, `/barcode-reset` пишет в кабинет;
- **сам печатный бланк не отправляем** (решение Сергея: лишнее), но запрашиваем — ради срока.

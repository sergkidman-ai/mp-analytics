## Связи универсальных моделей в цепочке FIFO (`analog_fifo`, 2026-08-14)

Один картридж продаётся под разными кодами (Q2612A = Canon 703): заказан 5335, со склада ушёл 0002.

`reports/fifo_fallback.py` добавлен шаг **`analog_fifo`**: `unit()` товар → набор → аналог,

**максимальный** себест. Без миграции 408 работает как раньше (`to_regclass`).

**Эффект в деньгах = 0 ₽ — и это правильно** (A/B, июль, 4 аккаунта): выше в цепочке стоит

проданного по FBO раньше своей первой отгрузки.

## Себест только «до даты отгрузки» (правило Сергея 2026-08-14, коммит `0d8927e`)

Товар сперва поступает на склад и только потом уходит покупателю → себест ищется по внешнему коду
**до даты отгрузки, но не позже**. Цена из будущего запрещена. Два места нарушали правило:

1. `fifo_fallback._by_ms` брал «первую ПОСЛЕ», если до даты товар не отгружался → теперь `None`,
   управление уходит дальше по цепочке.
2. `margin_by_sku._fallback_sources` (`cpu_hist`) брал себест из САМОГО СВЕЖЕГО месяца витрины
   независимо от собираемого: пересборка января подставляла цену августа. Теперь история режется
   параметром `before` = первый день собираемого месяца.

**Пересобран весь 2026** (8 мес × 4 аккаунта): COGS **+25 831 ₽** (чистая ниже на столько).
Крупнейшие: Ozon acc1 фев −9 473; WB acc2 мар +7 672, апр +5 358; WB acc1 янв +7 409, июн +6 569.
Статика вкладок синхронизирована: ВБ — рефриз из сырья (строки денег НЕ изменились, только
cogs/net), Ozon — `reports.ozon_mp_freeze cogs` (7 месяцев-аккаунтов); сверка после = 0 расхождений.

**Покрытие 2026:** WB 16 055 шт — 90.5 % своя отгрузка МС, 8.3 % FIFO по истории/товару, суррогат
карточки 5 шт; Ozon 11 375 отправлений — 96.8 % МС, 3.1 % FIFO, суррогат 8. Выручка без COGS —
17 748 ₽ (0.0 %). **Вердикт: коллектор приёмок МС не нужен** — закрыл бы 11 позиций из 27 430
(0.04 %) ценой постоянной нагрузки на МС. Вернуться, если суррогат вырастет выше ~1 %.

**Известный зазор (не закрыт, нужно решение):** внутри месяца витрины берут опорную дату
`day = date_to` (конец собираемого месяца), поэтому продажа 03.08 может получить себест отгрузки
от 20.08. Межмесячная «цена из будущего» закрыта, внутримесячная — нет. Строгий вариант — считать
по дате первой продажи nm в месяце.

## Статус «нужна ручная себест» (2026-08-14, коммит `0f933bf`)

Где FIFO нет нигде, себест раньше молча падал в `products.cost_seb` (метод `imputed`) — это средняя
по остатку, а не себест списания. Теперь ровно те же строки помечаются `method='need_manual'`:
оценка в ячейке остаётся (чтобы месяц не поехал), но строка ждёт цифры от человека. Ставят метку
3 коллектора + 3 кнопки «пересчитать» в `web/app.py`; ярлык «НУЖНА РУЧНАЯ СЕБЕСТ», опция фильтра
«Способ», бейдж и поле ввода — в `mp_cogs_page` / `ya_cogs_page` / `mp_cogs_drill`. Ввод цифры
переводит метод в `manual` (побеждает всё, переживает прогоны).

Бэкфилл: **WB 5 отгрузок / 10 612 ₽ (все `unredeemed` → сторно, ввод не даётся и не нужен),
Ozon 19 / 27 809 ₽ (из них 15 «Выполнен» — редактируемые: acc2 05 — 7, acc2 06 — 7, acc1 08 — 1),

## Сторно = ровно начисленное (правило Сергея, 2026-08-14) — СДЕЛАНО

«Сколько начислили — столько и сторнируем». Ozon сторнировал по **средней** цене единицы SKU
за всю историю — заменено на себест **самой отгрузки**: `posting_unit_cost()` в
`reports/margin_ozon_sku.py` строит `norm_posting → cogs_отгрузки / штук` из
`OperationAgentDeliveredToCustomer`; фолбэки (средняя по SKU → FIFO товара → группа → ручная)
только когда моста к отгрузке нет, источник пишется в лог («источник себеста: …»).
Проверка: `0253631835-0004-1` (SKU 1873143724, acc2 июль) 2 387.96 → 3 079.13 ₽ = FIFO отгрузки.
Пересобраны 2026-01…08 × oz_acc1/oz_acc2, Δ COGS **+15 675 ₽**, статика обновлена
(`ozon_mp_freeze.refresh_cogs`). ВБ (`margin_by_sku.py`) уже сторнировал по своей отгрузке —
пересборка 05/06/07 × acc1/acc2 не дала ни одной строки «без моста»; Яндекс исключает себест
возвращённого заказа целиком. Расхождений статика↔витрина по ВБ за 4 месяца — 0.

**Месяц НЕ выравниваем — решение Сергея 2026-08-14.** Раздел «Себестоимость» снимает себест
в месяце **отгрузки**, витрина/Отчёты МП — в месяце **денежного реверса** выручки; сумма за период
одна и та же, различается только разбивка по месяцам. Вопрос закрыт, не возвращаться.

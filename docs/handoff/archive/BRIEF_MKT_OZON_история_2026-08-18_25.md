25. **21.08 — закрытие сессии: `SHADOW_MODE_V0_1`, коммит `17aaddb`.**
    Статус контура — `SHADOW_MODE_V0_1`. Автоматически работают только
    OBSERVE → HYPOTHESIZE → PRIORITIZE → DESIGN → VALIDATE → PLAN; ACT — только после
    разрешения человека; EVALUATE → KEEP/ROLLBACK → MEMORY автоматически **не замкнуты**.
    * **H-002 = `BLOCKED_BY_POWER`.** 3,0 заказа на плечо при необходимых 128 (в волне 200 SKU —
      4,2; все восемь волн вместе — 33,3). W1 **не открыта и к согласованию не предъявляется**,
      разрешение основателя по ней не запрашивается; W1–W8 хранятся только как проект дизайна
      (`docs/experiments/waves/`). Отсутствие SKU-level мощности **нельзя обходить дроблением
      на волны**. Запрет программный: для бессильной гипотезы закрыты `READY`,
      `APPROVAL_REQUIRED`, `RUNNING`, автомат упирается в потолок `VALIDATED`, apply-план
      не создаётся (`исполнимый: False`). Разблокировка — только сменой дизайна: более крупная
      единица анализа, кластерный outcome, существенно более длинное окно, другая метрика.
      Тем же запретом закрыты H-003, H-005, H-007, H-010.
    * **Решения человека 21.08:** H-006, H-008, H-004 — `DEFERRED` (сегодня не одобрены);
      H-002 — `DEFERRED` + `BLOCKED_BY_POWER`; E5–E8 и H-001 продолжают только накапливать
      данные, состав и даты сверки не трогаем.
    * **Источник истины по финансам — BI.** При нехватке детализации действует
      `BLOCKED_BY_ECONOMICS_GRANULARITY`.
    * Ставки, цены, кампании, товары, cron/systemd и внешние API-записи не менялись.
    * **Следующий шаг: H-009 — автоматизация EVALUATE → KEEP/ROLLBACK → MEMORY.** Это
      capability gap системы (автоматический оценщик результатов), а не рекламный эксперимент;
      деньгами напрямую не оценивается. Старт: `venv/bin/python tools/ozon_hypo.py status`,
      затем `trace --for H-009`.

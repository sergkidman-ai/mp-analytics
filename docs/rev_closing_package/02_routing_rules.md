# Правила маршрутизации auto / review и порядок поиска

## Маршруты (route)
- **auto** — ответ можно публиковать без правок (шаблон/высокая уверенность).
- **review** — на вычитку человеком (все вопросы + содержательные/негативные отзывы).
- **human** — движок не отвечает, целиком на человека.

В боевом режиме с модерацией **любой** ответ всё равно проходит ручное подтверждение в Telegram
(режим «всё вручную»), route влияет только на пометку/приоритет.

## Отзывы (draft_review)
| Условие | route | conf | Ответ |
|---|---|---|---|
| рейтинг ≥4, есть текст | auto | 0.8 | позитив-ротация |
| рейтинг 5, текста нет (пустая звезда) | auto | 0.95 | позитив-ротация |
| рейтинг ≤3 (негатив) | review | 0.5 | хендофф по QR-чату |
| позитив с вопросом/проблемой по сути (есть `?` или дефект-слова) | review | — | LLM-ответ на фактах карточки |

Только позитив/пустые звёзды идут auto; всё негативное и содержательное — на человека.

## Вопросы — всегда route=review (никогда не auto)
Все вопросы уходят на вычитку. Внутри — многослойный подбор ответа. Финальная сборка ответа (`_llm()`
в `feedback_today.py`) с 2026-07-27 идёт на `QUESTION_MODEL` = `claude-opus-5` (было DeepSeek); веб-поиск
внутри слоя 4 остаётся на `WEB_MODEL`/DeepSeek, отзывы — на `MODEL`/DeepSeek без изменений.

### Порядок поиска для вопросов (как есть в коде feedback_today._answer)
1. **Карточка-серия (shortcut)** — если модель покупателя это вариант серии из списка
   совместимости карточки (суффиксы -N/-NF/-WF/-DN и служебные коды L662B и т.п.) →
   детерминированный ответ «да, подойдёт», **без веба** (бесплатно). Гейт: нет дефекта, нет вопроса о цвете.
2. **Знание модели (LLM) + КАТАЛОГ** — ответ по модели принтера с проверкой нашего каталога листингов
   (подставляет площадочный артикул WB/Ozon, если у нас есть листинг под эту модель).
3. **Кэш совместимости** — если по паре (товар × модель принтера) уже отвечали → берём вердикт из БД,
   веб НЕ зовём (главная экономия).
4. **Веб-поиск (DeepSeek)** — только если модель не уверена (need_web / conf<0.6 / тёмный регуляторный
   код). `web_compat` для совместимости, `web_fact` для ТТХ/подбора/процедурных (чип/прошивка).
   Sonnet-сплит (второй проход на claude-sonnet-5) убран 2026-07-27 как лишнее звено.
5. **Guardrailّы:**
   - код-расходника, которого нет в карточке/каталоге, — вырезается (защита от выдуманных артикулов);
   - ложное «нет в наличии» / увод «на сторону» при наличии нашего листинга — заменяется на наш артикул;
   - пред-продажный вопрос (нет коробки/чека) — убирается «напишите по QR на упаковке».

### Фактический расклад источников (по 15 обработанным вопросам)
карточка 7 · карточка-серия 3 · каталог/none 3 · веб-факт 1 · модель 1 → **веб реально дёргался 1 из 15**
(движок сильно card/catalog-first, веб — редкий и дорогой фолбэк).

## Известные слабые места (см. полный отчёт)
- не-картриджи (утюг/чайник) — движок иногда отвечает вместо эскалации на человека;
- утечка служебной разметки при неудачном парсе JSON;
- негатив-отзывы — единственный шаблон, приедается.

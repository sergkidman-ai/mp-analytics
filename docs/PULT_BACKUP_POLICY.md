Поток: infra. Проверено 16.11.2026. Предложение длительного хранения ещё не
утверждено владельцем; покупка места не выполнялась.

## Уточнение после обсуждения 16.11: предложение меньшего объёма

Владелец просит сократить ежедневное дублирование кода и объяснить ротацию.
Новое предложение: **3 ежедневных + 2 недельных, без месячных**, до 5 уникальных
точек. Недельная точка — одна выбранная полная копия, которую сохраняют дольше,
а не слияние ежедневных. Совпадающую ежедневную/недельную дату хранят один раз.
Код/окружение и оригиналы документов/медиа отделить от ежедневных дампов:
сохранять проверенную базовую версию и изменения, предварительно сверив GitHub
с реально развёрнутым кодом. Это предложение, действующие настройки не изменены.

Ниже 7/4/3 и 100 ГБ остаются расчётом расширенного варианта с полными пакетами.
100 ГБ не являются обязательным минимумом. Точное место сокращённого варианта
рассчитывать после проверки восстановления облегчённых пакетов. У Rev главная
лишняя ежедневная часть — venv321 МБ до сжатия, код всего6 МБ. У Beyindi медиа
уже не дублируются ежедневно. У Сокола БД всего1,55 МБ до сжатия; документы и
окружение занимают существенно больше. Исходные документы сохранять отдельно.

## Состав и первая контрольная точка

Обычная полная копия: согласованный PostgreSQL snapshot, дамп схемы/данных/
ACL, роли PostgreSQL, рабочий код с незакоммиченными изменениями, Git bundle,
версии Python-пакетов, первичные PDF/счета, `.env`, конфигурация нужных служб,
Caddy и российского nginx ingress, параметры восстановления доступа.
Секретная конфигурация находится только внутри зашифрованного пакета.
Это не образ всего VPS. Окружение Python переустанавливается по списку пакетов;
восстановление предполагает доступ к дистрибутивам PostgreSQL/Python/rclone.
Кэши повторных API-ответов и производные пары этикеток не копируются.

Первая точка состоит из трёх зашифрованных файлов в одной папке:

1. `pult-full-20261116T122651Z.tar.gpg`: 600432724 байта; дамп 552083860 байт,
   рабочий код и конфигурация. Snapshot 12:12 UTC. Восстановление проверено
   16.11 в 12:44 UTC; все 262 количества строк совпали.
2. `pult-bootstrap-20261116T123310Z.tar.gpg`: 450646 байт; роли и права доступа
   PostgreSQL, дополняющие первый дамп. Проверено повторным скачиванием.
3. `pult-documents-20261116T123929Z.tar.gpg`: 263342164 байта; 5649 первичных
   документов, проверены все хеши после скачивания и расшифровки.

Всего 864225534 байта, около **0,864 ГБ**. В следующих ежедневных копиях роли,
ACL и документы уже включаются в основной пакет. Дополнения первой точки
автоматическая ежедневная ротация не удаляет.

Восстановление выполнять только на новом сервере/в отдельной базе, сначала
проверить целостность и отключить бизнес-таймеры. Сначала восстановить роли,
затем БД, права, код и документы; инструкции первой точки — в bootstrap-архиве.
Рабочие пути и секреты обновлять под целевое окружение. Общие Caddy/nginx
конфигурации нельзя слепо подменять: на VPS находятся другие проекты.

## Предлагаемая постоянная политика

- Пульт: 7 ежедневных + 4 недельных + 3 месячных точки, до 14 полных пакетов.
  Даты могут совпадать, поэтому расчёт по 14 — консервативный.
- Сокол: действующие 14 успешных дней; Beyindi: действующие 9 успешных дней
  и все используемые ими общие объекты media/images/tools.
- Rev: 7 ежедневных + 4 недельных, дополнительно защищённые контрольные точки.
  Его автоматическая Drive-ротация сейчас только формирует план; чистка выполнена
  вручную с учётом `/root/rev-recovery/backups/protected-anchors.json`.
- Удалять истёкшие копии только после новой успешной внешней проверки.
  Последние проверенные точки, защищённые anchors, пароли, манифесты и общие
  объекты действующих точек сохранять. Чужую корзину аккаунта не очищать.
- Ежедневная копия даёт до 24 часов потери изменений при штатной работе;
  для меньшего окна нужна отдельная схема WAL/PITR и новый расчёт места.

Код в GitHub есть, но часть действующего кода ещё не закоммичена. Поэтому
одного GitHub для восстановления недостаточно. Сейчас снимок рабочего кода
входит в ежедневный пакет. После наведения порядка можно сохранять код,
окружение и неизменяемые документы по версиям и не дублировать их ежедневно;
это отдельная оптимизация, в текущий расчёт экономия не заложена.

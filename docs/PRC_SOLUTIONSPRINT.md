# Солюшнс принт: кабинет → оприходования МСК

Поток `prc`. Поручение и уточнения пользователя от 12.10.2026.

## Правила

- С 14.10.2026 по решению пользователя ручные загрузки прайса Спринта в МС прекращены.
  Штатный источник оприходований — только этот автоматический загрузчик ЛК.
- 8 старых документов СПб от 20.08.2026 на «Удаленном складе» удалены 14.10 по прямой
  команде пользователя; подтверждено 0 оставшихся СПб и неизменность 9 МСК / 848 позиций.
  Копии с позициями и журнал: `docs/reports/prc_solutionsprint/delete_spb_20261014/`.
- Вход: POST авторизации может вернуть HTTP 500 уже после создания сессии.
  С 19.10.2026 загрузчик проверяет её отдельным GET `/personal/`: обязательны
  ссылка выхода и отсутствие поля пароля. Пароль повторно не отправляет; ошибки
  остальных запросов и неподтверждённая сессия блокируют сбор.
- Источник: авторизованный `cartridge.ru`, регион **Москва**. `SOLUTIONSPRINT_LOGIN` и
  `SOLUTIONSPRINT_PASSWORD` читаются из `.env`; cookies и HTML кабинета не сохраняются.
- Найденная штатная выгрузка «Экспорт новинок» содержит только новинки и не содержит
  остатков. По окончательному уточнению 14.10.2026 используются разделы: Распродажа,
  Картриджи, Фотобарабаны, Чернила (отдельные и заправочные наборы), Печатающие головки,
  Бункер отработанного тонера, Узел переноса изображения, Блок проявки. Их точные URL
  заданы в `solutionsprint_source.CATEGORIES`; прочие категории не обходятся.
  Производитель — Solution(s) Print / Sprint / SP / S.Print либо Standart / Standard,
  оригинальность — «Совместимый». Проверяются штатными фильтрами ЛК с перечиткой
  выбранных чекбоксов на КАЖДОЙ странице. В Распродаже, где фильтра производителя нет,
  эти два свойства проверяются по карточке каждого товара. Имя принтера HP/Ricoh не
  определяет производителя расходника; заправочные наборы HP SK-* подтверждены как
  Solution Print по свойствам. Оригиналы/OEM исключены также по именам источника/МС.
  У разделов без разрешённых производителей/совместимых товаров фиксируется нулевой
  результат с причиной. Наборы картриджей остаются исключёнными действующим ЧС;
  это не запрет заправочных наборов. Повторы разделов не суммируются.
  В строках доступны закупочная цена и раздельные остатки складов.
- Количество = Москва + СПб. Повторы по разделам не суммируются. Дробные количества
  сохраняются; один скрытый склад признаётся нулевым лишь когда отдельный точный
  `MAX_QUANTITY` того же кода равен остатку видимого склада. «Под заказ» = 0.
- Цена Москвы: закупочная RUB из кабинета, не рекомендованная розничная. Если доступны
  только USD — курс ЦБ на дату загрузки × 1,03, округляется только результат до копеек.
- Код сайта превращается в точный московский артикул `SP<код>_MSK`. Разные товары под
  одним кодом и составные коды с `/` исключаются и фиксируются в отчёте.
- Только карточки контрагента «Солюшнс принт МСК». Архив, «Брак» в названии МС либо
  поставщика, ЧС, неоднозначные карточки не приходуются. Для «Брака» журналирует qty=0.
- Организация «ЦИФРОВОЙ КВАДРАТ», склад «Удаленный». Документы по 100 позиций.
- Обновляются **закупочная цена и Описание** существующих карточек, только при изменении.
  Новые карточки автоматически не создаются; несопоставленные проходят обычные правила
  «Новинок». Последний успешный прайс и строки сохраняются в `prc_price_load/row`.
- Регулярно заменяются только `s_print_msk_*` строго на нужном складе и организации.
  Существующие СПб-документы не входят в область удаления.
- Неполный каталог, потеря авторизации, аномалии цен или уменьшение числа позиций
  более чем на 30% останавливают замену. Предыдущие оприходования сохраняются.

## Замена и восстановление

Перед записью сохраняются план, все прежние документы с позициями и исходные карточки.
Новые документы сначала создаются непроведёнными с уникальным временным именем.
Проверяются позиции; карточки обновляются партиями не более 50 в минуту; после первых
200 — десятиминутная пауза и проверка отклика API операционных заказов. Эта проверка
не доказывает доставку вебхуков: подписки не отключаются. Затем повторно проверяется
идентичность, архив и «Брак» всех позиций, проводятся все новые документы и только после
перечитки удаляются прежние. Новые имена приводятся к `s_print_msk_YYYY-MM-DD_pN`.

При сбое незавершённый план остаётся в `logs/prc_solutionsprint_state.json`. Следующий
запуск восстанавливает его, не создаёт ещё одну партию. Удаление ограничено сохранёнными
id и перепроверкой склада, организации и версии документа. При сбое после проведения,
но до удаления, возможен временный двойной остаток; журнал позволяет завершить замену.
Во время обновления карточек новые документы не влияют на остатки.

После ручной замены документов (исправление 14.10.2026): если все сохранённые новые
документы исчезли, а в МС есть проведённая партия, прежний запуск помечается
`superseded`. Его состояние и список текущих документов сохраняются в папке отчёта;
затем собирается свежий каталог и строится новый план по текущему МС. Старый прайс
не восстанавливается поверх ручной загрузки. Частичное исчезновение, оставшийся
незаписанный черновик или отсутствие проведённой партии требуют разбора и
останавливают запись. Ошибки доступа/API не считаются удалением документа.
Перед восстановлением и перед проведением проверяется отсутствие посторонних
МСК-документов. В журнале ошибки API теперь содержат HTTP-статус и код МС без тела
ответа и секретов.

Одновременные запуски закрыты `flock`. Работа не начинается/приостанавливается перед
очередной партией карточек, если активны ночной `prc-enter-buyprice` или сервисы разового
обновления описаний. Пользователь явно назначил дневные запуски, что является исключением
из ночного окна общего `ms-mass-change`; темп, дельта, копии и проверка сохраняются.

## Запуск и диагностика

```bash
./venv/bin/python -m prices.solutionsprint                 # свежий кабинет, без записи в МС/БД
./venv/bin/python -m prices.solutionsprint --source /path/source.json  # повторный анализ
./venv/bin/python -m prices.solutionsprint --apply         # свежий кабинет и замена
systemctl status prc-solutionsprint.timer prc-solutionsprint.service
journalctl -u prc-solutionsprint.service -n 30 --no-pager
```

Юниты: `prices/prc-solutionsprint.{service,timer}`. Ежедневно **08:07, 13:12, 18:17 МСК**
(05:07, 10:12, 15:17 UTC), включая выходные. Пропущенный запуск не догоняется ночью.
Отчёты: `docs/reports/prc_solutionsprint/<время>/source.json`, `plan.json`, `summary.json`,
CSV исключений и аномалий. Сбой имеет ненулевой exit code в systemd; автоматическая
отправка сообщений в Telegram/почту этим модулем не выполняется.

## Контроль автоматической загрузки — с 19.10.2026

`prc-price-watch@s_print_msk.timer` проверяет результат ЛК каждые полчаса в своём
дневном окне. Почту Спринта больше не читает: старые письма несопоставленного
не подтверждают создание оприходований. Новинки синхронизирует сам загрузчик ЛК.

Ожидания: ежедневно 08:07/13:12/18:17 МСК, включая выходные. На завершение даются
2 часа, как в `prc-solutionsprint.service`: пороги 10:07/15:12/20:17 МСК,
уведомление при ближайшем последующем тике сторожа. При переходе к новому слоту
не забывается уже просроченный предыдущий. Учитывается только реальная успешная
загрузка `source_kind=cabinet`, `status=ok`, `dry_run=false`, с документами и
позициями. Время источника/плана (`moment`) должно быть не раньше ожидаемого
запуска; время завершения восстановления старого плана само по себе не подходит.

Текст тревоги называет пропущенный запуск, срок и последнее успешное обновление;
предлагает проверить сервис/ЛК и не загружать прайс вручную. Адресаты прежние,
одна доставка каждому на пропущенный слот. Неудачная доставка повторяется без
дублирования успешных. Суточный почтовый замок не влияет на эти уведомления.

Проверка без почты, уведомлений, запуска загрузки и изменения замков:
`./venv/bin/python -m ops.prc_price_watch --supplier s_print_msk --check-overdue`.
`--dry` даёт ту же безопасную проверку; `--force` не запускает загрузку из почты.

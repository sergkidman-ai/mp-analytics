# Харвестер габаритов — инструкция для запуска на Windows

> **Версия от 30.07.2026.** Заменяет предыдущую целиком — старый файл удалите.
> В прошлой версии поиск Wildberries молчал по всем позициям (`NOT_FOUND` 10 из 10):
> WB сменил адрес поиска и формат ответа. Исправлено и проверено — тест на тех же
> десяти моделях теперь находит карточки по всем десяти. Подробности внизу,
> в разделе «Что изменилось».

Что это. Небольшая программа, которая заходит на **публичные** страницы Wildberries
и Ozon, находит там карточки таких же картриджей у **других продавцов** и выписывает
размеры упаковки, если продавец их указал. Ничего не покупает, ничего не меняет,
никуда не отправляет — только читает и складывает найденное в файл-таблицу.

Зачем запускать на домашнем компьютере. На нашем сервере WB и Ozon закрыты прокси —
оттуда карточки не открываются. С обычного домашнего интернета всё видно нормально.

**Ничего страшного сделать нельзя.** Программа не знает наших паролей и токенов,
не заходит в личный кабинет, не выкладывает товары. Худшее, что может случиться, —
она ничего не найдёт и напишет `NOT_FOUND`.

## Шаг 1. Поставить Python (один раз, минут пять)

1. Открыть **https://www.python.org/downloads/** — большая жёлтая кнопка
   «Download Python» скачает установщик для Windows.
2. Запустить скачанный файл.
3. **ВАЖНО.** В самом низу первого окна установщика поставить галочку
   **«Add python.exe to PATH»**. Без неё дальше ничего не заработает.
4. Нажать «Install Now» и дождаться надписи «Setup was successful».

Проверка, что получилось: нажать `Win + R`, набрать `cmd`, Enter — откроется чёрное
окно командной строки. Напечатать в нём:

```
python --version
```

и нажать Enter. Должно ответить что-то вроде `Python 3.13.2`. Если пишет, что команда
не найдена — установка прошла без галочки из пункта 3, надо переустановить с ней.

## Шаг 2. Положить папку с программой

Распаковать присланную папку `harvester_pack` на рабочий стол. Внутри должно быть
четыре файла:

| файл | что это |
|---|---|
| `competitor_harvester.py` | сама программа |
| `residual_oem.csv` | полный список — 1163 позиции без габаритов |
| `top216_uncovered.csv` | приоритетный список — 216 моделей, дающих 80 % непокрытой выручки (20,17 млн ₽) |
| `HARVESTER_README.md` | этот файл |

## Шаг 3. Открыть командную строку в этой папке

Самый простой способ: открыть папку `harvester_pack` в проводнике, щёлкнуть мышью
по строке адреса сверху (там, где написан путь), напечатать там `cmd` и нажать Enter.
Откроется чёрное окно, уже находящееся в нужной папке.

## Шаг 4. Поставить единственную зависимость

В этом чёрном окне напечатать:

```
pip install requests
```

Enter. Пойдут строчки установки, в конце — `Successfully installed requests`.
Это делается один раз.

Если пишет, что `pip` не найден, попробовать вариант:

```
py -m pip install requests
```

## Шаг 5. ТЕСТОВЫЙ запуск на 10 позициях

Сначала обязательно пробуем на десяти — чтобы убедиться, что всё живо, и не ждать часами:

```
python competitor_harvester.py --input top216_uncovered.csv --limit 10
```

Программа будет писать по строчке на каждую позицию, примерно так:

```
Вход: top216_uncovered.csv — 216 позиций, уже собрано ранее 0, в этот прогон 10
Результат будет здесь: C:\Users\...\harvester_pack\competitor_dims.csv
  1/10  1032  KX-FAT410A           → CANDIDATE, коробку назвали 2 разных продавца (5 карточек)
  2/10  0280  MLT-D104S            → AMBIGUOUS, 5 карточек, согласия продавцов нет (5 карточек)
  ...
Готово. Результат: C:\Users\...\harvester_pack\competitor_dims.csv
```

Десять позиций занимают примерно **3–5 минут** (программа специально ходит медленно,
по секунде с небольшим между запросами, чтобы маркетплейсы не приняли её за робота-налётчика).

**Так выглядит нормальный тест** (проверено 30.07.2026 с нашего сервера): находятся
карточки по всем десяти позициям, `NOT_FOUND` — ноль или один. Если снова пойдёт
`NOT_FOUND` подряд — это уже не норма, см. следующий шаг.

## Шаг 5-бис. Если что-то не находится — запуск с диагностикой

У программы есть флаг `--debug`. С ним она печатает по первому запросу каждого вида
адрес, ответ сервера (`HTTP 200` — хорошо, `403`/`429` — нас не пускают) и первые
200 символов того, что пришло:

```
python competitor_harvester.py --input top216_uncovered.csv --limit 3 --debug
```

Пример нормального вывода:

```
  [debug] поиск WB — https://u-search.wb.ru/exactmatch/ru/common/v9/search
  [debug] адрес : https://u-search.wb.ru/exactmatch/ru/common/v9/search?appType=1&curr=rub&...
  [debug] статус: HTTP 200
  [debug] ответ : {"metadata":{"catalog_type":"merger",...,"name":"картридж PG-460XL-CL...
```

Что делать: выделить мышью **весь текст из чёрного окна**, скопировать (`Ctrl + C`
после выделения) и прислать. По этим строчкам сразу видно, что именно закрылось —
адрес, блокировка или формат ответа. Ничего секретного там нет: только адреса
публичных страниц и куски ответа маркетплейса.

## Шаг 6. Где результат

Файл **`competitor_dims.csv`** появится **в той же папке**, рядом с программой.
Открывается двойным щелчком в Excel; кодировка и разделитель `;` выставлены так,
чтобы Excel в русской раскладке открыл его правильно, без «кракозябр».

Колонки:

| колонка | смысл |
|---|---|
| `vendorCode` | наш артикул-мать |
| `oem` | код картриджа |
| `source` | у кого нашли — `конкурент-ВБ` или `конкурент-Озон` |
| `competitor_article` | артикул карточки конкурента |
| `url` | прямая ссылка на карточку — можно открыть и глазами проверить |
| `dimensions` | найденный размер, как он написан в карточке |
| `evidence` | дословно те характеристики карточки, из которых он собран |
| `seller_id` | номер продавца на WB |
| `seller_brand` | под каким брендом он торгует |
| `agree` | сколько **разных продавцов** независимо назвали ровно эту же коробку |
| `status` | `CANDIDATE` — коробку назвали минимум двое разных; `AMBIGUOUS` — согласия нет; `NOT_FOUND` — карточек с размерами нет |

Продавец считается по номеру, а не по бренду: один и тот же продавец торгует
под несколькими вывесками (например, номер 1375862 — это и NV Print, и Netproduct,
и CACTUS), и по брендам он сошёл бы за трёх независимых. Две карточки одного
продавца — это одно мнение.

При сравнении порядок сторон не важен: `12×33×12` и `33×12×12` — одна и та же
коробка, программа это понимает. **В файл размер пишется как есть, ничего
не переставляется и не округляется.**

**`CANDIDATE` — это ещё не подтверждено.** Окончательное `CONFIRMED` ставит отдельная
независимая проверка на сервере. Просто пришлите файл обратно.

Строки `AMBIGUOUS` тоже не выбрасывайте — там продавцы разошлись, и разбираться
с ними будем на сервере по ссылкам.

## Шаг 7. Если тест прошёл — полный прогон

По приоритетному списку (216 моделей, ~1,5–2 часа):

```
python competitor_harvester.py --input top216_uncovered.csv
```

По полному списку (1163 позиции, ~8–10 часов, можно оставить на ночь):

```
python competitor_harvester.py --input residual_oem.csv
```

Программу **можно прерывать** сочетанием `Ctrl + C` и запускать снова — она помнит,
что уже собрала (в служебном файле `competitor_dims.csv.done.txt`), и продолжит
с того места, где остановилась. Компьютер при этом не должен уходить в спящий режим.

Если в конце появилась строчка вроде «Отложено из-за молчания поиска WB: 7 шт.» —
это значит, что Wildberries временами нас притормаживал. Такие позиции **не записаны**
и **не помечены пройденными**: просто запустите ту же команду ещё раз, программа
возьмёт только их. Можно повторять, пока отложенных не останется.

## Если что-то пошло не так

**«python не является внутренней или внешней командой»** — Python поставлен без галочки
«Add python.exe to PATH» (шаг 1, пункт 3). Переустановить с галочкой.

**«Нужен модуль requests»** — пропущен шаг 4.

**В окне вместо русских букв кракозябры** — напечатать `chcp 65001`, нажать Enter
и запустить команду снова. На сам файл результата это не влияет, только на вид в окне.

**Все позиции подряд `NOT_FOUND`** — маркетплейс либо не отвечает, либо снова поменял
адрес поиска. Перезапустить с диагностикой (шаг 5-бис) и прислать весь текст из окна:

```
python competitor_harvester.py --input top216_uncovered.csv --limit 3 --debug
```

**«Ozon закрыт своей защитой от роботов — работаем только по Wildberries»** — так
и задумано, это не поломка. Ozon показывает автоматическим программам проверку
«я не робот», и с нашего сервера он закрыт наглухо. С домашнего интернета есть шанс,
что пропустит; если пропустит — в файле появятся строки `конкурент-Озон`, если нет —
программа один раз скажет эту фразу и дальше собирает только Wildberries.
Терять из-за этого нечего: WB даёт основную массу карточек.

**Хочется помедленнее, если интернет слабый** — добавить в конец команды `--pause 2`
(пауза 2 секунды между запросами вместо 1,2).

## Что программа делает с сетью и файлами (проверено построчно)

Читает — только эти публичные адреса, обычными GET-запросами, теми же, что и браузер:

* `u-search.wb.ru` (запасной — `search.wb.ru`) — публичный поиск Wildberries;
* `basket-XX.wbbasket.ru` — публичные данные карточки WB;
* `www.ozon.ru` и `www.ozon.ru/api/...-api.bx` — публичные данные карточки Ozon.

Пишет — **только два файла и только в свою же папку**: `competitor_dims.csv` (результат)
и `competitor_dims.csv.done.txt` (отметки о пройденных позициях, чтобы можно было
продолжить после перерыва).

Не делает: не отправляет ни одного запроса на запись (`POST`/`PUT`/`DELETE`),
не открывает личные кабинеты, не читает файл `.env` и никакие ключи, не ставит
дополнительных программ, ничего не удаляет за пределами своей папки, не отправляет
собранное куда-либо автоматически — файл вы пересылаете сами.

## Что изменилось в версии от 30.07.2026

Почему прошлый тест дал `NOT_FOUND` 10 из 10 — нашлось пять причин, все независимые:

1. **Адрес поиска.** `search.wb.ru` отвечает отказом «слишком часто» (HTTP 429).
   Рабочий адрес — `u-search.wb.ru`, версия `v9`. Теперь программа пробует четыре
   адреса по очереди и запоминает тот, который ответил.
2. **Формат ответа.** В новой версии поиска товары лежат в корне ответа, а программа
   искала их во вложенном разделе `data` — то есть даже на успешный ответ видела ноль
   карточек. Это и была главная причина.
3. **Опознание по «отпечатку».** Wildberries отсекал программу ещё на подключении:
   у Python набор шифров не такой, как у браузера. Набор приведён к браузерному —
   ничего не подменяя, обычный публичный доступ.
4. **Раскладка складов карточек.** WB добавил новые серверы `basket-XX`, старая
   таблица отправляла всё «свежее» на несуществующий адрес. Пересобрана по замерам,
   плюс перебор соседей, если адрес не угадан.
5. **Сборка размера.** Длина, ширина и высота упаковки лежат в карточке тремя
   отдельными строчками; программа брала первую и останавливалась. Теперь собирает
   все три и записывает дословную цитату в колонку `evidence`.

Что появилось нового:

* флаг **`--debug`** — печать адреса, ответа сервера и начала ответа (шаг 5-бис);
* колонки **`seller_id` / `seller_brand` / `agree`** и сверка по продавцам:
  `CANDIDATE` ставится, когда одну и ту же коробку независимо назвали минимум
  два РАЗНЫХ продавца, порядок сторон не важен. Раньше хватало одного расхождения
  из трёх, чтобы вся позиция стала `AMBIGUOUS`, а две карточки одного продавца
  считались за двоих;
* карточек на код смотрится **пять** вместо трёх — иначе двух разных продавцов
  часто просто не набирается;
* **позиции не теряются**: если поиск WB промолчал, позиция откладывается и её
  подхватит следующий запуск, а не записывается как «ничего нет»;
* Ozon: программа распознаёт его проверку «я не робот», один раз сообщает об этом
  и дальше не тратит на него время.

Проверка после правок (наш сервер, 30.07.2026): тест на тех же десяти моделях —
карточки найдены по всем десяти, `NOT_FOUND` ноль. Пример собранной строки:

```
0280;MLT-D104S;конкурент-ВБ;424024224;https://www.wildberries.ru/catalog/424024224/detail.aspx;
33x12x12;"Длина упаковки = 33 см; Ширина упаковки = 12 см; Высота упаковки = 12 см";1375862;NV Print;1;AMBIGUOUS
```

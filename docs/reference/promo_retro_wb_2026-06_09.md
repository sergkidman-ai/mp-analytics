# Ретро-оценка окупаемости акций на Wildberries, 01.06–13.09.2026

Статус: **оценка, а не факт.** Флага участия в акции в истории нет (`prc_mp_price_day`
собирается только с 23.09.2026, `wb_promo_plan_price` — с 19.09.2026). Участие
восстановлено косвенно — по падению **нашей** отпускной цены. Всё, что ниже, читать
как «эффект падения цены ≥10 %», а не как «эффект акции WB».

Только чтение БД. Ничего не менялось, живые API не дёргались.

## 1. Данные и метод

| Что | Как |
|---|---|
| Источник продаж | `raw_wb_report`, `doc_type_name='Продажа'` **и** `supplier_oper_name='Продажа'`, неделя по `rr_dt` (нед. с понедельника) |
| Наша цена | `retail_price_withdisc_rub` — цена продавца **до СПП** (проверено: `retail_amount = rpw × (1 − ppvz_spp_prc/100)`) |
| Цена покупателя | `retail_amount / quantity` — после СПП |
| К перечислению | `ppvz_for_pay / quantity` |
| Себестоимость | `margin_by_sku` (platform='wb', ключ `article` = `nm_id`), `cogs/qty` за месяц; пропуск → медиана по карточке. Покрытие промо-событий — **100 %** |
| Реклама | `wb_ad_nm_daily` (посуточно по nm_id), `wb_ads` (помесячно) |

Панель: полный календарный грид 2806 карточек × 21 неделя (с 20.04 для разгона базы),
недели без продаж = 0 штук. Цена в недели без продаж — протянута вперёд (`ffill`).

- **База цены** — скользящая медиана нашей цены за 4 предыдущие недели.
- **База штук** — скользящее среднее штук за 4 предыдущие недели (нули учтены).
- **Промо-неделя** — наша цена ниже базы на ≥10 % при себестоимости ±5 %.
- **Контроль** — |изменение цены| < 5 %. **Плацебо** — рост цены ≥10 %.

### Почему пришлось усложнить схему «промо vs обычная неделя»

Прямое сравнение даёт мусор, и это важно зафиксировать:

1. Цену мы видим **только там, где была продажа**. Значит «промо-неделя» по построению
   почти всегда неделя с продажей, а «обычная» может быть нулевой. Любая наивная
   разностная оценка ловит это, а не акцию: в сыром виде «лифт» промо-недель = 7,5×,
   но у недель с **ростом** цены он 4,3×, и у контрольных недель с продажей — тоже 4,3×.
   То есть 4,3× — это чистый артефакт отбора, а не эффект цены.
2. Медианный фон по контрольной группе (как в ТЗ) равен **0**: в типичной неделе
   типичная карточка не продаётся вообще. Поэтому фон считается отношением сумм
   (`Σштук / Σбазы` по контролю) — это и есть «общий прирост», но устойчивый к нулям.
3. Карточки, которым режут цену, изначально медленнее (средняя база 0,29 шт/нед против
   0,39 у контроля) — работает регрессия к среднему. Поэтому финальная оценка —
   **матчинг** промо-событий с контрольными по (корзина базовых штук × половина периода).

### Итоговая конструкция (event study)

Событие = неделя с продажей, в которой наша цена упала ≥10 % к базе.
Исход = штуки в **неделю события + 2 следующие недели** (следующие недели уже не
обусловлены фактом продажи, поэтому отбор там не работает).
Контрфакт = средние штуки «плоских» событий из той же страты (база × период),
оценённые по обычной цене карточки (`base_pay − cogs`).

Из-за требования «+2 недели» события обрываются на 24.08 — хвост финотчёта
(данные по `rr_dt` есть до 13.09) в оценку не попадает автоматически.

## 4. Эффект на штуки и эластичность

| Группа | Штук факт | Штук контрфакт | Прирост |
|---|---:|---:|---:|
| Промо (236 событий, окно t…t+2) | 438 | 389,7 | **+12,4 %** |

- **Эластичность: +5,9 % штук на каждые 10 % снижения нашей цены, |e| ≈ 0,59.**
  Спрос жёстко неэластичен: чтобы скидка окупилась при марже ~33 % от перечисления,
  нужно |e| заметно больше 1.
- Разбивка эффекта во времени (матчинг по страте, разница cut − flat):
  неделя события **+0,07 шт** (+5,6 % к 1,21), недели t+1..t+2 **+0,14 шт** (+31 % к 0,44),
  вероятность продажи в t+1..t+2 **+4,6 п.п.** к 26,3 % (+17 % относительно).
  То есть скидка работает не «в моменте», а как небольшой сдвиг вероятности следующей продажи.
- **Плацебо проходит**: у карточек с ростом цены ≥10 % вероятность продажи в t+1..t+2
  на 2,6 п.п. **ниже** плоских — правильный знак и малая величина, артефакта нет.

## 7. Оговорки (обязательные)

1. **Лаг финотчёта ~9–11 дней.** Максимальный `rr_dt` = 13.09.2026 при загруженных
   периодах до 30.09. Недели после 07.09 из панели исключены; события — только до 24.08
   (нужны 2 недели последействия). Проверка «отбросить всё после 24.08» ничего не меняет
   (тождественный результат) — хвост в оценку не попадает по построению.
2. **СПП меняется не нами и могла имитировать промо. Отделено.**
   Средневзвешенная СПП: июнь 28,3 % → июль 28,0 % → **август 17,9 % → сентябрь 18,1 %**.
   То есть в августе цена для покупателя выросла примерно на 10 % без нашего участия.
   Промо детектируется по `retail_price_withdisc_rub` (цена продавца **до** СПП), поэтому
   в классификацию СПП не попадает вообще. Если бы промо определялось по цене покупателя,
   доля «промо-недель» была бы 12,3 % вместо 9,9 % — то есть ~1/5 «акций» оказались бы
   чужим СПП. Остаточный риск: сдвиг СПП влияет на уровень спроса, но он снят недельными
   фиксированными эффектами (фон считается по контролю в ту же неделю).
3. **Реклама мешает, и мешает в одну сторону.** На промо-неделях реклама была у **31 %**
   карточек против **5 %** у плоских недель (средний расход 17,6 ₽/нед против 1,3 ₽).
   Прирост штук на промо частично рекламный, а не ценовой: без рекламы прирост падает с
   +12,4 % до **+2,3 %**. Значит истинный эффект цены **ещё меньше**, а убыток от акций —
   **ещё больше** оценённого. Абсолютные суммы рекламы малы (13–48 тыс ₽/мес на аккаунт,
   ~1–2 % оборота), в Δ ВП они не включены.
4. **Малые выборки.** 236 событий на 206 карточках; в разрезах — по 11–94 события.
   Разрезы «глубина >40 %» (11 событий) и «ТОП-20» (14 событий, 7 карточек) —
   иллюстративные, на них нельзя опираться отдельно.
5. **Что метод не видит.** Цена известна только в недели с продажей. Эффект «акция
   оживила мёртвую карточку» измеряется лишь косвенно (через вероятность продажи в
   t+1..t+2) и может быть недооценён. Возвраты (`doc_type_name='Возврат'`, 40 строк за
   период) не вычитались. Логистика, хранение, штрафы в валовую прибыль не включены —
   считается только (к перечислению − себестоимость).
6. **Что может перевернуть вывод.** (а) Если акции WB системно поднимали карточку в
   выдаче на недели вперёд за пределами окна t+2 — долгий хвост не измерен.
   (б) Если промо-цены сопровождались попаданием в акционные подборки/баннеры, эффект
   которых сидит в рекламной группе — тогда «связка скидка+реклама» окупается (+6,8 тыс ₽),
   а сама по себе скидка — нет. (в) Себестоимость помесячная: при реальном изменении
   закупки внутри месяца фильтр «±5 %» не сработает.

## 8. Что из этого делать

- Акции на WB за 01.06–13.09.2026 **съели около 109 тыс ₽ валовой прибыли**
  (Цифровой Квадрат −63 тыс ₽, Дисквэр −46 тыс ₽), и это скорее нижняя оценка убытка.
- Скидка окупается **только** на ходовых карточках (ТОП-20 по обороту: +12 тыс ₽,
  окупаемость 64 % событий) и при одновременной рекламе.
- Дешёвый терциль (≤ 2 063 ₽) в акции заводить нельзя: прироста штук нет вовсе.
- Углублять скидку сверх 25 % смысла нет: прирост штук на этом упирается в потолок.
- Флаг участия в акции нужно фиксировать в истории (`prc_mp_price_day` пишется с 23.09) —
  через 2–3 месяца этот же расчёт станет прямым измерением, а не реконструкцией.

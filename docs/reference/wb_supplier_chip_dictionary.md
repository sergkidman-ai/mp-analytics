# Чип: распознавание формулировок поставщика

Проверено 05.10.2026. Это справочник явных указаний, а не правило определения чипа по модели или отсутствию текста.

Существующий общий справочник: `prices/features.py`, `CHIP_PATTERNS`, `CHIP_RE`, `chip()`.
Дополнения к поставщицким написаниям: `tools/prc/tc_fields.py`, `EXTRA_NOCHIP`, `name_chip()`.
Подтверждённые исключения: `docs/MS_CARD_FIELDS.md`, раздел «Конфликты ТК ↔ название поставщика».

| Написание | Интерпретация |
|---|---|
| с чипом, with chip | с чипом |
| с многоразовым чипом Longlife | с чипом; Longlife остаётся в исходном свидетельстве, отсутствие счётчика не предполагается |
| без чипа, б/ч, w/o chip, no chip | без чипа |
| необходим / требуется чип, чип отдельно | без чипа в поставляемом картридже: чип нужно установить отдельно |
| чип без счётчика, чип безлимит, unlimited, no count | чип без счётчика |
| W/chip у Blossom | без чипа — документированное исключение именно поставщика Blossom |
| W/chip у остальных | с чипом по общему словарю; исключение Blossom не переносится на остальных |
| нет упоминания, не указан, шаблонное «не требуется чип» | явного свидетельства нет |

Обёртка для этой проверки: `ops/wb_supplier_chip_evidence.py`. Она использует существующий общий словарь, учитывает документированные дополнения и возвращает исходную формулировку. Поля «Название WB» и автоматически заполненные значения из ТК не считаются независимым свидетельством поставщика.

При нескольких разных явных классах для одного внешнего кода сохраняются все свидетельства и отмечается противоречие. Обычный чип и чип без счётчика не объединяются.

Проверка: `./venv/bin/python -m unittest tests.test_wb_supplier_chip_evidence`.
Результаты повторного прохода: `docs/reports/mkt_wb_chip_supplier_dictionary_evidence_2026-10-05.csv`.

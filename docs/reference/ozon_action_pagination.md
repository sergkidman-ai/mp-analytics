# Пагинация состава акций Ozon

`ops.ozon_actions.products` и `ops.ozon_stock_action.participants` возвращают
`ActionProducts`, совместимый с `list`. Дополнительные поля: `complete` и
`diagnostic` (account, action_id, received, reported_totals, pages, last_id,
termination, endpoint). По умолчанию неполная выдача вызывает
`ActionPaginationIncomplete`; полученная часть доступна в `exception.listing`.
Старые потребители сохраняют строгую проверку состава.

`allow_partial=True` разрешает проверять реально полученных участников.
Найденный ID и его цена являются положительным свидетельством; отсутствие ID
при `complete=False` не подтверждает снятия или безопасности товара.

Чтение следует `last_id` до конца выдачи. Совпадение количества с `total` не
останавливает обход раньше времени. Пустая страница с прежним курсором означает
окончание наблюдаемой выдачи. Расхождение количества с `total` или изменение
`total` между страницами дают `complete=False`. Если количества совпадают,
пустой терминатор допустим. Пустая страница с новым курсором не завершает обход.
Повтор непустой страницы, дубли ID, цикл, некорректная цена и превышение
`max_pages` остаются ошибками. `limit`: 1–100, по умолчанию 100;
`max_pages`: 1–10000, по умолчанию 10000.

Сторож акций явно читает наблюдаемую часть и изолирует сбои каждой акции и
кабинета. Остальные товары проверяются прежним правилом 300 ₽ / 10% себестоимости.
Неизвестная часть списка не считается безопасной. При сверке снятия отсутствие
в неполном списке оставляет `sent` с пояснением, а не `confirmed`. Найденный товар
с достаточной фактической ценой может подтвердить подъём и в частичной выдаче.
Лестница и прочие потребители по умолчанию отклоняют неполный состав.

Итог каждого кабинета выводится в stdout и `logs/oz_promo_guard_runs.jsonl`:
`status=ok/partial/failed/error`, количество строк, ошибок, неподтверждённых
операций и диагностика. `--no-log` отключает оба журнала: файл и таблицу решений.
После обработки обоих кабинетов неполнота или ошибки дают exit code 1.
При штатном `--apply` предупреждение входит в существующую сводку;
`--no-tg` запрещает отправку. Получатели, боты и cron не меняются.
Подробные исключения и курсоры остаются в локальном журнале; уведомление
содержит только краткую диагностику и количества.

Проверка без записи на площадку: тесты, сохранённые HTTP-страницы и ограниченные
запросы чтения. `python -m ops.ozon_promo_guard --no-log --no-tg` выполняет расчёт
без `apply`. Само наличие плана не разрешает ручной боевой запуск.

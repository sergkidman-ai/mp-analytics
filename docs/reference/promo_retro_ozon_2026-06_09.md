# Ретро-оценка окупаемости акций на Ozon, 01.06.2026 — 24.09.2026

Дата расчёта: 2026-09-24. Аккаунты: `oz_acc1` («Цифровой Квадрат»), `oz_acc2` («Дисквэр»).
Режим: только чтение, БД и код не менялись, живые API не дёргались.

> **Это оценка, а не факт.** Флаг участия в акции в истории не сохранялся (`prc_mp_price_day`
> пишется только с 23.09.2026). Участие восстановлено КОСВЕННО — по падению цены реализации
> относительно собственной скользящей медианы SKU. Любое падение цены другой природы
> (смена комплектации, ручная уценка, микс-эффект внутри отправления) в такой схеме
> неотличимо от акции.

## 1. Данные и метод

**Источник продаж.** `raw_ozon_transaction`, операции `OperationAgentDeliveredToCustomer`,
дедуп по `(account, operation_id)`, неделя по `operation_date` (недели с понедельника).
`/v3/finance/transaction/list` Ozon отключил 09.09.2026; с 08.09 строки собраны адаптером
из начислений (`payload->>'_source'='accrual'`) — в выборке периода это 831 SKU-неделя
и 1 466 штук, формат идентичен, отдельно не выделялись.

**Единичные метрики.** По условию задачи цена за штуку = `accruals_for_sale / jsonb_array_length(items)`,
комиссия за штуку = `-sale_commission / len(items)`. В смешанных отправлениях (357 из 7 993, 4,5 %)
цена размазывается поровну между разными SKU — это источник шума.

**Себестоимость.** `margin_by_sku` (platform='ozon') даёт `cogs` помесячно на SKU, но `qty` там
NULL для всех 4 076 строк периода. Поштучная себестоимость восстановлена как
`cogs_месяца / штуки_месяца` (штуки — из тех же транзакций, по календарному месяцу
`operation_date`). Для расчёта денег взята **константа по SKU за период** — медиана месячных
поштучных значений (разрешено ТЗ). Месячный ряд использован только для проверки стабильности ±5 %.

**Базовая цена** = скользящая медиана цены за штуку за предыдущие 4 недели, минимум 2 недели
с продажами. **Промо-неделя** = цена ≤ 0,90 × базовой при себестоимости в пределах ±5 %.

**Контроль (diff-in-diff).** Базовые штуки SKU = медиана недельных штук по его же неделям без
падения цены (>2 %). Недельный фон = `exp(median(log(qty / base_qty)))` по всем контрольным
SKU-неделям этой календарной недели (при <10 наблюдений фон = 1,0).
Ожидаемые штуки промо-недели = базовые штуки × фон недели.

**Деньги.** Факт = `(цена − комиссия − себестоимость) × штуки`.
Контрфакт = `(базовая цена × (1 − базовая ставка комиссии) − себестоимость) × ожидаемые штуки`.
Δ = факт − контрфакт.

Скрипты прогона (временные, в проект не клались):
`extract.py`, `extract2.py`, `analyze2.py`, `analyze3.py` в скретчпаде сессии.

## 4. Эластичность

- Агрегатно: 176 фактических штук против 150 ожидаемых → прирост ×1,17 при
  взвешенной скидке 23,1 % → **+7,5 % штук на каждые 10 % скидки**.
- Медиана по промо-неделям: **0,0 %** прироста на 10 % скидки (медианный прирост ровно ×1,00).
- Распределение прироста: >1 — 23 недели, ровно 1 — 20 недель, <1 — 19 недель.
  10-й процентиль ×0,50, 90-й ×2,60.
- **Окупили скидку** (Δ>0): 27,4 % промо-недель, 13 из 47 SKU (27,7 %).

Порог окупаемости при валовой марже ~30–35 % и скидке 20 % требует прироста примерно ×1,8–2,2.
Фактический агрегатный ×1,17 до него не дотягивает почти вдвое.

## 7. Оговорки, которые обязательны при чтении

1. **Сентябрь неполный и данные отстают.** Период обрезан 24.09; последняя полная неделя —
   с 21.09. Часть сентябрьских доставок ещё не начислена, сентябрьский Δ (−8,5 тыс ₽)
   почти наверняка недосчитан.
2. **Дотацию Ozon отделить не удалось.** В `raw_ozon_transaction` за период нет ни одного типа
   операции вида «компенсация скидки / софинансирование» (проверены все 40+ типов).
   `mkt_ozon_buyer_price` — один снимок на 06.08.2026, причём `buyer_price` там модельная
   (`our_price × k`, k = 0,5718 «аккаунт»), а не фактическая цена покупателя.
   `prc_mp_price_day` начинается 23.09.2026, и там `price_buyer = price_sale` во всех 2 110 строках.
   **Вывод: если Ozon софинансировал часть скидок, наша оценка убытка завышена**, и доказать
   обратное имеющимися данными нельзя. Это самая крупная неустранимая дыра расчёта.
   `accruals_for_sale` — то, что начислено нам, поэтому чистой дотации в нём быть не должно;
   но в этом случае «падение цены» отражает нашу собственную уценку, а не акцию Ozon.
3. **Реклама конфаундит.** За период потрачено: CPC 1 153 тыс ₽, «продвижение с оплатой за заказ»
   2 193 тыс ₽, «звёздные товары» 480 тыс ₽, «ускоренные отзывы» 360 тыс ₽.
   SKU-дневная реклама (`mkt_ozon_ads_sku_daily`) есть только с 27.07.2026. В окне август-сентябрь
   27 из 31 промо-недели шли при ненулевом рекламном расходе на этот SKU
   (медиана прироста ×1,00, Δ = −83 735 ₽) против 4 недель без рекламы (×1,42, Δ = −10 290 ₽).
   То есть **почти все обнаруженные «акции» шли одновременно с рекламой**, и разделить вклад
   скидки и ставки на этих данных нельзя. Вдобавок в этот же период менялись ставки
   (см. `mkt_ozon_bid_journal`, политика недельных ±10 %).
4. **Выборка мала и хвостата.** 62 промо-недели на 47 SKU при 2 202 торгующих SKU. 72,6 % недель —
   одна штука; медиана «прироста» механически равна 1,00, потому что и база, и факт равны 1 шт.
   Любой вывод об эластичности держится на 176 штуках.
5. **Недельный фон вышел ровно 1,00 на всех 17 неделях.** Контрольная группа (31–69 SKU-недель
   в неделю) состоит из тех же однопродажных карточек, поэтому медиана лог-отношения — ноль.
   Diff-in-diff формально сделан, но вычет фона фактически ничего не вычел: сезонность
   на таких данных не измеряется. Это ослабляет причинную интерпретацию.
6. **Понятие «акция» на Ozon размыто.** На 24.09.2026 формально в акциях числятся 837 из 1 504
   карточек acc1 (56 %) и 495 из 606 acc2 (82 %), при этом средний `discount_pct` = 0,0.
   Названия: «Эластичный бустинг. Без ограничения срока действия», «Акция для товаров со схемой FBS»,
   «Максимальный бустинг». Это постоянное участие без падения цены. Значит метрика «цена упала
   на 10 %» ловит НЕ участие в акциях, а редкие эпизоды реальной уценки — и наоборот,
   массовое «участие в акции» ценой не проявляется вовсе.
7. **Себестоимость — аллокация, а не факт по партии.** `margin_by_sku.qty` = NULL, поштучная
   себестоимость восстановлена делением. Для наборов это особенно грубо.
8. **Смешанные отправления** (4,5 %) размазывают цену поровну между разными SKU — по букве ТЗ,
   но это добавляет ложные «падения цены».

## 8. Что из этого следует

- В том виде, в каком «акции» существуют на Ozon у обоих аккаунтов, они **не выглядят рычагом**:
  участие почти поголовное и бесплатное по цене, а реальные уценки (то, что нашёл метод)
  в 73 % случаев не окупились.
- Убыток концентрирован: 5 SKU = 89 % потерь, наборы = 80 %, дорогой терциль = 63 %.
  Разбор десятка конкретных карточек даст больше, чем общая политика скидок.
- Главный методический дефицит закрывается только вперёд: с 23.09.2026 `prc_mp_price_day`
  пишет `in_promo`, `promo_names`, `discount_pct`, `price_buyer`. Через 6–8 недель этот же
  расчёт можно будет сделать на фактическом флаге, а не на догадке по цене.
- Для отделения дотации Ozon нужен сбор фактической цены покупателя (не модельной) в историю —
  сейчас такого ряда в БД нет.

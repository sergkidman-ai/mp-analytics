# Карточка товара в МойСклад — правила по каждому полю

Единый свод: что стоит в каждом поле карточки, откуда берётся и чего с ним делать нельзя.
`docs/PRC_RULES.md` описывает ПРОЦЕСС (прайс → оприходование → новинки → карточка), этот файл —
ПОЛЯ. Расходятся — прав этот. Заменил прежний `docs/PRC_TC_FIELDS_RULES.md` (20.08.2026).

## Общее

1. **У каждого значения есть источник.** Прайс поставщика, каталог ТК (`prc_tc_model`, ночной
   слепок), родня по внешнему коду, формула, константа. Источника нет — поле остаётся пустым
   и уходит в отчёт замечаний. Догадок не пишем.
2. **Дозаполняем только ПУСТОЕ.** Что стоит на карточке — не трогаем, если правило не говорит
   обратного явно (Цвет и Чип из ТК — перезаписываем; «Название WB» старого ручного образца —
   заменяем формульным).
3. **Архивные карточки не трогаем** ни по одному полю и не выносим в файлы на проверку.
4. **Запись в МС — только по явной команде Сергея.** Перед правкой — слепок карточки в `backups/`.
5. **Один внешний код = один товар.** Цвет, чип, Code128 у всех карточек одного внешнего кода
   совпадают; наименование, артикул, цена, поставщик — свои у каждой.

## Основные поля

| № | Поле | Источник | Правило |
|---|---|---|---|
| 1 | **Наименование** | прайс поставщика | как в прайсе; при пересоздании карточки переносим со старой |
| 2 | **Описание** | = наименование | при заведении новинки копия наименования |
| 3 | **Группа** | папка **бренда ПРИНТЕРА** | папки поставщиков и «Оригинальные» отбрасываем; струйную новинку Одиссея человек кладёт в струйную папку сам |
| 4 | **Поставщик** | группа юрлиц поставщика | не один контрагент, а группа (`prices/supplier_group.py`); правила выбора юрлица — ниже |
| 5 | **Артикул** | прайс поставщика | только на ОДНУ (главную) карточку позиции — иначе `ambiguous`; существующий артикул НЕ перезаписываем; пустой в МС не отправляем (это отсутствие поля, а не пустая строка) |
| 6 | **Код** | внешний код + аббревиатура поставщика | `3588` + `sk`. **С внешним кодом расходиться не может.** Аббревиатура — `CODE_SUFFIX` без значения по умолчанию: незнакомый префикс останавливает сборку. Код в МС **НЕ уникален** |
| 7 | **Внешний код** | наш реестр / каталог ТК | ровно 4 цифры, ключ связи с ТК. Новый берём ВВЕРХ от последнего занятого (не в дырки), проверяя живым опросом МС. **У живой карточки не правим** — только архив + новая (раздел «Процедуры») |
| 8 | **Вес** | прайс поставщика | нет в прайсе — вес самой свежей карточки того же внешнего кода (дата из id), не частотный |
| 9 | **Единица измерения** | константа | `шт` |
| 10 | **Страна** | константа | `Китай` |
| 11 | **НДС** | константа | 22, `vatEnabled: true`, `useParentVat: false` |
| 12 | **Закупочная цена** | прайс поставщика | в МС уходит в копейках (× 100) |
| 13 | **Штрихкод Code128** | родня по внешнему коду | `DS` + 3 буквы товара + внешний код с нулями (`DSDQM0003588`). Принадлежит ТОВАРУ: один и тот же у всех карточек кода, буквы от поставщика не зависят. **Сами не генерируем** — копируем у карточки с тем же внешним кодом; у НОВОГО внешнего кода Code128 не ставим вовсе. Проверено на 44 828 живых карточках: правило держится в 37 817 случаях, расходится в 16 |
| 14 | **ean8 / ean13** | МС | не трогаем и не ждём — генерируется сам; при пересоздании переносим со старой карточки |
| 15 | **Архив** | — | см. «Процедуры» |

**Юрлицо поставщика** (у кого их несколько):
- **Одиссей** — на `ООО "ОДИССЕЙ" WB` идут бренд White Box и **вся струйка любого бренда**
  (признак — категория МС `Картриджи/…/струйные <бренд>`); остальное на `ООО "ОДИССЕЙ"`.
- **КВК ТРЕЙД** — на `… OEM` идут товары OEM (артикул `OEM …`, код `…oem`) и вся струйка.
- **ТОНЕРОПТТОРГ** — признак СТРОГО один: слово «T2» в наименовании (`[TТ]2` отдельным словом,
  буква бывает кириллической); есть — `… T2`, нет — `ТОНЕРОПТТОРГ (Изипринт)`.
- **Солюшнс принт** — юрлицо = ГОРОД ПРАЙСА (`s_print_msk` → «… МСК»), а не признак товара;
  один товар законно живёт двумя карточками, у московской артикул с хвостом `_MSK`.

## Доп. поля (атрибуты)

| № | Поле | Источник | Правило |
|---|---|---|---|
| 16 | **Модель** | ТК `title` | как есть |
| 17 | **Доп. название модели** | ТК `additional_title` | OEM-код как есть |
| 18 | **Цвет** | ТК | русские слова **строчными**; наборы как есть; существующее значение **перезаписываем** |
| 19 | **Чип** | ТК | формулировки затираем; в ТК пусто → пишем **«не указан»** |
| 20 | **Ресурс (поставщика)** | название товара **поставщика** | числом; в названии нет — оставляем пусто. Расхождение с ресурсом ТК — норма (у поставщика бывает своя цифра и опечатки) |
| 21 | **Название WB** | **формула** `tools/prc/wb_fill.py → compose()` | **не переносим, не копируем у родни, руками не пишем.** Собирается из каталога ТК по НАШЕМУ внешнему коду; формула ниже. Ручные значения старого образца заменяем формульным; формула молчит — поле пустое с замечанием |
| 22 | **Код поставщика** | = артикул поставщика | ставится при заведении |
| 23 | **Гарантия/ Срок службы** | константа | 365 |
| 24 | **Связь** | человек | номера товаров четырьмя цифрами с ведущими нулями, разделитель `;`, без пробелов; каждый код проверяется по каталогу; архивные в сверке не участвуют |
| 25 | **Бренд, Длина/Ширина/Высота см.** | поток `gab` | **не наша территория.** Габариты только реальные — замер поставщика или наследование родитель→ребёнок; синтетику (медианы, коэффициенты) не пишем никогда |
| 26 | **Стоп лист, Ссылка, Изображение** | карточка | при пересоздании переносим со старой как есть |
| 27 | **Ячейка СПБ / МСК / Дубровка** | склад | при пересоздании **сверять с соседями по внешнему коду**: у карточки, стоявшей на чужом коде, ячейка бывает от чужого товара (у 2651sf было `XEROX-03`, у остальных карточек кода 2651 — `RICOH`). Чужую снимаем через `value: null` — простой PUT без поля атрибут НЕ убирает |

**Формула «Названия WB»** (согласована 16.08.2026, реализация — шапка `tools/prc/wb_fill.py`):

    тип + модель + «для» + бренд принтера + доп. название + цвет + чип + «XL ресурс»

- тип — `consumable_type` дословно, «Комплект …» → «Набор …»;
- модель — `title` без значка «№»;
- бренд — преобладающий в `printer_models`; Konica Minolta → Konica, F+ Imaging → F+,
  Fuji Xerox → Xerox. Бренд уже внутри модели — «для …» не добавляем;
- доп. название — `additional_title`; не пишем, если это перечень (запятая внутри) или если
  без него не влезаем в 60 символов этикетки;
- цвет — `ink_colors` строчными через «/»; **у наборов цвет не пишем**;
- чип — «с чипом» / «с чипом без счётчика» / «без чипа»; в ТК пусто — в названии ничего;
- «XL ресурс» — при `capacity = Увеличенная`, ровно в конце.

## Конфликты ТК ↔ название поставщика

Заполняем поле только при согласии источников. Расхождение → поле НЕ пишем, карточка идёт
в файл на проверку (XLSX в бот PRC), после разбора заполняем.

- **Цвет.** Проверенные человеком расхождения — в белом списке `docs/prc_color_approved.csv`
  (по коду карточки), они конфликтом больше не считаются.
- **Чип**, три вида холда: *в ТК нет данных, а поставщик чип в названии указал* — «не указан»
  не пишем; *противоречие* — «с чипом» vs «без чипа» и «с чипом» vs «с чипом без счётчика»;
  *написание поставщика* — Blossom `W/chip` = **без** чипа, «чип безлимит» = чип без счётчика,
  «б/ч» = без чипа. Чип обычный и чип без счётчика — РАЗНЫЕ товары и разные внешние коды.
- **Ресурс.** «N к.» = N копий, множитель ×1000 не применяем: у фотобарабанов поставщики пишут
  полное число («300000 к.»), проверено — 1253 совпадения один-в-один с ТК и ноль случаев
  «ТК = N×1000». Для справки: ресурс фотобарабанов в ТК есть, медиана 40 000, максимум 600 000.
- **Внешнего кода нет в каталоге ТК** → карточку не трогаем вообще, ни по одному полю.

## Обязательные 11 полей

При СОЗДАНИИ и при ПРАВКЕ карточка не готова без: 1) Наименование, 2) Описание, 3) Группа,
4) Поставщик, 5) Артикул, 6) Код, 7) Внешний код, 8) Вес, 9) Ед. измерения, 10) Название WB,
11) Штрихкод Code128. У сведённых сирот набор закрывает кнопка «Свести»: `prices/unlink_apply`
даёт 6, 7, 10; `tools/prc/unlink_fill` — 2, 3, 4, 8, 9, 11; 1 и 5 приходят из оприходования.

## Процедуры

### Убрать карточку в архив

1. **Только при нулевом остатке на НАШИХ складах** (Звездный, Дисквер и прочие свои).
   «Удаленный склад» — виртуальный остаток поставщика, «Транзит» — товар в пути: не наши штуки.
   Есть остаток — карточку не трогаем, она идёт отдельной строкой отчёта.
2. Слепок карточки в `backups/` — ДО первой правки.
3. Снимаем **артикул, код, внешний код и штрихкоды** (они уникальны и нужны новой карточке;
   вместо внешнего кода МС подставит свой случайный) и ставим `archived: true`.
4. **Архив без замены** — когда правильной модели в ТК нет вовсе. Новую не создаём: товар
   вернётся «новинкой» при следующем оприходовании, там его и привяжут.

### Создать новую карточку

1. Со старой переносим: `name`, `description`, `article`, `vat`, `uom`, `country`, `supplier`,
   `productFolder`, `weight`, `volume`, `buyPrice`, `minPrice`, `salePrices`, `trackingType`,
   `paymentItemType`.
2. `externalCode` = правильный код ТК; `code` = внешний код + аббревиатура поставщика;
   `barcodes` = ean старой + Code128 товара (поле 13).
3. Поля 16–20 — из ТК по правилам таблицы, уже от НОВОЙ карточки ТК.
4. **«Название WB» собираем формулой заново** (поле 21) — у старой карточки оно от прежнего,
   неверного кода. 20.08.2026 перенос вместо формулы дал 19 карточек с чужими названиями
   («Картридж 040M … пурпурный» на жёлтой карточке), всё переписано формулой.
5. **Все остальные доп. поля переносим целиком** (22–27): новая карточка — тот же товар,
   терять Код поставщика, Гарантию, Бренд, габариты, Стоп лист, Ссылку, Изображение нельзя.
6. **Порядок шагов обязателен:** слепок → освободить уникальные поля у старой и убрать её в архив
   → создать новую. Иначе МС ответит «уже занято». Если создание упало — старая карточка
   возвращается из архива со всеми полями.

### Перевести карточку на верный внешний код

Только через архив старой + создание новой (`tools/prc/recard.py`). Внешний код — ключ, по
которому карточка связана с ТК, площадками, оприходованиями и продажами; правка задним числом
переписывает, чем карточка была (решение Сергея 20.08.2026).

**Парный обмен кодов** (6358↔6359, 1266↔1267, 5061↔5062): вторая карточка пары остаётся без
источника Code128 — единственным носителем была первая, которую мы сами обезличили. Штрихкод
берём из слепка, сделанного до правки; выдумывать нельзя.

## Где реализовано

- `tools/prc/tc_fields.py` — заливка полей 16–20 из ТК, холды по конфликтам.
- `tools/prc/recard.py` — перевод на верный внешний код, режим `--retire` (архив без замены).
- `tools/prc/wb_fill.py` — формула «Названия WB» (`compose`).
- `prices/ms_import.py` — заведение новинки (константы, `CODE_SUFFIX`, `supplier_of`, `ATTRS`).
- `tools/prc/unlink_fill.py`, `prices/unlink_apply.py` — дозаполнение сведённых сирот.

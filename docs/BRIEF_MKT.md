### Контракт API рекламы ВБ (выяснено 25.08, действует)
- `POST /adv/v2/seacat/save-ad` **СОЗДАЁТ кампанию**, а не правит состав.
- Правка состава — `PATCH /adv/v0/auction/nms`, тело с двойной вложенностью:
  `{"nms":[{"advert_id":N,"nms":{"add":[…],"delete":[…]}}]}`. Плоские варианты дают
  «can not deserialize response body». Статусы кампании 4/9/11. Добавленной карточке ВБ ставит
  текущую **минимальную** ставку кампании, не нашу. Ответы идут из общего кэша ВБ
  (`origin: camp-api-public-cache`) и могут прийти про ЧУЖУЮ кампанию — сверять advert_id.
- **`delete` СУЩЕСТВУЕТ** — рычаг для правила ⚫ (вывод) Роя, сейчас не подключён.
- **Лимит 50 номенклатур.** Старые кампании acc2 стоят по **~194–200** (пережили ужесточение),
  добавить в них нельзя ничего. На acc1 место есть. Прямого геттера состава нет (404).
- **Категория:** карточку чужого предмета кампания не примет (у нас практически везде 1820).
- Сигнал «сумрака» с 25.08 работает на обоих аккаунтах (`ops/tc_price_alert.py`, крон `20 6,13`).

## Рекламная стратегия (что поднимаем, что опускаем)
Крон `12 8 * * 1` (пн 11:12 МСК) → `ops/wb_roy_weekly.sh`, оба аккаунта, автор `roy`.
Правила Роя: 🟢 +10 % · 🔴 −10 % · 🟤 в пол · ⚫ вывод в пол · 🟡 не трогаем.
Константы: пол 7.30 ₽, потолок 25 ₽, шаг +10 %, срез 0.90. Зелёным считается только позиция,
у которой ДРР профиля ниже СВОЕГО потолка (**маржа − 25 %**) — то есть ставку поднимает не
«хороший ДРР», а ДРР, оставляющий 25 % маржи после рекламы. Карточка с маржой 30 % имеет
потолок ДРР 5 %, с маржой 60 % — 35 %: чем прибыльнее, тем агрессивнее её разгоняем.
Карантин посева `SEED_GRACE_DAYS = 14` — свежие `author='seed'` Рой не трогает две недели.
Сторож остатка (`ops/wb_stock_guard.py`, автор `stock-guard`) — симметрично: нет живого
`totalQuantity` → в пол, вернулся → ТА ЖЕ ставка из `old_cpc`. На крон не поставлен.
Авторы в `wb_bid_log`: `ladder`, `lower`, `roy`, `roy-rollback`, `seed`, `stock-guard`.
**Разница аккаунтов не в правилах, а в материале:** acc1 — 1 799 SKU со ставкой, из них 998 на
полу, кампании с местом; acc2 — 380 SKU, 96 на полу, все 71 кампания забита под старый лимит,
завести новое нельзя. Поэтому acc1 масштабируется вширь, acc2 упёрся в потолок площадки.
**Дыра:** правила по марже нет. Убыточная карточка зелёной не станет, но и вывести её ничто
не заставляет — нужен рычаг «маржа < 0 → пол + `delete`».

- **`wb_price.market_price` — НЕ цена рынка**, а наша цена после СПП (docstring
  `collectors/wb_market_price.py`). Рынок только из SERP-снимков `tools/core_<ГГГГММДД>_detail.csv`

- **`wb_stocks` — FBO-only**, не признак доступности: карточка продаётся с ФБС при нулевом FBO.
  Молчание card.wb.ru тоже нельзя читать как «остатка нет» — неответившие батчи пропускаем.
- Рабочие ФБС-склады в `supplier_stock`: `Удаленный склад`, `Звездный`, `Дисквер`.
  Мост карточка ↔ МойСклад: первые 4 цифры `vendor_code` → `ms_product.external_code`.
- **`wb_funnel.period` — начало МЕСЯЦА, не недели**; сентябрь неполный, месяцы в лоб не сравнивать.
  Недельные ряды сравнивать только одинаковыми днями недели (пн–чт к пн–чт).
- Коррелированные подзапросы к `supplier_stock` по карточке вешают прогон на 15 минут —
  агрегировать одним проходом (CTE по `ms_id`).

## Параллельная работа (worktree-изоляция)
Общий чекаут всегда на `main`, ветку здесь не переключать. Работа в ветке — только в своём worktree:
```bash
git worktree add .claude/worktrees/mkt-<задача> -b mkt/<задача> origin/main
cd .claude/worktrees/mkt-<задача> && echo mkt > .workstream
```

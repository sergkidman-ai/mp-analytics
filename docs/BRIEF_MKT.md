### API рекламы ВБ — что выяснено 25.08 (две прежние записи брифа были НЕВЕРНЫ)
- `POST /adv/v2/seacat/save-ad` **СОЗДАЁТ кампанию**, а не правит состав.
- Правка состава — `PATCH /adv/v0/auction/nms`, тело с двойной вложенностью:
  `{"nms":[{"advert_id":N,"nms":{"add":[…],"delete":[…]}}]}`. Плоские варианты дают
  «can not deserialize response body». Работает для статусов кампании 4/9/11.
  Добавленной карточке ВБ ставит текущую **минимальную** ставку кампании, не нашу.
- **`delete` СУЩЕСТВУЕТ** — запись «метода удалить номенклатуру в API ВБ нет» неверна.
  Это рычаг для правила ⚫ (вывод) Роя: сейчас оно только роняет ставку в пол, а карточка
  продолжает висеть в кампании.
- **Лимит 50 номенклатур**, и это главное ограничение: **старые кампании acc2 стоят по ~200**
  (35498721 = 200, 35498747 = 200, 35498703 = 200, 35499306 = 194, 35498781 = 200, 35499257 = 198).
  Они пережили ужесточение лимита, но добавить в них **нельзя ничего**: 200+N > 50.
  На **acc1 место есть**: 36879647 = 26 (свободно 24), 36880441 = 44 (свободно 6),
  36874215 = 91, 36878836 = 81.
- **Категория:** «new nomenclatures should belong to the same category already existing in the
  campaign» — кандидатов резать по предмету кампании (у нас практически везде 1820).
- **Прямого геттера состава нет** (все `/adv/v1|v2|v3/promotion/adverts` → 404), но есть **оракул**
  `real_count()`: сверхлимитный запрос всегда отклоняется, а в отказе ВБ пишет итоговое число →
  текущий состав = число − отправленное. По факту это чтение. Флаг `--count`.
- **Ответы контура идут из общего кэша ВБ** (`origin: camp-api-public-cache`) и приходили про
  ЧУЖУЮ кампанию 33614302, которой у нас нет. `real_count()` сверяет advert_id в отказе со своим
  и молчит, если он чужой. После любой записи состав проверять отдельно.
- Разведка: `POST /adv/v2/supplier/nms` тело `[subjectId]` → 200 (acc2 14 441, acc1 14 633
  карточки с полем `subjectId`), `GET /adv/v1/supplier/subjects` → 200.

## Грабли, за которые уже заплатили
- **`wb_price.market_price` — НЕ цена рынка**, а наша собственная цена после СПП
  (см. docstring `collectors/wb_market_price.py`). Реальный рынок только из SERP-снимков
  `tools/core_<ГГГГММДД>_detail.csv` (крон `40 22 * * *`).
- **`wb_stocks` — FBO-only** и не является признаком доступности: карточка может продаваться
  с ФБС при нулевом FBO. Правда о наличии — `totalQuantity` с публичного card.wb.ru.
- Рабочие ФБС-склады в `supplier_stock`: `Удаленный склад`, `Звездный`, `Дисквер`.
- Мост карточка ↔ МойСклад: первые 4 цифры `vendor_code` → `ms_product.external_code`.
- Молчание card.wb.ru нельзя читать как «остатка нет» — иначе сторож уронит ставки в пол
  на ровном месте. Неответившие батчи пропускаем.
- Коррелированные подзапросы к `supplier_stock` по каждой карточке вешают прогон на 15 минут —
  агрегировать одним проходом (CTE по `ms_id`), а не подзапросом на строку.
- Недельные ряды сравнивать только одинаковыми днями недели (пн–чт к пн–чт).

## Параллельная работа (worktree-изоляция)
Общий чекаут всегда на `main`, ветку здесь не переключать. Работа в ветке — только в своём worktree:
```bash
git worktree add .claude/worktrees/mkt-<задача> -b mkt/<задача> origin/main
cd .claude/worktrees/mkt-<задача> && echo mkt > .workstream
```

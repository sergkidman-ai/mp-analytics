## Себест: два источника и ничего больше (решение Сергея 07.08.2026)

отработает сама. **Алерт «вышла из сумрака»** — `ops/tc_price_alert.py` + миграция

## Джем: даёт ли он SEO-базу (разбор 07.08.2026, решать после 20.08)

Вопрос Сергея: «какие ключи конвертят, а какие нет — возможность оптимизации карточек под
работающие ключи, или это пустая трудоёмкая задача?» Проверено по `wb_search_text`.

**Поля для этого есть.** По каждой паре «запрос × товар»: `frequency`, `week_frequency`,
`median_position` / `avg_position`, `open_card`, `add_to_cart`, `orders`, `open_to_cart`,
`cart_to_order`, `visibility` + `_dyn` (динамика к прошлому окну).

**Но по конверсии ключа решать НЕЛЬЗЯ — не хватает объёма, и это не лечится сбором.**
Окно 2026-07-31: 274 строки «запрос × товар» → 175 дали хоть один переход, 36 корзину,
**13 заказ**. Итого частотность 997, переходов 320, заказов 13. У каждого «топ-конвертящего»
запроса ровно 1 заказ: CR 100 % с одного перехода, 50 % с двух. У нас ~86 заказов в неделю на
весь аккаунт, размазанных по тысячам запросов, — сколько ни расширяй сбор, на запрос придётся
1–2 заказа. Это та же ловушка тонкой выборки, от которой мы отгородились порогом
`MIN_QTY_FACT = 5` в юнит-экономике.

**Что из Джема РАБОТАЕТ для SEO — метрика «частотность × наша позиция»**, статистика тут не нужна:
запрос ищут N раз в неделю, мы по нему на 40-й позиции или нас нет вовсе → это чинится текстом
карточки и проверяется той же таблицей через неделю. Второй рабочий слой — **«трафик есть,
заказов нет»**: за неделю 10 запросов, 83 перехода впустую; обычно нерелевантность (находят по
модели, которой мы не подходим) → ключ из карточки вычистить, чтобы не жечь показы.

**Главное ограничение — наше собственное.** `collectors/wb_jam.py::_target_nmids` тянет запросы
только по «проблемным»: `open_card >= MIN_OPEN AND (avg_position_dyn>0 OR orders_dyn<0 OR
visibility_dyn<0) ORDER BY open_card DESC LIMIT 120`. За всю историю это **225 nm_id из 9841** —
SEO-базы у нас фактически нет, есть её кусочек. Расширение сбора тарифом уже оплачено, но прежде
чем начинать — померить, сколько это запросов к API и времени.

**Вердикт:** не пустая трудоёмкость, но работать надо по частотности и позиции, а не по
конверсии ключей. Возврат к вопросу после 20.08 вместе с решением по тарифу. Цифры разбора —
`reports/data/jam_seo_check.txt`.

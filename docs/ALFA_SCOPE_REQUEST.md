# Запрос в Альфа-Банк: расширение скоупов API (черновики платежей + остатки)

**Кому:** `alfa_api@alfabank.ru` · **Поток:** inv · **Составлено:** 2026-07-27
**Статус:** готово к отправке (отправляет Сергей). Ответ банка → сюда же и в `docs/HANDOFF.md`.

## Зачем

Наша сторона интеграции готова полностью: черновики платёжек формируются автоматически из графика
оплаты поставщикам, остаётся только подписать их человеком в Альфа-Бизнес. Упираемся ровно в права
доступа ключа — **ни один из двух нужных методов не открыт ни в проме, ни в песочнице**, хотя в
выданном нам описании доступа scope эти права содержит.

## Проверено 2026-07-27 (оба контура, один и тот же ключ-схема `ApiKey` + mTLS)

| Метод | Назначение | Prod (`baas.alfabank.ru`) | Sandbox (`sandbox.alfabank.ru`) |
|---|---|---|---|
| `GET /api/jp/v1/statement/transactions` | выписка (используем ежедневно) | **200 OK** | **200 OK** |
| `GET /api/pp/v1/accounts` | остаток на р/с | **403 `insufficient_scope`** | **403 `insufficient_scope`** |
| `POST /api/jp/v2/payments` | создание НЕПОДПИСАННОГО черновика платёжки | **403 `insufficient_scope`** | **403 `insufficient_scope`** |

Тело ответа в обоих случаях:
`{"error":"insufficient_scope","error_description":"The request requires higher privileges than provided by the access token"}`

Важно: в песочнице поведение идентичное прому, поэтому **отладить сценарий на тестовом контуре
тоже нельзя** — это не вопрос перехода в бой, а вопрос прав ключа.

## Что просим открыть

Для организации **ООО «ЦИФРОВОЙ КВАДРАТ»**, ИНН `7807355364`, р/с `40702810432000015093`
(Дисквэр в интеграцию не входит — его счёт в другом банке):

1. **`signature`** — метод `POST /api/jp/v2/payments`.
   Подчёркиваем: платёжки создаём **БЕЗ `digestSignatures`**, то есть как черновик на подпись.
   Автоматической подписи и автоматического списания в контуре нет и не планируется — подписывает
   человек в веб-интерфейсе Альфа-Бизнес. Сопутствующие методы того же блока, которые нужны для
   контроля состояния: `GET /api/jp/v2/payments/{externalId}` и `.../state`.
2. **`customer profile inn role eio`** — метод `GET /api/pp/v1/accounts` (только чтение остатка).
   Нужен, чтобы не формировать платёж на сумму больше фактического остатка на счёте.

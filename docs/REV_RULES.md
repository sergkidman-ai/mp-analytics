# Правила потока rev (действующие)

## Исправления источников — 12.11.2026

- Факты Маркета — точный offerId и кабинет из собственной карточки, без WB-префиксов.
- Ozon — точный SKU и его кабинет, без подмены вариантом по началу артикула.
- «Чип не требуется», «с чипом», «без чипа», установленный чип, контроль уровня и настройки
  — разные утверждения. Не достраивать одно из другого; шаблоны подчиняются тому же правилу.
- Цвет одного поля не доказывает состав комплекта. Противоречие требует проверки источника.
- Вопрос не форсируется на модерацию только из-за типа question. Автоматическая отправка
  возможна по существующим узким правилам после новой проверки фактов и PASS контролёра.
- Смена фактов отменяет прежний машинный вердикт. Ручные решения и правки сохраняются.
- Данные выбора поставщика используются внутри системы; в LLM не отправлять закупочные
  цены, остатки, поставщиков и внутренние имена. Лучший поставщик сегодня не является
  доказательством производителя/чипа конкретной уже проданной партии.


## Контроль провайдеров — 11.11.2026

- Фактические ошибки создания/чтения Batch, ошибки внутри результатов Batch и DeepSeek Search
  сохраняют безопасную причину и отдельный алерт в rev_provider_alert. Только прежний личный чат
  Rev: HTTP 400 spend/workspace limit отдельно от недостатка денег (402/credit balance),
  отказов ключа, временного rate limit и сетевого сбоя. Секреты/сырые ошибки не сохраняются.
- Красный алерт для денег/лимита/авторизации — при первом отказе. Временный сбой — жёлтый,
  второй подряд — красный без совета пополнить баланс. Повтор одной проблемы не чаще 6 часов;
  при подтверждённом восстановлении — один зелёный. Состояние и Telegram message ID в БД.
- Независимый feedback-rev-health.timer каждые 5 минут проверяет бесплатный API баланса
  DeepSeek и доставляет недоставленные алерты. Предупреждение ниже $1, усиленное ниже $0.25;
  положительный малый остаток сам по себе обработку не блокирует. Нет API баланса посредника —
  не выдумывать остаток. Доступный ключ Anthropic не используется как источник суммы баланса:
  контролируются реальные рабочие запросы, без дополнительных платных проб.
- После отказа реальные ожидающие задания проверяют восстановление каждые 5 минут в пределах
  общего бюджета, без пустых платных запросов. Сбор, автошаблоны и уже сохранённые данные
  продолжают работать. Неопределённые отправки и резервы не повторяются вслепую.

## Простые текущие отзывы — решение Сергея 11.11.2026

- Текущие отзывы WB и Маркета на 5★ без признаков проблемы/вопроса отвечаются автоматически:
  «Здравствуйте! Спасибо за отзыв и оценку.» Отзывы на 1★ — согласованным негативным текстом
  из раздела архива ниже, без технических утверждений, обещаний возврата/замены и вызовов LLM.
  Для этих 1★ более старое правило модерации негатива по рейтингу карточки не применяется.
- Проверка этого пути детерминированная: актуальный рейтинг/содержание + точное совпадение
  с утверждённым текстом. Это не PASS Anthropic. Изменённый текст и другие классы исключены.
- Простые шаблоны не направляются в Telegram на выборочную модерацию и не ждут Batch.
  Решения, ручные правки, открытые сессии редактирования и пропуски сохраняются под общим
  замком карточки. Сверка площадки и журнал публикаций остаются обязательными.
- Anthropic HTTP 400/401/403/404/413/422/429: отклонённый Batch не расходует резерв,
  неопределённый сетевой исход сохраняет резерв до сверки. Лимит workspace виден в сводке;
  между проверками используется пауза, локальный дневной предел $2 не увеличивается.
- Сводка — раз в сутки и при смене блокировки, с отдельным числом готовых черновиков.

Вынесено из `docs/BRIEF_REV.md` 08.09.2026, чтобы бриф держался в 150 строк. Читать при любой
правке движка ответов: здесь запреты, нарушение которых стоит денег или репутации.

1. **Что уходит во внешние LLM (13.08.2026).** Разрешено: только УЖЕ ОПУБЛИКОВАННОЕ на витринах
   площадок (название, артикул площадки, характеристики, описание, совместимость, наши листинги),
   текст обращения покупателя и наши прошлые опубликованные ответы. Запрещено на уровне СБОРКИ
   промпта: любые финансовые и закупочные данные МойСклада — закупочные цены, себестоимость,
   поставщики, маржа, наценка, остатки, обороты. Держится кодом: `reports/prompt_privacy.py` —
   `assert_public_facts()` роняет сборку на закрытом ключе, `scrub_finance()` вырезает закупочную
   фактуру из НАШИХ блоков (текст покупателя не трогаем). `reports/feedback_grounding.py`
   (единственный, кто читает `raw_moysklad_product`) в живом цикле не используется — не подключать
   без пересмотра правила.
2. **Внутренние складские пометки — только оператору.** Внутреннее имя МС («\*ВНИМАНИЕ\*»,
   «White Box», «DS», «уценка») режется `public_name()` во всех точках выхода; в карточке
   модерации имя и внутренний артикул показываются ПОЛНОСТЬЮ — по ним владелец узнаёт товар.
   Повод — инцидент OKI C822 (12.08): внутреннее предупреждение ушло покупателю.
3. **Достоверность фактов карточки (13.08.2026, инцидент 6806).** Омоглифы приводит
   `core/text_norm.fix_homoglyphs()`; двойник Ozon ищется строго по коду оффера (`_oz_twin()`),
   нет точного двойника — факт остаётся неизвестным и в ответ НЕ идёт; имя товара Яндекса берётся
   с витрины Маркета, не из МС.
4. **Контроль отправки и балансы (17.08.2026).** Движок обязан САМ сообщать, что ответы не уходят
   и почему; баланс DeepSeek и Anthropic проверяется каждый цикл (`feedback_bot/health.py`:
   предполёт, постфактум, `OnFailure=` на падение цикла). Когда беда уходит — обязательно шлётся
   🟢: молчание не должно быть неотличимо от поломки. Пополнение решает Сергей в потоке `infra`.
5. **Цвет алерта по классу причины (18.08.2026).** `BILLING` / `AUTH` / `CONFIG` → 🔴 с конкретным
   действием; `TRANSIENT` (529, 429, 5xx, таймаут) → 🟡 «Провайдер моргнул»; второй такой цикл
   подряд → 🔴, но БЕЗ «пополнить». **Запрет: не подклеивать «Пополнить баланс» к причине, которая
   не про баланс** — ложный призыв убивает доверие к настоящему 🔴.
6. **Пустые отзывы отвечаются шаблоном, а не висят.** Пустая 4★ → `route='auto'` (`63faf7f`),
   пустые ≤3★ → хендофф по QR (`1909e0b`), пустые Ozon-отзывы площадка не принимает вообще →
   `skipped_no_text`.
7. **Модерация негатива по рейтингу карточки (24.08.2026).** `reports/card_rating.py`
   (`DEAD=4.0`, `MIN_N=5`): карточка жива → негатив с текстом идёт человеку; карточка под убой →
   `route='auto'` и сухой `DEAD_TEXT` (хендофф в чат по QR). Рейтинга площадки нет и своих отзывов
   <5 → вердикт не выносим, отдаём человеку. Источники рейтинга: WB — `wb_search_report`,
   Ozon — `ozon_rating` (замер 17.07, умер вместе с review API), иначе среднее по своим отзывам.
8. **Автотекст в чатах площадок не делаем** (решение 24.08.2026): объём 2–5 диалогов в месяц,
   цена ошибки — возврат/деньги/претензия. Только видимость: коллектор `kind='chat'`, сторож SLA
   «клиент написал — мы молчим», карточка с черновиком, публикация кнопкой. Чат Ozon `v3` жив на
   ОБОИХ аккаунтах (от Premium Plus не зависит), Яндекс жив, WB закрыт скоупом токена.
9. **Первым покупателю не пишем.** `/v1/chat/start` у Ozon доступен на обоих аккаунтах (проверено
   24.08 безопасной пробой, ничего не отправлено) — применение только по прямой команде Сергея.

## Восстановленный контур и память — проверено 04.11.2026

- Класс обращения определяется по body/pros/cons и рейтингу; жалоба не становится позитивом из-за 5★. Короткие простые оценки обрабатываются шаблонами; технические вопросы и содержательные отзывы — существующим движком.
- Для вопроса собирается публичная карточка площадки, список совместимости, варианты/состав товара и подходящие наши листинги каталога. До генерации проверяется approved_answers: артикул/код семейства + класс + ключ вопроса, актуальность и сигнатура карточки. Семейный, устаревший и первые повторные ответы требуют подтверждения.
- Генератор получает до пяти похожих опубликованных ответов из корпуса, до пяти утверждённых ответов того же класса/бренда и применимые brand_notes по серии/теме. История — пример, а не перенос всех её фактов на иной товар. Отдельный точный кэш approved_answers поддерживает вопросы; опубликованные ручные ответы на отзывы участвуют через корпус.
- При недостатке фактов используется DeepSeek Search. Поисковая выдача сама по себе не подтверждает свойства нашего лота: область применимости проверяется отдельно; оригинальная жидкость/чип не доказывают свойства совместимого товара. Приоритет: карточка нашего товара → применимые экспертные знания → утверждённые ответы → внешние источники.
- Формулировка и отдельный контроль — Anthropic Sonnet 4.6 через Batch. Контролёр проверяет факты и полноту ответа, дополнительные guard-проверки — обещания, претензии, технические пробелы и маршрутизацию. PASS контролёра не отменяет остальные ограничения publish_gate. При обрезанном ответе контролёра допустим один отдельный бюджетированный повтор; предметный FIX повтором не обходится.
- Ручная правка сохраняется до публикации и не заменяется генератором. После подтверждённой отправки поддерживаемый вопрос пополняет approved_answers, применимое утвердительное подтверждение — compat_ref. Несохранённый/неопубликованный черновик не считается подтверждённым знанием.
- Исторический разбор не снимает skipped_old, не публикует и не рассылает сотни карточек. Он возобновляется порциями штатного короткого цикла и подчиняется общему бюджету. Новые обращения имеют приоритет.

## Архив Маркета — прямое решение Сергея 04.11.2026

- Только исходная когорта 776 исторических отзывов ya_acc1: автоматические фиксированные ответы на позитив и негатив, без отправки карточек для модерации. Существующие карточки обновляются на статус результата. Правила текущих отзывов/вопросов и других площадок этим решением не меняются.
- Негативный текст одобрен дословно: «Здравствуйте! Сожалеем, что покупка Вас разочаровала. Если вопрос ещё актуален, напишите нам в чат по QR-коду на упаковке или в товарном чеке.» Позитивный ответ: «Здравствуйте! Спасибо за отзыв и оценку.»
- Только эти тексты допускаются автоматическим обработчиком архива. Существующие ручные правки/пропуски сохраняются. Перед POST обязательна сверка ответа площадки; после — подтверждение чтением. Неопределённый результат не повторять. Существующий дневной лимит бэклога 150 на кабинет сохраняется, порции по 5.

## Архивные вопросы Маркета — решение Сергея 05.11.2026

- Anthropic запрещён для генерации и контроля архивных вопросов: отдельный бесплатный путь по карточке, утверждённым ответам и проверенным источникам. Границы — yandex/question + архивная запись/когорта; живые вопросы других потоков не меняются.
- Блокировка действует на входе обычного движка, в прямой генерации, контролёре, llm_batch.ask и перед отправкой платной очереди. Предыдущий опубликованный ответ или ручное решение сохраняются; уже оплаченные результаты не удаляются.
- DeepSeek Search допустим для поиска недостающих внешних фактов под общим бюджетом. Сырая выдача не становится фактом автоматически: сохраняются проверенный источник и точная область применения. Проверка source_rules_no_llm не выдаётся за PASS Anthropic.
- Нет карточки удалённого товара/производителя/надписи на конкретной упаковке — это конкретный пробел, а не повод выдумать ответ или объявить товар вне профиля.

# Проверка сторожа акций Ozon по неукомплектованным заказам

Поток fin; поручение пользователя 20.10.2026. Адресат: существующая сессия wb4c.

Пользователь просит проверить, как отработал сторож акций по заказам в МС
«Неукомплектован», ПО КОТОРЫМ НАТАЛИИ УЖЕ ПРИШЛИ УВЕДОМЛЕНИЯ.
Уточнение пользователя: проверять именно этот список, а не все заказы ниже пола.
Ожидание: соответствующий
товар должен быть исключён из акции Ozon. Нужен проверенный результат по заказам,
а не только наличие успешного запуска задания.

## Область проверки

Начать read-only preflight, сохранить чужие изменения; использовать свой worktree.
Пилот — Ozon Дисквэр oz_acc2, «Склад → Заказы покупателей».
Исходный список — customer_guard_incidents с фактической отправкой Наталии
(delivery=sent, recipient/telegram_message_id/attempted_at), связанные order_id
и check_id → customer_guard_checks. В момент передачи сохранены 3 sent прежнего
типа below_floor; среди них выделить заказы «Неукомплектован» на момент сигнала.
Состояние на момент сигнала брать из соответствующего снимка/истории МС, а не
подменять сегодняшним latest_check_id. Затем отдельно проверить текущие статус,
расчёт и участие в акции. Если заказ после уведомления сменил статус/отменился,
он остаётся в аудите с объяснением хронологии. Если статус в момент сигнала нельзя
подтвердить — явно отметить это, не расширять список на все неукомплектованные.
Данные текущего расчёта: customer_guard_orders.latest_check_id → checks.result,
актуальная база fin_ozon_expense_current. Список и доказательства сохранить
в отчёт, в чат краткую сводку.

1. Сопоставить номер отправления → offer_id/SKU/product_id Ozon → выбранный товар
   МС/поставщик. Наборы разбирать по справочнику ТК; не сопоставлять их наугад.
2. Для каждого товара показать цену, себестоимость и её источник, пол, отклонение,
   расчётную чистую прибыль, версию/период базы расходов и время проверки.
3. Установить фактическую логику сторожа акций: видит ли он такой товар и стоимость
   поставщика на Удалённом складе, если в заказе стоит наш склад назначения;
   какие условия/ограничения исключения, расписание и активный runtime.
   Не предполагать, что сторож акций подписан на события заказов: проверить связь.
4. Проверить логи/аудит последнего подходящего запуска после появления/изменения
   заказа и относительно времени доставленного уведомления Наталии: решение по SKU, запрос исключения, ответ API, ошибки, пропуски.
5. Узким read-only запросом Ozon сверить текущее участие товара в соответствующих
   акциях; учесть несколько акций и возможность повторного добавления Ozon.
   Отсутствие в акции сейчас само по себе не доказывает работу нашего сторожа.
6. Итоговая таблица: заказ, SKU, статус МС, цена/себест/пол/чистая прибыль,
   время расчёта, акция, решение сторожа и время, API-результат, текущее участие,
   вывод/точная причина невыхода. Если данных недостаточно — явно указать пробел.
7. При дефекте описать причину, затронутый объём и минимальный вариант исправления.
   Это поручение на аудит: не запускать apply, не менять цены/участие в акциях,
   не расширять scope фонового сторожа и не выполнять массовые пересборки.
   Существующую авторизацию других задач не переносить автоматически на этот аудит.

## Важное различие порогов

Сторож заказов сегодня изменён: уведомления Наталии только при расчётной чистой
прибыли ≤0 ₽. Это НЕ изменение целевого пола для сторожа акций. Ниже целевого пола
можно быть с положительной прибылью: такой товар включить в аудит, ЕСЛИ он входит в указанный список доставленных уведомлений.
Пример различия (не утверждаем его текущий статус): 10879561-0077-1,
цена728, себест69.28, пол941.85, прибыль+216.15 ₽ при общей сентябрьской базе.
Код нового порога уведомлений507d3ef; worker release
/opt/mp-analytics/runtime/customer-guard-507d3ef24f5f. Расписание10/10/60 не менялось.
Доступ к МС при необходимости только выделенным SHIPMENT_GUARD_MS_TOKEN,
без fallback admin/operator. Для read-only Ozon использовать существующий общий lock
и узкие выборки. Секреты/персональные данные не выводить.

Отчёт оставить в своём worktree; вернуть путь и краткий результат в сессию wb4c.
Если доступна прямая очередь ответа, исходная сессия cogsguard; UUID не угадывать.

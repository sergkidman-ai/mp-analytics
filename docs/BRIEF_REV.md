## Правила (действующие)

1. **Что уходит во внешние LLM (13.08.2026).** Разрешено: только УЖЕ ОПУБЛИКОВАННОЕ на витринах
   площадок (название, артикул площадки, характеристики, описание, совместимость, наши листинги),
   текст обращения покупателя и наши прошлые опубликованные ответы. Запрещено на уровне СБОРКИ
   промпта: любые финансовые и закупочные данные МойСклада — закупочные цены, себестоимость,
   поставщики, маржа, наценка, остатки, обороты. Держится кодом: `reports/prompt_privacy.py` —
   `assert_public_facts()` роняет сборку на закрытом ключе, `scrub_finance()` вырезает закупочную
   фактуру из НАШИХ блоков (текст покупателя не трогаем). `reports/feedback_grounding.py`
   (единственный, кто читает `raw_moysklad_product`) в живом цикле не используется — не подключать
   без пересмотра правила.
2. **Внутренние складские пометки — только оператору.** Внутреннее имя МС («\*ВНИМАНИЕ\*»,
   «White Box», «DS», «уценка») режется `public_name()` во всех точках выхода; в карточке
   модерации имя и внутренний артикул показываются ПОЛНОСТЬЮ — по ним владелец узнаёт товар.
   Повод — инцидент OKI C822 (12.08): внутреннее предупреждение ушло покупателю.
3. **Достоверность фактов карточки (13.08.2026, инцидент 6806).** Омоглифы приводит
   `core/text_norm.fix_homoglyphs()`; двойник Ozon ищется строго по коду оффера (`_oz_twin()`),
   нет точного двойника — факт остаётся неизвестным и в ответ НЕ идёт; имя товара Яндекса берётся
   с витрины Маркета, не из МС.
4. **Контроль отправки и балансы (17.08.2026).** Движок обязан САМ сообщать, что ответы не уходят
   и почему; баланс DeepSeek и Anthropic проверяется каждый цикл (`feedback_bot/health.py`:
   предполёт, постфактум, `OnFailure=` на падение цикла). Когда беда уходит — обязательно шлётся
   🟢: молчание не должно быть неотличимо от поломки. Пополнение решает Сергей в потоке `infra`.
5. **Цвет алерта по классу причины (18.08.2026).** `BILLING` / `AUTH` / `CONFIG` → 🔴 с конкретным
   действием; `TRANSIENT` (529, 429, 5xx, таймаут) → 🟡 «Провайдер моргнул»; второй такой цикл
   подряд → 🔴, но БЕЗ «пополнить». **Запрет: не подклеивать «Пополнить баланс» к причине, которая
   не про баланс** — ложный призыв убивает доверие к настоящему 🔴.
6. **Пустые отзывы отвечаются шаблоном, а не висят.** Пустая 4★ → `route='auto'` (`63faf7f`),
   пустые ≤3★ → хендофф по QR (`1909e0b`), пустые Ozon-отзывы площадка не принимает вообще →
   `skipped_no_text`.
7. **Модерация негатива по рейтингу карточки (24.08.2026).** `reports/card_rating.py`
   (`DEAD=4.0`, `MIN_N=5`): карточка жива → негатив с текстом идёт человеку; карточка под убой →
   `route='auto'` и сухой `DEAD_TEXT` (хендофф в чат по QR). Рейтинга площадки нет и своих отзывов
   <5 → вердикт не выносим, отдаём человеку. Источники рейтинга: WB — `wb_search_report`,
   Ozon — `ozon_rating` (замер 17.07, умер вместе с review API), иначе среднее по своим отзывам.
8. **Автотекст в чатах площадок не делаем** (решение 24.08.2026): объём 2–5 диалогов в месяц,
   цена ошибки — возврат/деньги/претензия. Только видимость: коллектор `kind='chat'`, сторож SLA

## Вкладка «Распродажа остатков ВБ»

`/reports/wb-clearance` (подраздел «Склад»), страница статическая: `reports/wb_clearance_page.py`
→ `web/static/reports_wb_clearance.html`, перегенерация в `run_daily` и в API dismiss/restore.
Список распродажи приходит файлом «Распродажа_стока_ВБ_*.xlsx» через `dropbox_bot` в `dropbox/`
→ `collectors/wb_clearance.py` (юрлицо по имени файла, файл = полный срез: `DELETE` по account
+ upsert, ключ «Артикул WB» = `nm_id`). Живой остаток — `warehouse_remains` → `wb_stocks`;
закрытые сотрудником позиции — `wb_clearance_dismissed`.

Сигналы: остаток ВБ 0 и возврат едет обратно → 🟡 «Возврат в пути»; остаток 0 без возврата →
🔴 «Поднять цену»; остаток ≤ `LOW_THRESHOLD` (=1) → 🟡 «Заканчивается»; больше → 🟢 «Распродажа».

**Запреты вкладки:** транзит в `quantity` НЕ суммировать — «остаток ВБ» это только то, что
физически лежит на складе, иначе 🔴 не сработает вовремя. Псевдосклад «Всего находится на складах»
в `wb_stocks` не писать — двойной счёт. Транзит живёт отдельной строкой `warehouse='(в пути)'`
с `quantity=0` (колонки `in_way_to_client` / `in_way_from_client`); у потребителей `wb_stocks`
счёт SKU ограничен `quantity > 0`. Разбор целиком — в архиве.

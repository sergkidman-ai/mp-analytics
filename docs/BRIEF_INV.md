## Где работаю

  **Opus** (архитектура контура, спорные решения) — выбрать на старте и НЕ менять.

## Зона ответственности
Деньги на входе и выходе: выписки банков → МойСклад (`paymentin`/`paymentout`), привязка
платежей к приёмкам, черновики платёжных поручений, счета поставщиков и сроки оплаты.
**Два контура, две организации:** Альфа-Банк — ООО «Цифровой Квадрат»; Сбер — ООО «ДИСКВЭР».

## Границы
`margin_by_sku` и витрины fin — **read-only**. Веб-дашборд (`web/app.py`) — не мой, изменения
запрашивать у владельца. Секреты только в `.env` и `secrets/` (оба gitignored).

## Запреты потока
- **Боевые платёжки — только черновиками** (без ЭП): банк создаёт документ в статусе «черновик»,
  подписывает человек в вебе. Автоподписание не реализовывать.
- Ключи, токены, `client_secret` — **никогда** в чат, лог и git (в логах только длина и хвост).
- Ротацию/перевыпуск боевых кредов запускать осознанно: последствие отказа — встал весь контур.

- **Фрагмент назначения в правиле (миграция 210, решение Сергея 04.08).** `opex_rule.purpose_like`
  необязателен: пусто = правило на всего контрагента (как раньше), заполнено = только на платежи,
  где фрагмент встречается в назначении (регистр не важен, матч через `position(lower…)`).
  Уникальность правила — пара «контрагент + фрагмент», у одного ИНН может быть общее правило
  и несколько уточнённых. При совпадении нескольких **выигрывает самое специфичное** — с самым
  длинным фрагментом (`DISTINCT ON (t.id) … ORDER BY length(purpose_like) DESC`).
  В UI: селект «запоминать: контрагента / + фрагмент назначения / не запоминать» (выбор живёт
  в localStorage) и панель «🔁 правила» — список с числом авторазметок и удалением.
  **Удаление правила снимает только его авторазметку** (`source='rule'`), ручная остаётся,
  затем правила прогоняются заново, чтобы платёж подхватило более точное.
  API: `GET /api/opex/rules`, `POST /api/opex/rules/delete`.
  Проверено вживую и откачено: правило с фрагментом «Требование об уплате пени» разметило 3 из 27

# BRIEF_EV — дневник событий и сторожа изменений

**Поток `ev`.** Ветка/worktree: `ev/diary-stock` → `.claude/worktrees/ev-diary-stock`.
Миграции — блок **5xx**. Территория (страж): `ops/biz_diary.py`, `ops/stock_watch.py`,
`web/diary_api.py`, `migrations/5xx_*.sql`, этот бриф.

## Зачем поток

Цифры показывают ЧТО произошло, но не помнят ПОЧЕМУ. Просадка Дисквэра 20.08 — рынок или
наше отключение «Звёздных товаров»? Дневник кладёт события рядом с цифрами: наши решения
(`own`), изменения площадок (`mp`), остатки/поставки (`supply`) — одна таблица `biz_events`,
один хронологический список на главной, маркеры 📌 в недельной динамике.

Дизайн согласован с Натальей 21.08 — `docs/reports/biz_events_proposal_2026-08-21.md`.

## Сделано

- `migrations/500_biz_events.sql`, `501_stock_watch.sql` — применены к БД.
- `ops/biz_diary.py` — ядро: `add/recent/by_week/delete`, разбор свободного текста
  (`20.08`, `18 августа`, `вчера`; площадка и аккаунт по словам «Дисквэр»/«Цифровой»/«ВБ»).
  Что не распознано — оставляем пустым, НЕ угадываем: неверная площадка сажает событие
  на чужой график. `--seed` завёл 4 события из записки Натальи от 20.08.
- `web/diary_api.py` + 3 строки в `web/app.py` — `/api/diary` (список/добавить/удалить/
  `parse`/`weeks`). Отдельным роутером: `app.py` на 4300 строк правит поток fin.
- `web/static/home.html` — блок «🗓 Что мы меняли» между недельной динамикой и площадками,
  форма записи, 📌 у недель с событиями.
- `ops/stock_watch.py` — сторож остатков поставщика: подписки в `stock_watch`, состояние
  `ok/low/zero/nodata` против дребезга, одно сводное сообщение в бот PRC за прогон,
  смена состояния пишется в дневник (`kind='supply'`). Заведены 4 кода Натальи:
  3801at–3804at, склад «Удаленный склад», порог 5. Тревога проверена подменой порога.

## Ключ данных (грабли, не повторять)

`3804at` — **код товара ПОСТАВЩИКА** (`ms_product.code`), у него ОДИН остаток.
Не путать с `external_code='3804'` — это наша материнская карточка, под ней 9–11 строк
разных поставщиков. Джойн: `ms_product.code → ms_id → supplier_stock.ms_id`.

## Открыто

1. **Новости площадок.** ВБ — API v2 работает с `WB_TOKEN_ACC1` (v1 → 404). У Ozon и Маркета
   API новостей НЕТ, сайты отдают 403 (жёсткий антибот) — обходить не стали. Рабочий канал
   найден: почта `operator.dsquare@yandex.ru` получает их **заранее** (Маркет — «Новое в
   тарифах с 1 сентября» пришло 20.08, за 12 дней; Ozon — «Подключили доупаковку»). Транспорт
   IMAP уже есть (`invoice_bot/mail_poller.py`).
   **Вопрос Наталье:** на этот адрес пришло всего 3 письма Ozon — основная рассылка Ozon
   идёт на другой ящик, нужен адрес. Кода это не требует.
2. Кнопка «померить эффект» события (сравнение недель пн–вс до/после) — не написана.
   Обязательны две защиты: сравнимость дней недели и запрет мерить по неполному месяцу.
3. Приём событий из бота свободным текстом — парсер готов (`parse_free`), обвязки бота нет.

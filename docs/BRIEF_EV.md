# BRIEF_EV — дневник событий и сторожа изменений

**Поток `ev`.** Ветка/worktree: `ev/diary-stock` → `.claude/worktrees/ev-diary-stock`.
Миграции — блок **5xx**. Территория (страж): `ops/biz_diary.py`, `ops/stock_watch.py`,
`web/diary_api.py`, `migrations/5xx_*.sql`, этот бриф.

## Зачем поток

Цифры показывают ЧТО произошло, но не помнят ПОЧЕМУ. Просадка Дисквэра 20.08 — рынок или
наше отключение «Звёздных товаров»? Дневник кладёт события рядом с цифрами: наши решения
(`own`), изменения площадок (`mp`), остатки/поставки (`supply`) — одна таблица `biz_events`,
один хронологический список на главной, маркеры 📌 в недельной динамике.

Дизайн согласован с Натальей 21.08 — `docs/reports/biz_events_proposal_2026-08-21.md`.

## Сделано

- `ops/biz_diary.py` — ядро: `add/recent/by_week/delete`, разбор свободного текста

  3801at–3804at, склад «Удаленный склад», порог 5. Тревога проверена подменой порога.

## Ключ данных (грабли, не повторять)

`3804at` — **код товара ПОСТАВЩИКА** (`ms_product.code`), у него ОДИН остаток.
Не путать с `external_code='3804'` — это наша материнская карточка, под ней 9–11 строк
разных поставщиков. Джойн: `ms_product.code → ms_id → supplier_stock.ms_id`.

## Новости Ozon — канал найден (21.08, подсказала Наталья)

Новости приходят в **чаты ЛК**, и Chat API к ним пускает: `POST /v3/chat/list` +
`/v3/chat/history` обычной парой Client-Id/Api-Key (v1/v2 → 404). Отбор — по АВТОРУ
сообщения `user.type == 'NotificationUser'` (`o3_notification_user_sc`), НЕ по типу чата:
рассылки лежат в `UNSPECIFIED`, а фильтр списка по `chat_type` сервер молча игнорирует.
Чаты `BUYER_SELLER` и `SELLER_SUPPORT` пропускаем — это переписка, не новости (обход
падает с 1478 чатов до ~46).

`ops/mp_news.py` + `migrations/502_mp_notices.sql`: сырьё всех уведомлений в `mp_notices`,
важность по правилам (`alert` / `watch` / `info`), в дневник и в бот идёт только `alert`
за последние 14 дней (`--diary-days`). Собрано 1068 уведомлений с 24.05: 111 alert,
33 watch, 924 info. Что ловится: тарифы, изменения договора, подписки Premium,
«Подключили вам „Сбор первых отзывов“», «Для части ваших товаров подключили доупаковку»,
«Добавили ваши товары в акцию» — то самое, что списывает деньги, пока не отключишь.

**Грабли:** классифицировать по ТЕЛУ письма нельзя — у операционного «У вас есть возвраты
в точке выдачи» в тексте есть «тариф хранения», и оно уезжало в тревоги. Решает заголовок;
тело смотрим только на «подключили вам» / «добавили ваши товары». Правила менять безопасно:
`--reclassify` пересчитывает по сырью без похода в API и САМ снимает с дневника записи,
переставшие быть важными.

## Новости WB — лента v2 в ту же таблицу (21.08)

`GET common-api.wildberries.ru/api/communications/v2/news?from=YYYY-MM-DD`, заголовок
`Authorization: WB_TOKEN_ACC1` (у токена Дисквэра нет категории → 404; новости общие
для площадки, одного токена хватает). Отдаёт до 100 записей, листается сдвигом `from`;
признак конца — страница без новых `id`, на дату опираться нельзя (граничная новость
приезжает дважды).

**Лимит жёсткий:** подряд идущие запросы ловят 429. В `wb_news` пауза 8 с между страницами
и повтор после 429 с ростом ожидания (30/60/90 с) — полный обход за 100 дней идёт ~13 минут.
Это не сбой, это цена ленты; в cron она никому не мешает.

Собрано 727 новостей за 100 дней: 26 тревог, 9 watch. В дневник, как и у Ozon, идут только
тревоги за 14 дней. Событие WB пишется **без аккаунта** (`account=NULL`): новость общая для
площадки, привязка к одному аккаунту посадила бы её не на тот график.

Разовый добор истории по одному правилу: `--platform wb --days 100 --diary-days 100
--diary-rule 'склад/ЧП'` — так в дневник подняты июльские пожары на складах, не поднимая
июльские тарифы (они уже неактуальны).

## Новости Маркета — почтовый канал (21.08)

API новостей у Маркета нет (`/news`, `/campaigns/{id}/notifications` → 404), сайт отдаёт 403.
Рабочий канал — почта: Наталья отключила мусорные уведомления в ЛК и настроила пересылку
нужных писем в папку **«Яндекс.Маркет»** ящика `operator` (подпапка «Маркет. Не важное» — её
корзина, не читаем). Приёмник — `collect_yandex()` в `ops/mp_news.py`, транспорт — готовые
`prices/mailbox.py` (`connect` / `imap_utf7` для кириллицы), ящик открывается **readonly**:
флаг «прочитано» ставит человек, не сборщик.

Две ловушки, обе закрыты в коде:
- **Дата письма ≠ дата новости.** Письмо — пересылка: заголовок `Date` = когда переслали
  (21.08), а новость от 20.08. Дату берём из шапки «Пересылаемое сообщение»
  (`20.08.2026, 13:17, Новости Маркета (seller@market.yandex.ru)`), `Date` — только фолбэк.
- **Письмо — вёрстка.** Нужен снос `<style>` (иначе в тело новости уезжает CSS) и невидимой
  набивки U+2800 (пустой шрифт Брайля, растягивает preheader), плюс срез служебных строк
  «Кому/Тема» и подвала «отписаться» — `_fwd_trim()`.

Первое письмо разобрано: 20.08 «Новое в тарифах с 1 сентября» → `alert`/тарифы → дневник +
бот. То есть новость легла в ленту за 12 дней до вступления — ровно то, что просили.

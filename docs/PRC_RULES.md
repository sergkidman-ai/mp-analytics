# Поток `prc` — действующие правила и знания о системе

Свод вынесен из `docs/BRIEF_PRC.md` 16.08.2026 (бриф разросся до 1341 строки при лимите 150).
История этапов — `docs/archive/BRIEF_PRC_история_до_2026-08-16.md` (номера пунктов в скобках
ссылаются туда). Здесь только то, что действует **сейчас**.

## Матчинг и загрузка прайса

1. Матчинг строго «артикул поставщика == поле Артикул в МС». По имени/штрихкоду не угадываем (1).
2. Не грузим строку: нет в МС · карточка архивная · «брак» в наименовании · нет цены · остаток
   не разобран · артикул неоднозначен (2).
3. **`ambiguous` — законная причина, а не глюк** (20). Если по артикулу нашлось несколько карточек
   и ни одна не отличается поставщиком, `prices/loader.py:pick_card` отказывается выбирать: приходовать
   вслепую = размазать остаток по дублям. До ручной чистки МС такие строки выбывают из работы.
4. Остаток берём из прайса; текстовые формулировки разворачивает ТАБЛИЦА профиля. Незнакомая
   формулировка молча в число не превращается — строка в отчёт (3). Минимума остатка не ставим:
   отсечка стоит дальше по цепочке, дублировать нельзя (11).
5. Цена = цена прайса × курс ЦБ на дату × надбавка, копейки «половина вверх». **Курс не округляем**
   (округление до 4 знаков дало 51 расхождение на 1108 позициях) (4).
6. Дубль артикула внутри прайса: полные повторы схлопываем молча; при разном остатке берём строку
   с **бо́льшим остатком целиком** (со своей ценой), вторая — `duplicate_smaller`; равный остаток
   при разной цене — обе снимаются человеку (`duplicate`). Остатки складывать нельзя (10, 45).
7. Категории прайса фильтруем ДО матчинга и до обращения к МС; правило = (префикс группы, только эти
   подгруппы, кроме этих), сравнение **по префиксу**, не по точному имени (13).
8. Чёрный список: строка не выбрасывается, а получает причину `blacklisted` — остаётся в журнале
   и `*_skipped.csv`, не идёт в `prc_unmatched` и новинки. Ключ `upper(btrim(артикул))`,
   импорт идемпотентный (14). Бренд может браковаться правилом, а не списком:
   `blacklist.BRAND_RULES`, у `odissey` `^ТУ\b` — товар без упаковки, не берём совсем (54).
9. Аномалии цены проверяем ДО записи. База сравнения — **наша прошлая боевая закупочная
   из `prc_price_row`**, не `buyPrice` карточки. ±50% = флаг; коридор 20–200 000 ₽ снимает строку;
   сдвиг медианы прайса >20% или флагов >5% = блокировка целиком; обход `--ignore-anomalies`;
   сухие прогоны в базу сравнения не идут (9).

## Документ Оприходование в МС

10. Имя `<группа>_<ГГГГ-ММ-ДД>_p<N>`, описание = группа, ООО «ЦИФРОВОЙ КВАДРАТ», склад «Удаленный»,
    проведён, 100 позиций (5).
11. Порядок замены: пометить прошлые `_old<ЧЧММСС>` → создать новые → обновить карточки → удалить
    старые. Удалять ДО создания нельзя — обнулится остаток (6, 12).
12. Удаляем только документы своей группы и только на «Удаленном»; фильтр МС перепроверяется своим
    regex (7). Оприходования на других складах (Звездный, Кантемировская, Брак) не трогаем (53).
13. Описание и закупочную карточки обновляем только при совпадении И артикула, И поставщика (группы).
    Ручные правки описания при этом перезаписываются — решение Сергея (8).

## Новинки и заведение карточек

14. Владелец товара — **ГРУППА юрлиц поставщика** (`prices/supplier_group.py` поверх
    `invoice_bot/supplier_groups.py`), не один контрагент. Чужая карточка → причина `foreign`,
    строка едет в «Новинки» и не закрывается как `exists`.
15. Признаков сверки **шесть**: модель, тип, бренд, цвет, ресурс/объём, чип. Три состояния
    (да / нет / молчит), молчание в `N/6` не идёт. Ресурс/объём совпадает при расхождении до **25%**.
    Бренд не фильтрует кандидатов, только опускает в хвост. Мягкие противоречия — бренд и ресурс
    (метка «⚠»), жёсткий отказ — цвет и чип. `exists` ставит только автомат, человек —
    `matched/new/partial/skip`; **автозакрытие 6/6 не включено** (17, 30, 62).
16. Решение по каждой новинке принимает человек; прогон прайса решения НЕ затирает, пересобирает
    только признаки и подсказки (18).
17. Неполный набор цветов = `decision='partial'`, полка ожидания, а не отказ (22). Лист ожидания
    сверяется каждый прогон по всем поставщикам; **ЧС не приговор** — `waiting.revive` снимает соседа
    с ЧС и заводит пару; `dead` только по ассортиментным причинам; сосед из ЧС, которого не было ни
    в одном прайсе, не возвращается («спросить у поставщика»); «в ЧС ли» спрашиваем у `prc_blacklist`,
    а не у журнала (23).
18. Ассортимент: не берём промывочную жидкость и перезаправляемые. Цветной товар — только полным
    комплектом, комплект считаем по ВСЕМУ прайсу; **бренд в комплекте не учитываем, тип товара —
    учитываем**; неполный комплект не хороним (16).
19. Заведение карточки: новая = близнец родни того же ВНЕШНЕГО кода. Всё про товар (группа, вес,
    Code128, «Название WB») — от родни, всё про поставку (наименование, артикул, цена, поставщик) —
    из прайса. Не сочиняем: нет у родни — в отчёт замечаний. Существующий артикул не перезаписываем (24).
20. «Название WB»: предлог **«для» перед брендом принтера ВСЕГДА**; вариант родни выбирается
    по шаблону `_wb_fit` (цвет/XL/чип, без аббревиатуры поставщика); родни нет — `wb_compose()`
    собирает из каталога ТК; каталог молчит — поле пустое с замечанием, догадок не пишем (24, 37).
21. Вес: **прайс поставщика — первоисточник**; нет в прайсе — вес самой свежей карточки того же
    внешнего кода (дата из id, `created_at()`), не частотный (24).
22. Code128 = `DS` + 3 буквы + внешний код с нулями, ОДИН И ТОТ ЖЕ у всех карточек кода; у НОВОГО
    внешнего кода Code128 не ставим. **ean8 не трогаем и не ждём** — генерируется позже сам (24, 25, 27).
23. Группа карточки = папка БРЕНДА ПРИНТЕРА; папки поставщиков и «Оригинальные» отбрасываются (24).
24. Внешний код — 4 цифры, идём ВВЕРХ от последнего занятого (не в дырки), проверять живым опросом МС,
    а не снимком `ms_product` (25).
25. Карточку на НАБОР с НОВЫМ внешним кодом не заводим; если внешний код набора уже есть — позицию
    поставщика привязываем обычной карточкой (25).
26. Универсальный картридж (HP+Canon и т.п.) — отдельная карточка на каждый бренд, взаимная «Связь»;
    **артикул поставщика ставится только на ОДНУ карточку**, иначе `ambiguous` и позиция вылетает (25, 27, 43).
27. Модель новинки — следующая ступень ресурса, а не копия названия поставщика
    (CF226A → CF226X → CF226XL → CF226XXL) (25). Заведённую новинку сразу добавляем в текущее
    оприходование этого поставщика (25).
28. **Порог «тонер/чернила больше 150 г не берём» ОТМЕНЁН** (`REFILL_LIMIT` удалён): разбор идёт
    от МОДЕЛИ картриджа — список принтеров (нероссийские убрать) + доза полной заправки; из одной
    позиции выходит несколько карточек (26). Сыпучий тонер: карточка = МОДЕЛЬ КАРТРИДЖА, а не флакон;
    заводим только если есть флакон ровно нужной дозы (27).
29. Чип: «с чипом» и «с чипом без счётчика» — разная подробность, не противоречие; обоюдное молчание =
    совпадение; **чип не придумываем**; чип обычный vs без счётчика = РАЗНЫЕ товары и разные внешние
    коды (33, 35, 60).
30. «Связь» (`prc_novelty.link`, доп.поле МС): номер товара **четырьмя цифрами с ведущими нулями,
    разделитель `;`, без пробелов**; каждый код проверяется по каталогу; архивные карточки в сверке
    не участвуют (21).
31. `CODE_SUFFIX` без значения по умолчанию: незнакомый префикс останавливает сборку и называет
    артикул — код новому бренду выбирает человек (55).
32. Неразобранные показываем только при наличии остатка у поставщика: остаток — ТОЛЬКО из последнего
    удачного прайса (`NOVELTY_STOCK`/`IN_STOCK`), в `classify` проверяется ПЕРВЫМ, до поиска карточки;
    из базы строки не удаляем, галка «и без остатка» (`?no_stock=1`) их возвращает (48).
33. ТК (TheCartridge) — первоисточник признаков: первый проход по каталогу ТК, что не сошлось —
    добираем по МС; **в API ТК на разборе не ходим** (ночной слепок); `kind` из ТК не берём;
    расхождения ТК↔МС правятся руками, автоматически МС не трогаем (60). Связи универсальных моделей
    из ТК — **пока только справочник**, в матчинг и в МС без отдельного решения не заводятся;
    направления `incoming`/`outgoing` не схлопывать (61).
34. **Юрлицо Одиссея у новой карточки (решение Сергея 18.08.2026).** У Одиссея два контрагента.
    На `ООО "ОДИССЕЙ" WB` идут ДВА набора: бренд **White Box** (метка в наименовании,
    `ms_import.is_white_box`) и **вся струйка любого бренда** — признак струйки берётся из
    КАТЕГОРИИ МС `Картриджи/…/струйные <бренд>` (`ms_import.is_inkjet`). Остальное — лазерка
    Аквамарина, Hi-Black и пр. — на `ООО "ОДИССЕЙ"`. Аббревиатуру кода это не меняет: струйный
    Аквамарин остаётся `…at`, отличается только юрлицо. Автоматика (`ms_import.supplier_of`)
    берёт категорию у родни того же внешнего кода; у карточки с НОВЫМ внешним кодом родни нет,
    поэтому струйную новинку Одиссея человек кладёт в струйную папку и ставит юрлицо сам.
35. **Юрлицо КВК ТРЕЙД у новой карточки (то же устройство, решение Сергея 18.08.2026).**
    У поставщика два контрагента: `ООО "КВК ТРЕЙД"` (`727e2c1e-…`) и `ООО "КВК ТРЕЙД" OEM`
    (`bdd618ae-…`). На OEM-контрагента идут **товары OEM** (артикул `OEM …`, наш код `…oem`)
    **и вся струйка**; всё остальное — на `ООО "КВК ТРЕЙД"`. Профиля прайса у КВК нет
    (`CODE_SUFFIX`/`profiles` его не знают), карточки заводит человек — значит юрлицо ставится
    руками, автоматика тут не подстрахует.

36. **Юрлицо ТОНЕРОПТТОРГ у новой карточки (решение Сергея 18.08.2026).** Два контрагента:
    `ТОНЕРОПТТОРГ (Изипринт)` (`c9c7b549-…`) и `ТОНЕРОПТТОРГ (Изипринт) T2` (`daffd8b7-…`).
    Признак СТРОГО ОДИН — **вхождение «T2» в НАИМЕНОВАНИЕ товара** («Картридж T2 для …»):
    есть метка → контрагент `… T2`, нет → `ТОНЕРОПТТОРГ (Изипринт)`. Ни категория, ни артикул,
    ни наш код признаком не являются: там едут два бренда одного поставщика — T2 и EasyPrint.
    Тонкости разбора имени: буква «T» бывает латинской и кириллической (`[TТ]2`); метку считаем
    только ОТДЕЛЬНЫМ словом — `(?<![0-9A-Za-zА-Яа-я])[TТ]2(?![0-9A-Za-z])` — иначе в неё попадут
    `CT2`, `TK-1T2`; правый край допускает слипшийся пробел («Картридж T2для HP», карточка
    `0776t2` — реальная опечатка поставщика). Наш код (`…t2` / `…ep`) — независимый сигнал
    человека: расходится с именем — смотреть глазами, а не переписывать молча.

## Запись, согласования, безопасность

34. **Чужие живые карточки в МС сами не правим** — только те, что заводим; правку существующих делает
    человек (34). Любая запись в МС — по отдельному «да» Сергея на конкретную партию.
35. Работа с шаблоном человека: правки в КОПИЮ `…_fixed.xlsx`, присланный файл не трогаем;
    `tpl_check` → `tpl_load` без `--apply` (проба) → с `--apply` → `tpl_verify` (57). Шаблон проверяется
    теми же 6 признаками + «Связь» седьмым: признак противоречит ВСЕЙ родне → строку не грузим,
    части родни → замечание «глазами» (33, 34).
36. **Разведка в сети платная**: только по строкам `decision='new'`, единица работы — СТРОКА прайса,
    один запрос сразу по всем пунктам; смета ≈ $0.17 ≈ 14 ₽ за строку; гейт `confirm` в четырёх местах;
    кэш по МОДЕЛИ; данные без ссылки-источника не принимаются (`null`); **каждый живой прогон —
    отдельное «да» Сергея на сумму** (28).
37. Письмо помечается прочитанным только при `--apply` и `status == ok`, по стабильному UID; сбой
    пометки загрузку не роняет (46).
38. Сторож: юниты `prc-price-watch@<ключ>.{service,timer}`, окно 07:09–21:39 МСК, `RandomizedDelaySec`
    5 мин. Подключение нового поставщика = боевой `--apply` руками с «ок» → **засеять
    `logs/prc_price_watch_<ключ>.json`** → `systemctl enable --now`. Без засева повторится боевая
    загрузка: `fetch_latest_price` ищет по ALL, пометка прочитанным не защищает (41, 51).
    Замок на сутки: сегодняшнее письмо + `result==0` → в IMAP до завтра не ходим; отмена по аномалиям
    замок НЕ ставит; обход `--force` (52).
39. Телеграм-сводка — ОДНА строка (`Кактус — Оприходование в МС — ОК, новых позиций — 34`), ниже только
    ошибки/предупреждения. Бот `@ds_prc_bot`, `TG_PRC_BOT_TOKEN`/`TG_PRC_NOTIFY_ID`; **прайсы слать
    в `TG_NOTIFY_ID` нельзя — там другие люди** (42). В сводку сторожа пишем только то, что человеку
    реально разбирать — `pending_in_stock`, не всю очередь (58).
40. Список новинок уходит оператору на `operator.dsquare@yandex.ru` (`prices.mailout`, SMTP выводится
    из `MAIL_HOST`); автоотправка после `--apply` НЕ включена (15).

## Знания о системе (не потерять)

**Профили и курсы.** Колортек — xlsx, шапка стр. 6, USD ×1.03. Одиссей — xls, шапка 6–8, ЦБ **×1.00**
(надбавки нет, доказано обратным расчётом по 1154 позициям: курс 81.1291 = ЦБ). Сакура — xls, шапка
стр. 4, ×1.03, **цену прайса берём как есть** (ручная загрузка местами округляла до целого доллара —
правила в этом нет). Кактус — xlsx, рубли, курс не нужен.

**Кактус.** Письмо от ООО «КОМПАНИЯ ФЕРРЕТ», в письме ДВА прайса → фильтр вложения `file_pattern`;
артикул МС = колонка **«Парт. Но.»**, не «Но.»; в прайсе 46 групп каталога (сейфы, стулья) — без
фильтра категорий новинки предложат завести стул.

**Суффиксы кодов карточек = поставщик.** `cs` Cactus/G&G/Print-Rite (Феррет), `ce` картриджи CET
(ООО «КОМПАНИЯ ФЕРРЕТ»), `csp` наборы `CSP-`, `bt` ИП Капшук Наталья Сергеевна (= Булат), `gf` Grafit
(не `bt`!), `hb` Hi-Black, `gp` GalaPrint, `pl` ProfiLine, `sl` БУЛАТ s-Line, `sg` SG, `at` Аквамарин
(911 карточек; есть ещё `aq` 37 — выбран `at`), `wb` WB, `ty` ТУ, `msk`/`spb` склады Спринта, `7q`,
`bs` Блоссом (`BS-`), `SP{code}_MSK` Солюшнс, `-or` — метка оригинала (живёт в КОДЕ карточки,
не во внешнем коде).

**МойСклад, грабли.** Имя оприходования **уникально** (`HTTP 412 code 3006`); `quantity=0` не
принимает (3003) — позицию удалять, а не обнулять; числовой артикул из xlsx приезжает int и отбивается
`400 code 2016` — приводить к строке; **внешний код очистить нельзя** — на пустое значение МС
генерирует новый автокод; пакетное удаление отдаёт 409 со смешанным массивом — удалять по одной, ловить
**1028 «объект уже используется»** и читать `dependencies`; `/report/stock/bystore` не принимает
несколько `product=` (ошибка 1030) — рабочий путь `/report/stock/all` с `filter=store=…;product=…`,
общий список — `stockMode=positiveOnly`; **`core/ms_api.py` клеит `BASE + path` без разделителя** —
путь обязан начинаться со слэша, иначе 503, который читается как «МС лежит»; поиск по артикулу — только
точный `filter=article=` (подстрока даёт ложное `CS-TKY4-100` ↔ `CS-TKY4-1000`); отчёт остатков
отдаётся с задержкой ~минуту; даты заведения в API нет — восстанавливается из id (time-UUID).
Склады: Звездный `e0d74d6f-db92-11ee-0a80-0cda000a40b5`, **Дисквер** (не «Дисквэр»)
`d9f78430-0879-11f0-0a80-08bb001470db`.

**Витрина `ms_product`** обновляется целиком по воскресеньям, архивные карточки в неё не грузятся вовсе
(`collectors/moysklad.py:125`), «продаж ноль» в ней ≠ «не продавалось» (глубина `ms_demand_cogs`
с 10.2025) — для решений об удалении опрашивать живой МС.

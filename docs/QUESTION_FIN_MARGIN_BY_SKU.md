# Вопрос потоку `fin`: `margin_by_sku` завышает прибыль Ozon acc1 на 1,12 млн ₽ за июль

Поток: `mkt` → `fin`. Дата: 10.08.2026. Ветка: `mkt/ozon-ads-coverage`.

## Коротко

За июль-2026 по acc1 `margin_by_sku` показывает прибыль **3 056 386 ₽ (28,9 % от выручки)**.
Сальдо транзакций Ozon за тот же период минус та же себестоимость даёт **1 935 449 ₽ (18,3 %)**.
Расхождение — **1 120 937 ₽, это 10,6 п.п. маржи**.

Это не академический вопрос: `mkt_ozon_margin_control.margin_own_live` считается по той же
модели затрат (медиана по acc1 = 28,9 %, ровно как в `margin_by_sku`), а из неё берётся
**потолок ставки CPC** для разгона рекламы:

```
ceil = (price * margin_own_live/100 - price * ППО) * CR
```

Если маржа завышена на 10,6 п.п. при средней ~29 %, потолок завышен примерно **в полтора раза**.
Мы разгоняем ставки к целям, которые могут быть за гранью безубыточности.

`margin_by_sku.other` покрывает из этого только **500 393 ₽**.

Параметр модели: `mkt_ozon_margin_control.other_rate = 0,0981` (9,81 % от цены, единый на весь
acc1). По транзакциям аналогичный блок затрат тянет на **14,34 %** — то есть сам `other_rate`
занижен на **4,5 п.п.**, а оставшиеся ~5 п.п. расхождения сидят в других статьях модели.

## Вопросы

1. Какие статьи транзакций `margin_by_sku` относит в `other`, а какие игнорирует? Нужен список
   `operation_type_name` → колонка модели, чтобы не гадать.
2. `other_rate` — константа на аккаунт. Она откуда: замер за какой месяц, по какой формуле?
   Кто её пересчитывает и с какой периодичностью?
3. Реклама (`Оплата за клик` 169 648 + `Продвижение с оплатой за заказ` 541 441) — она **должна**
   входить в маржу или считается отдельным слоем? Для потолка CPC это принципиально: если ППО
   уже сидит в `other_rate`, формула вычитает его **дважды** (в `ceil` он вычитается явно).
4. Откуда 108 820 ₽ разницы в базе «начислено к получению»: сдвиг периода, невыкупы,
   или начисления, не дошедшие до транзакций в июле?

## Что меняется у нас после ответа

* Пересчёт `other_rate` → падение `margin_own_live` → пересчёт `bid_ceiling` во всех трёх
  планировщиках (`tools/ozon_acc1_plan.py`, `ozon_acc1_plan2.py`, `ozon_bid_plan.py`)
  и перезалив целей в `mkt_ozon_bid_ramp`.
* Отдельно и независимо: после 23.08.2026 отваливается Premium Pro (2,53 п.п.), это
  уже учтено в `MARGIN_UP = 2.4`. Звёздные товары (1,55 п.п.) отключить нельзя — из допущения
  убраны 10.08.2026.
* Пока ответа нет, разгон идёт к потолку, посчитанному по маржe 28,9 %. Если верна цифра 18,3 %,
  цели надо резать примерно на треть.

## Как воспроизвести

```sql
-- модель
SELECT sum(revenue_buyer), sum(cogs), sum(commission), sum(logistics),
       sum(returns_sum), sum(storage), sum(other), sum(net_profit)
  FROM margin_by_sku WHERE account='oz_acc1' AND period_from='2026-07-01';

-- факт
SELECT payload->>'operation_type_name', sum((payload->>'amount')::numeric)
  FROM raw_ozon_transaction WHERE account='oz_acc1' AND period_from='2026-07-01'
 GROUP BY 1 ORDER BY 2;
```

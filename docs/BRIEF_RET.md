## Задача

Отдельный Telegram-бот раз в день присылает полный список висящих FBS-возвратов по
Ozon / Яндекс / WB: сгруппировано по ПВЗ, с адресом, составом возврата, сроком забрать
и штрихкодом получения (картинкой — там, где площадка его отдаёт).

## Правила классификации — только в `returns_bot/pending.py`

Стадии `pickup` (забрать) / `transit` (едет) / `attention` (потерян/утилизация) / `closed`.
WB: статус приходит русской строкой, гейт — `isStatusActive` (0 = история при любом статусе);
`Готов к выдаче` → pickup, `В пути в пвз` → transit, живой неизвестный статус → `attention`
(в сводке не виден, `SHOW_STAGES` — только pickup; заметить можно прогоном `collect`).
Ozon `Utilized`/`WriteOff` и Яндекс `EXPIRED`/`RECEIVED_FOR_EXPROPRIATION` — **closed**:
товара уже нет, действия невозможны, в ежедневный список они шум. Правка правил — только здесь.

**Что бот показывает — `pending.SHOW_STAGES`, сейчас только `pickup`** (решение Сергея 02.08.2026).
Убраны из показа: «в пути» (Едет к вам / Едет на склад Ozon / Ожидает отправки / Привезёт курьер)
и «разобраться» (Ищем товар / потерян / готовится к утилизации) — действия по ним всё равно нет.
**Собираем и храним по-прежнему всё**, вернуть показ = добавить стадию в `SHOW_STAGES`.
«Привезёт курьер» (`ReturningToSellerByCourier`) Сергей отложил «возможно, понадобится позже» —
возвращать отдельной стадией, а не всем блоком `transit`.

**Фаза 9 — приёмка: недельный отчёт «что уже получено» (10.08.2026).**
Ежедневная сводка отвечает «что забрать», этот отчёт — «что приехало и что с этим делать».

- **Второй адресат.** Алексей Шаров (`780828338`) добавлен в `TG_RETURNS_ALLOWED_IDS`
  и `TG_RETURNS_NOTIFY_ID` — получает и ежедневную сводку, и недельную приёмку.
  Наталье нужен тот же отчёт, но её `chat_id` в боте нет: добавим, когда напишет `/start`.
- **Чужой чат теперь виден в журнале** (`bot._who`, коммит `30f944b`). До этого сообщение
  неразрешённого пользователя молча отбрасывалось, а Telegram удалял апдейт вместе с `chat_id` —
  человека нельзя было добавить, пока он не напишет ещё раз.
- **Своя дата получения `received_at`** (миграция 302). У площадок такой даты нет: у Ozon
  `arrived_moment` — приезд коробки в ПВЗ, у ВБ `readyToReturnDt` — готовность к выдаче,
  у Яндекса и Real-FBS нет ничего. `collect.store()` штампует её один раз, когда впервые видит
  статус «получено» (`RECEIVED_STATUSES`); перезаписывать нельзя — дата поедет при каждом сборе.
  История до 10.08.2026 залита разово из `arrived_at`/`created_at` (1479 строк из 4064).
- **Был ли контакт с покупателем** — строго из `return_type` площадки (`weekly_received.CONTACT`),
  без догадок: Ozon `ClientReturn`/`PartialReturn`/`FullReturn` и Яндекс `RETURN` — был;
  Ozon `Cancellation` и Яндекс `UNREDEEMED` — не было; **у ВБ признака нет вовсе** — отдельная
  корзина «не определить», такие проверяем как вскрытые.
- **Вывоз со стока FBO Ozon — все коробки на проверку** (Сергей 10.08.2026). Работаем только по
  ФБС, на склад Ozon товар попадает после отмены, невыкупа или возврата после получения, то есть
  вскрытым может быть любой. Прежняя формулировка «упаковка заводская, проверять только Брак»
  **неверна**; «Брак» помечается 🔴 и идёт первым. Дата в отчёте — `delivery_date` (приезд
  коробки), не `created_at`: заявка создаётся сильно раньше приезда.
- **Расписание** — `returns-weekly.timer`, понедельник 06:20 UTC = 09:20 МСК, за прошлую
  неделю пн–вс по Москве. На 15 минут позже ежедневной: обе шлёт один бот.

## Запреты

- Только **чтение** API площадок. Ничего не согласовываем, не оспариваем, не заявляем на вывоз,
  в кабинеты не пишем.
- Витрины fin (`margin_by_sku`, `ms_return_cogs`) не трогаем: там деньги, здесь физика.
- **Свой QR из номера возврата не рисуем.** Только коды, которые площадка отдала сама
  (Ozon PNG/`logistic.barcode`). Если ПВЗ сканирует другой код — картинка вводит в заблуждение.
- Мерж в `main` — только по явному «ок» Сергея.

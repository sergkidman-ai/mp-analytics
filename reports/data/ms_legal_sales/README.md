# Продажи юрлицам из МойСклада

`raw/YYYY-MM.json` — отгрузки Цифрового квадрата по четырём проектам за месяц после исключения замен `.0`/`.1`; проект может быть указан в отгрузке или связанном заказе. Принимаются заказы со статусом «Доставлен», а также «Претензия решена обмен» при полной связанной оплате исходной отгрузки. Если в отгрузке отсутствует связь с заказом, её восстанавливаем только при совпадении номера, организации, контрагента, суммы и допустимого статуса заказа. Для отгрузок без проекта проверяем целевые заказы по номеру. Тип контрагента проверяется в МС: `legal` или `entrepreneur`. Если тип в отгрузке и заказе расходится, учитываем юридическое лицо из заказа только при связанной оплате того же контрагента; это расхождение требует исправления карточек в МС.

`costs.json` — точная FIFO-себестоимость каждой отгрузки из `report/stock/byoperation` после сверки товарных позиций. `payments.json` — связи входящих платежей с заказами и отгрузками, в том числе через счёт покупателю. `report.json` — атомарно обновляемый снимок для `/reports/legal-sales`.

Исключение по подтверждённому недовложению `56856`: исходная отгрузка оформлена на 3 шт. и 4853 ₽, фактически из неё доставлена 1 шт.; досылка `56856.1` закрыла ещё 2 шт. В отчёте это **одна** продажа 4853 ₽ на дату исходной отгрузки с ссылкой на досылку. FIFO фактически доставленных 3 шт. = FIFO 1 шт. из `56856` + FIFO 2 шт. из `56856.1`; связь, суммы, SKU, количество и статусы обоих заказов проверяются при каждой сборке. Отдельный оборот по `.1` не добавляется.

Обмены `56742` и `56809` включены как исходные оплаченные продажи на даты исходных отгрузок. По решению пользователя их себестоимость — **только FIFO первоначальных отгрузок**: 23036,84 ₽ и 2022,01 ₽ соответственно. Замены `.0`/`.1` не увеличивают в этом отчёте ни продажу, ни оплату, ни себестоимость исходной продажи.

Разовый пересчёт: `./venv/bin/python -m collectors.ms_legal_sales scan YYYY-MM` для нужных месяцев, затем `./venv/bin/python -m collectors.ms_legal_sales build`. Ежедневный `run_daily.py` вызывает `refresh`: пересканирует текущий месяц (и прошлый в первые пять дней), перечитает типы контрагентов, оплаты и FIFO текущего месяца. Старые месяцы можно пересканировать вручную. Сумма оплаты отражает только связи в МС; отсутствие связи отмечено в интерфейсе.

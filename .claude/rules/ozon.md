# Ozon

## Финансы

- **Сплит строки «Продажи»** (Выручка / Баллы за скидки / Программы партнёров) берётся ТОЛЬКО из
  отчёта о реализации `/v2/finance/realization`. **Постинги врут** — источником сплита не являются.
  Реализовано и задеплоено.
- Состав 10 строк «Финансы → Баланс» закреплён реестром `ops/ozon_lines_registry.py` + аудит новых
  типов начислений. Классификация по подстроке кода операции — источник тихих ошибок, так не делать.
- Расходы — из `finance/transaction/list`.
- Витрина `margin_by_sku` **завышает** прибыль Ozon acc1 примерно на 10.6 п.п.; потолок ставок CPC
  считается по этой же модели — учитывать при выводах о рентабельности рекламы.

## Карточки и запись

- **Отправка изменений на Ozon — только по отдельной прямой команде Сергея.** Наличие данных ≠
  разрешение на запись; dry-run и подготовка разрешены.
- Габариты карточки обновлять **только отдельным методом**, не слать карточку целиком.
- Карточка в статусе «Ошибка» после ТК: «Не обновлён» лечится повторной отправкой того же значения;
  контентные ERROR правятся только в ТК. `task_id` лежит в корне ответа, `skipped` бывает при HTTP 200.
- Остатки МойСклада сшиваются с карточками Ozon по `supplier_stock.external_code`, а НЕ по `article`.

## Прочее

- `NOT_STARTED` в Performance API — это очередь, а не ошибка: ждать до 30 минут и перезаказывать отчёт.
- Ozon сам ночью добавляет товары в региональные акции; наш рычаг — только снятие (режим подметания).
- Ставки ведутся **недельными** шагами ±10 % по тирам с журналом решений; ежедневный разгон отменён
  как убыточный.
- Падение видимости лето-2026 — потеря показов (−29 % при +31 % спроса), не цена и не конверсия.

Тела — карточки памяти `ozon-*` в `/opt/mp-knowledge/memory/`.
